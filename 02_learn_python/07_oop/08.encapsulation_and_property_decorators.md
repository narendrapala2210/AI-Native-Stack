## 1. Conceptual Deep-Dive: Information Hiding in Python

Unlike languages with strict keyword access specifiers (`public`, `private`, `protected`), Python manages access control via conventions and name mangling:
1. **Public (`var`)**: Accessible from any caller.
2. **Protected Convention (`_var`)**:
   - Single leading underscore signals to developers: "Internal implementation detail. Do not mutate directly from outside."
   - Not enforced by the runtime, but respected by IDEs, linters, and `from module import *`.
3. **Private Name Mangling (`__var`)**:
   - Two or more leading underscores (and at most one trailing underscore) triggers CPython **name mangling**.
   - CPython transparently rewrites `__var` internally as `_ClassName__var`.
   - Primary purpose: Preventing accidental attribute overrides in subclasses (not cryptographic privacy).
4. **Managed Properties (`@property`)**:
   - The `@property` decorator turns a method into a read-only attribute getter.
   - `@<name>.setter` defines validation logic when assigning (`obj.val = 10`).
   - `@<name>.deleter` defines cleanup when deleting (`del obj.val`).
   - Allows classes to transition from bare public attributes to validated getters/setters without breaking public API contracts.

```python
class BankAccount:
    def __init__(self, balance: float):
        self._balance = balance  # Protected convention

    @property
    def balance(self) -> float:
        return self._balance

    @balance.setter
    def balance(self, value: float):
        if value < 0:
            raise ValueError("Balance cannot be negative!")
        self._balance = value
```

## 🛠️ Practical Hands-On & Real-World Examples

### Example 1: Validated Temperature Sensor with Full Property Lifecycle
Implement a thermal calibration model with getter, setter, deleter, and automatic Fahrenheit conversion.

```python
class TemperatureProbe:
    def __init__(self, celsius: float = 0.0):
        self._celsius = None
        self.celsius = celsius  # Invokes the setter validation immediately

    @property
    def celsius(self) -> float:
        # Getter: Retrieve temperature in Celsius
        return self._celsius

    @celsius.setter
    def celsius(self, value: float):
        # Setter: Validate absolute zero boundary (-273.15 C)
        if value < -273.15:
            raise ValueError(f"Physics Violation: Temperature {value}C is below Absolute Zero (-273.15C)!")
        self._celsius = round(float(value), 2)

    @celsius.deleter
    def celsius(self):
        # Deleter: Reset sensor to factory calibrated default
        print("Resetting sensor: Deleting calibrated Celsius reading...")
        self._celsius = 0.0

    @property
    def fahrenheit(self) -> float:
        # Computed property: Read-only derived calculation
        return round((self._celsius * 9 / 5) + 32, 2)

def test_sensor():
    probe = TemperatureProbe(25.0)
    print(f"Current Temp: {probe.celsius}C | {probe.fahrenheit}F")

    probe.celsius = 100.0
    print(f"Boiling Temp: {probe.celsius}C | {probe.fahrenheit}F")

    # Test deleter
    del probe.celsius
    print(f"After Reset:  {probe.celsius}C | {probe.fahrenheit}F")

    # Test boundary violation
    try:
        probe.celsius = -300.0
    except ValueError as e:
        print(f"Validation Caught: {e}")

test_sensor()
```

#### Step-by-Step Explanation:
1. Setting `self.celsius` inside `__init__` executes the setter method, guaranteeing all instances adhere to validation from moment of creation.
2. `fahrenheit` is a computed property without a setter, making it effectively read-only.
3. Attempting to assign `-300.0` raises a `ValueError`.

#### Expected Output:
```text
Current Temp: 25.0C | 77.0F
Boiling Temp: 100.0C | 212.0F
Resetting sensor: Deleting calibrated Celsius reading...
After Reset:  0.0C | 32.0F
Validation Caught: Physics Violation: Temperature -300.0C is below Absolute Zero (-273.15C)!
```

### Example 2: Name Mangling Preventing Attribute Collisions in Subclasses
Demonstrate how double underscore name mangling isolates variables across deep inheritance hierarchies.

```python
class PaymentGateway:
    def __init__(self, api_key: str):
        # Mangled to _PaymentGateway__api_key
        self.__api_key = api_key

    def authenticate(self):
        return f"Authenticated with key: {self.__api_key[:4]}****"

class StripeGateway(PaymentGateway):
    def __init__(self, api_key: str, merchant_id: str):
        super().__init__(api_key)
        # Mangled to _StripeGateway__api_key - DOES NOT overwrite parent's __api_key!
        self.__api_key = "STRIPE_INTERNAL_" + api_key
        self.merchant_id = merchant_id

    def get_stripe_internal(self):
        return self.__api_key

def test_mangling():
    gateway = StripeGateway("sk_live_9921473210", "acct_883")
    
    # Parent method accesses _PaymentGateway__api_key
    print(gateway.authenticate())
    
    # Subclass method accesses _StripeGateway__api_key
    print(f"Subclass key: {gateway.get_stripe_internal()}")

    # Inspect internal __dict__ keys
    print("\nUnderlying Object Dictionary Keys:")
    for k in gateway.__dict__:
        print(f"  {k}")

test_mangling()
```

#### Step-by-Step Explanation:
1. If single underscores were used, `StripeGateway` would accidentally overwrite `_api_key` needed by `PaymentGateway.authenticate()`.
2. Name mangling namespaces the attribute to `_ClassName__attribute`, preserving independent state across class boundaries.

#### Expected Output:
```text
Authenticated with key: sk_l****
Subclass key: STRIPE_INTERNAL_sk_live_9921473210

Underlying Object Dictionary Keys:
  _PaymentGateway__api_key
  _StripeGateway__api_key
  merchant_id
```

### Example 3: Thread-Safe Dynamic Lazy-Loaded Property Cache
Create a reusable lazy property descriptor that computes expensive metrics once and caches the result on the instance.

```python
import time

class LazyProperty:
    def __init__(self, func):
        self.func = func
        self.name = func.__name__

    def __get__(self, instance, cls):
        if instance is None:
            return self
        # Compute value once
        value = self.func(instance)
        # Cache directly onto instance __dict__, bypassing the descriptor on future calls!
        instance.__dict__[self.name] = value
        return value

class DatasetAnalyzer:
    def __init__(self, records: list):
        self.records = records

    @LazyProperty
    def statistical_variance(self) -> float:
        # Simulate heavy analytical computation
        print("Computing heavy statistical variance (simulating 100ms calculation)...")
        time.sleep(0.1)
        mean = sum(self.records) / len(self.records)
        return sum((x - mean) ** 2 for x in self.records) / len(self.records)

def test_lazy_property():
    analyzer = DatasetAnalyzer([12, 45, 67, 89, 23, 56, 78, 90, 11, 34])

    print("--- First Call (Calculated) ---")
    start = time.perf_counter()
    v1 = analyzer.statistical_variance
    elapsed1 = time.perf_counter() - start
    print(f"Variance: {v1:.2f} (Time: {elapsed1*1000:.2f}ms)")

    print("\n--- Second Call (From Instance Cache) ---")
    start = time.perf_counter()
    v2 = analyzer.statistical_variance
    elapsed2 = time.perf_counter() - start
    print(f"Variance: {v2:.2f} (Time: {elapsed2*1000:.2f}ms)")

test_lazy_property()
```

#### Step-by-Step Explanation:
1. `LazyProperty` intercepts the first attribute access, computes the variance, and writes it directly to `instance.__dict__['statistical_variance']`.
2. Subsequent accesses locate the attribute in the instance dictionary directly in sub-microsecond time.

#### Expected Output:
```text
--- First Call (Calculated) ---
Computing heavy statistical variance (simulating 100ms calculation)...
Variance: 772.44 (Time: ~100ms)

--- Second Call (From Instance Cache) ---
Variance: 772.44 (Time: ~0.00ms)
```
