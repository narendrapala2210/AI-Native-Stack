## 1. Conceptual Deep-Dive: The Diamond Problem & C3 MRO

Python supports **Multiple Inheritance**, allowing a class to inherit from more than one base class (`class C(A, B):`).

### The Diamond Problem
When Class `B` and Class `C` both inherit from Class `A`, and Class `D` inherits from both `B` and `C`:
- If `B` and `C` override a method from `A`, which implementation does `D` execute?
- In legacy languages or naive depth-first searches, unpredictable duplicate calls and inconsistencies occur.

### C3 Linearization Algorithm
CPython resolves method resolution order using the **C3 Linearization Algorithm**:
1. **Strict Monotonicity**: If class `A` precedes class `B` in the resolution order of any parent, it must precede `B` in all derived classes.
2. **Local Precedence Order (LPO)**: In `class D(B, C):`, class `B` is always evaluated before `C`.
3. **`super()` Cooperative Multiple Inheritance**:
   - `super()` does NOT simply call the parent class; it calls the **next class in the instance's MRO**!
   - Every class in a cooperative hierarchy must call `super().__init__(...)` and forward keyword arguments.

```python
# Inspecting MRO
class D(B, C): pass
print(D.mro())  # Returns list of classes in exact execution order
```

## 🛠️ Practical Hands-On & Real-World Examples

### Example 1: Resolving the Classic Diamond Problem with Cooperative `super()`
Demonstrate cooperative multiple inheritance across a diamond graph ensuring each constructor runs exactly once.

```python
class BaseEntity:
    def __init__(self, entity_id: str, **kwargs):
        print(f"  [BaseEntity.__init__] entity_id={entity_id}")
        self.entity_id = entity_id
        super().__init__(**kwargs)

class Auditable(BaseEntity):
    def __init__(self, auditor: str = "System", **kwargs):
        print(f"  [Auditable.__init__] auditor={auditor}")
        self.auditor = auditor
        super().__init__(**kwargs)

class Encrypted(BaseEntity):
    def __init__(self, cipher: str = "AES-256", **kwargs):
        print(f"  [Encrypted.__init__] cipher={cipher}")
        self.cipher = cipher
        super().__init__(**kwargs)

class SecureRecord(Auditable, Encrypted):
    def __init__(self, record_name: str, **kwargs):
        print(f"  [SecureRecord.__init__] record_name={record_name}")
        self.record_name = record_name
        super().__init__(**kwargs)

def test_diamond_resolution():
    print("MRO for SecureRecord:")
    for cls in SecureRecord.mro():
        print(f"  -> {cls.__name__}")

    print("\nInstantiating SecureRecord:")
    rec = SecureRecord(
        record_name="Patient_File_01",
        auditor="Compliance_Officer_Bob",
        cipher="ChaCha20",
        entity_id="ENT-991"
    )

test_diamond_resolution()
```

#### Step-by-Step Explanation:
1. `SecureRecord.mro()` dictates the call chain: `SecureRecord` -> `Auditable` -> `Encrypted` -> `BaseEntity` -> `object`.
2. Because every method uses `super().__init__(**kwargs)`, arguments flow cooperatively and `BaseEntity.__init__` executes exactly once.

#### Expected Output:
```text
MRO for SecureRecord:
  -> SecureRecord
  -> Auditable
  -> Encrypted
  -> BaseEntity
  -> object

Instantiating SecureRecord:
  [SecureRecord.__init__] record_name=Patient_File_01
  [Auditable.__init__] auditor=Compliance_Officer_Bob
  [Encrypted.__init__] cipher=ChaCha20
  [BaseEntity.__init__] entity_id=ENT-991
```

### Example 2: Mixin Architecture for Reusable Microservice Logging & Serialization
Build composable components using the Mixin pattern without building rigid deep inheritance trees.

```python
import json

class JsonSerializableMixin:
    # Mixin providing JSON export for any class exposing __dict__
    def to_json(self) -> str:
        # Extract public serializable attributes
        data = {k: v for k, v in self.__dict__.items() if not k.startswith("_")}
        return json.dumps(data, indent=2)

class TimestampedMixin:
    # Mixin attaching creation timestamps
    def __init__(self, **kwargs):
        import time
        self.created_at = time.strftime("%Y-%m-%dT%H:%M:%SZ", time.gmtime())
        super().__init__(**kwargs)

class ServiceTask(TimestampedMixin, JsonSerializableMixin):
    def __init__(self, task_id: str, priority: int, **kwargs):
        self.task_id = task_id
        self.priority = priority
        super().__init__(**kwargs)

def test_mixin():
    task = ServiceTask(task_id="TASK-8812", priority=1)
    print("Serialized Task JSON via Mixin:")
    print(task.to_json())

test_mixin()
```

#### Step-by-Step Explanation:
1. Mixins are lightweight classes providing specific orthogonal behaviors (`JsonSerializableMixin`, `TimestampedMixin`) without storing independent identity.
2. `ServiceTask` composes these functionalities cleanly via multiple inheritance.

#### Expected Output:
```text
Serialized Task JSON via Mixin:
{
  "task_id": "TASK-8812",
  "priority": 1,
  "created_at": "..."
}
```

### Example 3: C3 Linearization Inconsistency Detection (`TypeError`)
Demonstrate an illegal inheritance graph that violates C3 monotonicity and observe Python's error guard.

```python
def demonstrate_c3_violation():
    class X: pass
    class Y: pass
    
    # Class A expects X before Y
    class A(X, Y): pass
    
    # Class B expects Y before X
    class B(Y, X): pass

    print("Attempting to create class C(A, B)...")
    try:
        # Cannot create a consistent linear order where X comes before Y and Y comes before X!
        class C(A, B): pass
    except TypeError as e:
        print(f"C3 Algorithm Protection: {e}")

demonstrate_c3_violation()
```

#### Step-by-Step Explanation:
1. `A` orders `X` before `Y`.
2. `B` orders `Y` before `X`.
3. Creating `class C(A, B)` presents a direct cyclical contradiction. Python's C3 compiler rejects this at class definition time with `TypeError: Cannot create a consistent method resolution order (MRO)`.

#### Expected Output:
```text
Attempting to create class C(A, B)...
C3 Algorithm Protection: Cannot create a consistent method resolution order (MRO) for bases X, Y
```
