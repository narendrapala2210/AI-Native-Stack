## 1. Conceptual Deep-Dive: Zero-Configuration SQL in Python

Python includes the full-featured, zero-configuration **SQLite** database engine in the standard library via `sqlite3`:
1. **Serverless & Embedded**:
   - The entire database runs within the application process.
   - Stores tables, indexes, and records in a single self-contained disk file or in-memory (`:memory:`).
2. **Core Architecture**:
   - **Connection (`sqlite3.connect`)**: Manages transactions, rollback, and commit boundaries.
   - **Cursor (`conn.cursor()`)**: Executes queries and iterates over result rows.
   - **Row Factory (`conn.row_factory`)**: Formats returned records (e.g. `sqlite3.Row` for dictionary-like column access).
3. **Critical Security Rule: Parameterized Queries**:
   - **Never interpolate strings into SQL statements** (`f"SELECT * FROM users WHERE name = '{name}'"` is vulnerable to catastrophic SQL Injection!).
   - Always pass parameters as tuples using placeholders `?` (`conn.execute("SELECT * FROM users WHERE name = ?", (name,))`).

## 🛠️ Practical Hands-On & Real-World Examples

### Example 1: Full CRUD Transaction Pipeline with Parameterized Queries
Create a database table, insert records safely, query rows, and commit transactions.

```python
import sqlite3

def run_database_crud():
    # Use in-memory database for testing (:memory:)
    conn = sqlite3.connect(":memory:")
    cursor = conn.cursor()

    # 1. Create schema
    cursor.execute(
        "CREATE TABLE accounts ("
        "account_id INTEGER PRIMARY KEY AUTOINCREMENT, "
        "owner_name TEXT NOT NULL, "
        "balance REAL NOT NULL, "
        "created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP"
        ")"
    )

    # 2. Parameterized batch insertion
    new_accounts = [
        ("Alice Smith", 4500.50),
        ("Bob Jones", 1200.00),
        ("Charlie Davis", 8950.25)
    ]
    cursor.executemany("INSERT INTO accounts (owner_name, balance) VALUES (?, ?)", new_accounts)
    conn.commit()

    # 3. Query records with safe parameter substitution
    cursor.execute("SELECT account_id, owner_name, balance FROM accounts WHERE balance > ?", (2000.0,))
    rows = cursor.fetchall()

    print("High-Balance Accounts (> $2,000):")
    for r in rows:
        print(f"  ID #{r[0]}: {r[1]:<15} | Balance: ${r[2]:,.2f}")

    conn.close()

run_database_crud()
```

#### Step-by-Step Explanation:
1. `cursor.executemany()` batches insertion in a single compiled statement.
2. `VALUES (?, ?)` uses parameter substitution, protecting against SQL injection attacks.

#### Expected Output:
```text
High-Balance Accounts (> $2,000):
  ID #1: Alice Smith     | Balance: $4,500.50
  ID #3: Charlie Davis   | Balance: $8,950.25
```

### Example 2: Column-Name Access with `sqlite3.Row`
Configure `row_factory` to access database result columns by name instead of numeric indices.

```python
import sqlite3

def test_row_factory():
    conn = sqlite3.connect(":memory:")
    # Enable named column access!
    conn.row_factory = sqlite3.Row

    conn.execute("CREATE TABLE inventory (sku TEXT, item_name TEXT, stock INTEGER)")
    conn.execute("INSERT INTO inventory VALUES ('SKU-100', 'Wireless Keyboard', 45)")
    conn.commit()

    cursor = conn.execute("SELECT * FROM inventory WHERE sku = ?", ('SKU-100',))
    row = cursor.fetchone()

    # Access by column name like a dictionary!
    print("Item Name :", row["item_name"])
    print("Stock Qty :", row["stock"])
    print("Dictionary:", dict(row))

    conn.close()

test_row_factory()
```

#### Step-by-Step Explanation:
1. Setting `conn.row_factory = sqlite3.Row` wraps result tuples into lightweight mappings.
2. `dict(row)` converts the row directly into a Python dictionary.

#### Expected Output:
```text
Item Name : Wireless Keyboard
Stock Qty : 45
Dictionary: {'sku': 'SKU-100', 'item_name': 'Wireless Keyboard', 'stock': 45}
```

### Example 3: Transaction Rollback on Failure using `with conn:`
Ensure atomic multi-step balance transfers rollback completely if any step fails.

```python
import sqlite3

def execute_balance_transfer(conn, sender_id: int, receiver_id: int, amount: float):
    # 'with conn:' creates an automatic transaction context:
    # Commits automatically on success, rolls back automatically on exception!
    with conn:
        # Deduct from sender
        conn.execute("UPDATE accounts SET balance = balance - ? WHERE account_id = ?", (amount, sender_id))
        
        # Simulate an unexpected fault during transfer
        if amount > 5000:
            raise ValueError("Transfer limit exceeded! Transaction aborted.")

        # Credit receiver
        conn.execute("UPDATE accounts SET balance = balance + ? WHERE account_id = ?", (amount, receiver_id))

def test_transaction_rollback():
    conn = sqlite3.connect(":memory:")
    conn.execute("CREATE TABLE accounts (account_id INT, balance REAL)")
    conn.execute("INSERT INTO accounts VALUES (1, 10000.0), (2, 2000.0)")

    print("Initial Balances:")
    print(" ", conn.execute("SELECT * FROM accounts").fetchall())

    # Attempt illegal transfer (> 5000)
    try:
        execute_balance_transfer(conn, sender_id=1, receiver_id=2, amount=7000.0)
    except ValueError as e:
        print(f"\nCaught Expected Fault: {e}")

    print("\nBalances after Rollback (Untouched!):")
    print(" ", conn.execute("SELECT * FROM accounts").fetchall())

    conn.close()

test_transaction_rollback()
```

#### Step-by-Step Explanation:
1. `with conn:` wraps statements in `BEGIN TRANSACTION`.
2. If `ValueError` is raised, Python automatically triggers `ROLLBACK`, guaranteeing sender balance is not deducted.

#### Expected Output:
```text
Initial Balances:
  [(1, 10000.0), (2, 2000.0)]

Caught Expected Fault: Transfer limit exceeded! Transaction aborted.

Balances after Rollback (Untouched!):
  [(1, 10000.0), (2, 2000.0)]
```
