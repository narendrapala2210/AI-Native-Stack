## 1. Conceptual Deep-Dive: Code as Data

Python exposes its compiler internals and runtime call stacks to developers:
1. **The `inspect` Module**:
   - Analyzes live objects: modules, classes, functions, tracebacks, frame objects.
   - `inspect.signature(func)`: Extracts parameters, default values, kind modifiers, and type annotations.
   - `inspect.getsource(func)`: Retrieves raw source code of functions in memory.
   - `inspect.isclass()`, `inspect.isfunction()`, `inspect.iscoroutinefunction()`.
2. **The `ast` Module (Abstract Syntax Tree)**:
   - Python code is parsed into an AST tree before bytecode compilation.
   - `ast.parse(source_string)`: Parses Python code into an AST node tree.
   - `ast.NodeVisitor`: Traverses the tree to analyze code structure, lint for antipatterns, or count function definitions.
   - `ast.NodeTransformer`: Modifies the AST before compilation, enabling code instrumentation.

## 2. Practical Code Examples with Step-by-Step Explanations

### Example 1: Function Signature Binding and Type-Checking with `inspect`
Inspect parameter signatures dynamically and bind arguments to detect mismatches before execution.

```python
import inspect

def process_transaction(user_id: int, amount: float, currency: str = "USD") -> bool:
    return True

def audit_function_parameters(func):
    sig = inspect.signature(func)
    print(f"Function: {func.__name__}")
    print(f"Return Annotation: {sig.return_annotation}")

    print("Parameters:")
    for param_name, param in sig.parameters.items():
        print(f"  {param_name:<10} | Default: {param.default!r:<10} | Type: {param.annotation}")

    # Validate simulated argument bindings
    bound_args = sig.bind(101, 450.50, currency="EUR")
    print(f"Bound Arguments: {bound_args.arguments}")

audit_function_parameters(process_transaction)
```

#### Step-by-Step Explanation:
1. `inspect.signature()` analyzes parameter declarations.
2. `sig.bind()` maps positional and keyword arguments, verifying no required arguments are omitted.

#### Expected Output:
```text
Function: process_transaction
Return Annotation: <class 'bool'>
Parameters:
  user_id    | Default: <class 'inspect._empty'> | Type: <class 'int'>
  amount     | Default: <class 'inspect._empty'> | Type: <class 'float'>
  currency   | Default: 'USD'      | Type: <class 'str'>
Bound Arguments: {'user_id': 101, 'amount': 450.5, 'currency': 'EUR'}
```

### Example 2: Static Code Security Auditor using `ast.NodeVisitor`
Scan Python source code statically using AST to detect forbidden use of dangerous `eval()` and `exec()`.

```python
import ast

class SecurityAuditor(ast.NodeVisitor):
    def __init__(self):
        self.violations = []

    def visit_Call(self, node):
        # Intercept all function call nodes in the syntax tree
        if isinstance(node.func, ast.Name):
            if node.func.id in {"eval", "exec"}:
                self.violations.append((node.func.id, node.lineno))
        # Continue traversing children
        self.generic_visit(node)

sample_code = (
    "x = 10\n"
    "eval('x + 5')\n"
    "print('Clean statement')\n"
    "exec('import os')\n"
)

tree = ast.parse(sample_code)
auditor = SecurityAuditor()
auditor.visit(tree)

print("AST Security Scan Results:")
for func_name, line in auditor.violations:
    print(f"  [ALERT] Forbidden call '{func_name}' found at line {line}")
```

#### Step-by-Step Explanation:
1. `ast.parse()` constructs an AST without executing any of the code.
2. `SecurityAuditor` inherits from `ast.NodeVisitor` and overrides `visit_Call` to inspect every function call in the tree.
3. If an unauthorized function name like `eval` or `exec` is detected, its line number is recorded.

#### Expected Output:
```text
AST Security Scan Results:
  [ALERT] Forbidden call 'eval' found at line 2
  [ALERT] Forbidden call 'exec' found at line 4
```

### Example 3: Inspecting Current Call Stack Frames
Examine active execution stack frames to build custom debuggers and loggers.

```python
import inspect

def innermost_worker():
    # inspect.currentframe() retrieves active CPython execution frame
    current_frame = inspect.currentframe()
    caller_frame = current_frame.f_back

    print(f"Executing Function:   {current_frame.f_code.co_name}")
    print(f"Called By Function:   {caller_frame.f_code.co_name}")
    print(f"Caller Local Context: {caller_frame.f_locals}")

def outer_controller():
    session_id = "sess_abc999"
    innermost_worker()

outer_controller()
```

#### Step-by-Step Explanation:
1. `inspect.currentframe()` accesses the live Python execution frame object.
2. `f_back` navigates up the call stack to inspect the caller's function name and local variable environment.
3. This mechanism powers debuggers (pdb) and structured logging frameworks.

#### Expected Output:
```text
Executing Function:   innermost_worker
Called By Function:   outer_controller
Caller Local Context: {'session_id': 'sess_abc999'}
```

## 3. Key Takeaways & Best Practices

1. Use `inspect.signature` to build dynamic validation engines and dependency injection containers.
2. Use `ast.parse` and `ast.NodeVisitor` to write custom static linters, metrics checkers, and security scanners.
3. Release frame objects after inspecting them (`del current_frame`) to avoid circular references in garbage collection.
