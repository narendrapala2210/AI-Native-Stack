## 1. Conceptual Deep-Dive: Race Conditions & Thread Synchronization

When multiple threads concurrently mutate shared state without coordination, unpredictable **race conditions** and data corruption occur.

Python's `threading` module provides synchronization primitives:
1. **`threading.Lock`**:
   - Mutual exclusion lock (mutex). Only one thread can acquire the lock at a time (`with lock:`).
2. **`threading.RLock` (Reentrant Lock)**:
   - A lock that can be acquired multiple times by the **same** thread without deadlocking.
3. **`threading.Semaphore(value)`**:
   - Maintains an atomic counter, allowing at most $N$ concurrent threads (ideal for connection pool rate-limiting).
4. **`threading.Event`**:
   - Communicates flags between threads (`event.set()`, `event.wait()`).
5. **`queue.Queue`**:
   - Thread-safe FIFO queue with built-in locking for safe Producer-Consumer pipelines.

## 🛠️ Practical Hands-On & Real-World Examples

### Example 1: Preventing Race Conditions with `threading.Lock`
Simulate concurrent bank account deposits demonstrating race condition bugs and the mutex fix.

```python
import threading
import time

class BankAccount:
    def __init__(self):
        self.balance = 0
        self.lock = threading.Lock()

    def deposit_safe(self, amount: int):
        # with self.lock guarantees atomic updates!
        with self.lock:
            curr = self.balance
            time.sleep(0.0001)  # Simulate brief context switch window
            self.balance = curr + amount

def run_concurrent_deposits():
    account = BankAccount()
    threads = []

    # 100 threads each depositing 10
    for _ in range(100):
        t = threading.Thread(target=account.deposit_safe, args=(10,))
        threads.append(t)
        t.start()

    for t in threads:
        t.join()

    print(f"Final Balance (Expected 1000): ${account.balance}")

run_concurrent_deposits()
```

#### Step-by-Step Explanation:
1. Without `self.lock`, threads overwrite each other's intermediate `self.balance` calculations.
2. `with self.lock:` serializes the critical section, ensuring mathematical correctness.

#### Expected Output:
```text
Final Balance (Expected 1000): $1000
```

### Example 2: Thread-Safe Producer-Consumer Pipeline with `queue.Queue`
Coordinate data producers and background workers using thread-safe queues.

```python
import threading
import queue
import time

def worker_consumer(task_queue: queue.Queue, worker_id: int):
    while True:
        task = task_queue.get()
        if task is None:
            # Sentinel signaling termination
            task_queue.task_done()
            break
        print(f"  [Worker #{worker_id}] Processed job: {task}")
        task_queue.task_done()

def test_producer_consumer():
    task_queue = queue.Queue()

    # Spawn 2 consumer threads
    threads = []
    for i in range(2):
        t = threading.Thread(target=worker_consumer, args=(task_queue, i + 1))
        t.start()
        threads.append(t)

    # Producers enqueue work
    for job in ["ResizeImage", "SendEmail", "GeneratePDF", "ComputeAnalytics"]:
        task_queue.put(job)

    # Block until all items processed
    task_queue.join()

    # Send shutdown sentinels
    for _ in range(2): task_queue.put(None)
    for t in threads: t.join()

    print("All queue tasks completed successfully.")

test_producer_consumer()
```

#### Step-by-Step Explanation:
1. `queue.Queue` handles all locking internally; `task_queue.put()` and `.get()` are thread-safe.
2. `task_queue.join()` waits until all items have called `.task_done()`.

#### Expected Output:
```text
  [Worker #1] Processed job: ResizeImage
  [Worker #2] Processed job: SendEmail
  [Worker #1] Processed job: GeneratePDF
  [Worker #2] Processed job: ComputeAnalytics
All queue tasks completed successfully.
```

### Example 3: Rate-Limiting External Resource Access with `threading.Semaphore`
Restrict concurrent access to a simulated resource to at most 3 simultaneous connections.

```python
import threading
import time

# Allow max 3 concurrent threads in critical section
connection_pool = threading.Semaphore(3)

def access_database_connection(client_id: int):
    with connection_pool:
        print(f"Client #{client_id} acquired database connection.")
        time.sleep(0.05)  # Simulate DB query
        print(f"Client #{client_id} released connection.")

def test_semaphore():
    threads = [threading.Thread(target=access_database_connection, args=(i,)) for i in range(6)]
    for t in threads: t.start()
    for t in threads: t.join()

test_semaphore()
```

#### Step-by-Step Explanation:
1. `threading.Semaphore(3)` permits up to 3 threads to enter concurrently; subsequent threads wait until a slot is released.

#### Expected Output:
```text
Client #0 acquired database connection.
Client #1 acquired database connection.
Client #2 acquired database connection.
Client #0 released connection.
Client #3 acquired database connection.
...
```
