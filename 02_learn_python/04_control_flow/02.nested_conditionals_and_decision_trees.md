## 📖 Concept Overview
A **Nested Conditional** is an `if`, `elif`, or `else` block placed inside the repeating body of another conditional statement.

```python
if outer_condition:
    if inner_condition_1:
        # Executes only if both outer and inner 1 are True
    else:
        # Executes if outer is True but inner 1 is False
else:
    # Executes if outer is False
```

### When to Use Nested Conditionals
Nested conditionals model hierarchical **Decision Trees**—situations where secondary criteria only become relevant after a primary condition is satisfied (e.g. evaluating user authorization only after verifying user credentials).

## 🛠️ Practical Hands-On & Real-World Examples

### Example 1: Multi-Factor Authentication (MFA) Verification Gateway
Implement an authentication gatekeeper verifying username/password first, followed by second-factor OTP tokens.

```python
def verify_mfa_login(username_db: dict, input_user: str, input_pass: str, input_otp: str) -> dict:
    if input_user in username_db:
        stored_record = username_db[input_user]
        
        # Nested check 1: Password match
        if stored_record["password"] == input_pass:
            
            # Nested check 2: MFA verification
            if stored_record["mfa_enabled"]:
                if input_otp == stored_record["current_otp"]:
                    return {"status": "SUCCESS", "message": f"Welcome, {input_user}!"}
                else:
                    return {"status": "FAILED", "message": "Invalid MFA OTP code."}
            else:
                return {"status": "SUCCESS", "message": f"Welcome, {input_user} (MFA disabled)."}
                
        else:
            return {"status": "FAILED", "message": "Incorrect password."}
    else:
        return {"status": "FAILED", "message": "User account does not exist."}

db = {
    "admin": {"password": "SecretPassword123", "mfa_enabled": True, "current_otp": "884912"}
}

print("Attempt 1:", verify_mfa_login(db, "admin", "SecretPassword123", "884912")["message"])
print("Attempt 2:", verify_mfa_login(db, "admin", "SecretPassword123", "000000")["message"])
print("Attempt 3:", verify_mfa_login(db, "unknown", "pass", "123")["message"])
```

#### Step-by-Step Explanation:
1. Outer condition verifies account existence.
2. Inner conditions progressively validate password and second-factor security codes.

#### Expected Output:
```text
Attempt 1: Welcome, admin!
Attempt 2: Invalid MFA OTP code.
Attempt 3: User account does not exist.
```

### Example 2: Loan Qualification Risk Matrix
Evaluate home mortgage applications against credit score, debt-to-income (DTI) ratio, and employment status.

```python
def evaluate_loan_eligibility(credit_score: int, dti_ratio: float, employed_years: int) -> str:
    if credit_score >= 720:
        if dti_ratio <= 0.36:
            return "APPROVED: Prime interest rate (3.5%)."
        else:
            if employed_years >= 3:
                return "APPROVED: Standard rate with higher reserve requirement."
            else:
                return "REJECTED: High DTI with insufficient employment history."
    elif 650 <= credit_score < 720:
        if dti_ratio <= 0.28 and employed_years >= 2:
            return "APPROVED: Near-prime rate (4.8%)."
        else:
            return "REJECTED: Marginal credit score requires lower DTI."
    else:
        return "REJECTED: Credit score below minimum lending threshold."

print("Applicant 1:", evaluate_loan_eligibility(750, 0.30, 4))
print("Applicant 2:", evaluate_loan_eligibility(740, 0.40, 1))
print("Applicant 3:", evaluate_loan_eligibility(600, 0.20, 5))
```

#### Step-by-Step Explanation:
1. Structures risk assessment into distinct tiers based on primary credit scores.
2. Evaluates secondary mitigating criteria (DTI and tenure) conditionally.

#### Expected Output:
```text
Applicant 1: APPROVED: Prime interest rate (3.5%).
Applicant 2: REJECTED: High DTI with insufficient employment history.
Applicant 3: REJECTED: Credit score below minimum lending threshold.
```

### Example 3: Guard Clauses & Early Return (Refactoring Deep Nesting)
Demonstrate how deeply nested conditional "arrow code" can be refactored into clean guard clauses with early returns.

```python
# Deeply nested (hard to maintain) vs Guard Clauses (clean)
def validate_withdrawal_clean(balance: float, amount: float, account_active: bool) -> tuple[bool, str]:
    # Guard clause 1: Check account status
    if not account_active:
        return False, "Account is frozen or inactive."
        
    # Guard clause 2: Check valid amount
    if amount <= 0:
        return False, "Withdrawal amount must be positive."
        
    # Guard clause 3: Check sufficient funds
    if amount > balance:
        return False, f"Insufficient balance (${balance:.2f}) for withdrawal (${amount:.2f})."
        
    # Happy path is completely flat!
    new_balance = balance - amount
    return True, f"Withdrawal successful. New balance: ${new_balance:.2f}"

print(validate_withdrawal_clean(500.0, 100.0, True))
print(validate_withdrawal_clean(500.0, 600.0, True))
print(validate_withdrawal_clean(500.0, 100.0, False))
```

#### Step-by-Step Explanation:
1. Guard clauses handle failure and edge conditions at the top of the function.
2. Flattens nested indentations, improving readability.

#### Expected Output:
```text
(True, 'Withdrawal successful. New balance: $400.00')
(False, 'Insufficient balance ($500.00) for withdrawal ($600.00).')
(False, 'Account is frozen or inactive.')
```
