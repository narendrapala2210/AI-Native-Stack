## 1. Conceptual Deep-Dive: Twelve-Factor App Configuration

In production Python applications, AI agents, and enterprise services, hardcoding secrets or configurations in source code creates severe security vulnerabilities and deployment roadblocks.

The **Twelve-Factor App** methodology specifies:
- Store configuration in the environment.
- Maintain strict separation between configuration and source code.
- Ensure identical codebase deploys cleanly across development, staging, and production environments.

Configuration Hierarchy (Highest to Lowest Precedence):
1. Command-line flags (`--port 8080`)
2. System environment variables (`os.environ["DATABASE_URL"]`)
3. Dotenv files (`.env.local`, `.env`)
4. In-code application defaults

---

## 2. Configuration Strategy Comparison

| Approach | Security | Flexibility | Best Use Case |
|---|---|---|---|
| Hardcoded constants | Insecure (committed to Git) | Zero | Never for credentials |
| JSON / YAML config files | Moderate | High | Complex hierarchical parameters |
| Environment variables | High | High | Cloud containers (Docker, K8s) |
| `.env` files | High (when added to `.gitignore`) | High | Local developer workstation setups |

## 3. Practical Code Examples with Step-by-Step Explanations

### Example 1: Custom Dotenv Parser
Parse `.env` files into application configuration without third-party dependencies.

```python
import os

def load_dotenv_custom(filepath: str = ".env"):
    """Reads a .env file and populates os.environ for missing keys."""
    if not os.path.exists(filepath):
        return

    with open(filepath, "r", encoding="utf-8") as f:
        for line in f:
            line = line.strip()
            # Ignore empty lines and comments
            if not line or line.startswith("#") or "=" not in line:
                continue
            
            key, val = line.split("=", 1)
            key = key.strip()
            val = val.strip().strip("'\"")
            
            # System environment takes precedence over .env file
            if key not in os.environ:
                os.environ[key] = val

# Test custom dotenv loader
test_env_content = (
    "# Local configuration\n"
    "APP_ENV=development\n"
    "API_TIMEOUT_SEC=30\n"
    "SECRET_KEY=dev_secret_xyz123\n"
)

with open(".env.test", "w", encoding="utf-8") as f:
    f.write(test_env_content)

load_dotenv_custom(".env.test")

print(f"Loaded APP_ENV:         {os.environ.get('APP_ENV')}")
print(f"Loaded API_TIMEOUT_SEC: {os.environ.get('API_TIMEOUT_SEC')}")

os.remove(".env.test")
```

#### Step-by-Step Explanation:
1. Skips blank lines and comment lines beginning with `#`.
2. Splits on the first `=` sign to handle values containing equal signs.
3. Checks `if key not in os.environ:` so existing system environment variables take precedence over `.env` files.

#### Expected Output:
```text
Loaded APP_ENV:         development
Loaded API_TIMEOUT_SEC: 30
```

### Example 2: Strongly-Typed Application Settings Class
Parse and validate configuration values into native Python types.

```python
import os

class AppConfig:
    def __init__(self):
        self.app_env: str = os.getenv("APP_ENV", "production")
        self.port: int = int(os.getenv("PORT", "8000"))
        self.debug: bool = os.getenv("DEBUG", "False").lower() in ("true", "1", "t")
        self.db_url: str = os.getenv("DATABASE_URL", "sqlite:///default.db")

    def __repr__(self):
        # Mask sensitive secrets in logs
        masked_db = self.db_url.split("@")[-1] if "@" in self.db_url else self.db_url
        return f"AppConfig(env={self.app_env!r}, port={self.port}, debug={self.debug}, db=...{masked_db})"

os.environ["PORT"] = "9000"
os.environ["DEBUG"] = "true"

config = AppConfig()
print(f"Active Configuration: {config}")
print(f"Port type: {type(config.port)}, Debug type: {type(config.debug)}")
```

#### Step-by-Step Explanation:
1. Converts raw environment strings into appropriate types (`int`, `bool`).
2. Provides fallbacks via default values when environment variables are not set.
3. Masks sensitive database connection strings in `__repr__` to prevent accidental credential leakage in log files.

#### Expected Output:
```text
Active Configuration: AppConfig(env='production', port=9000, debug=True, db=...sqlite:///default.db)
Port type: <class 'int'>, Debug type: <class 'bool'>
```

### Example 3: Dynamic Fallback Resolution Chain
Resolve configuration values across CLI arguments, environment variables, and defaults.

```python
import os

def resolve_config(cli_val: str | None, env_key: str, default: str) -> str:
    """Resolves value using precedence: CLI > Environment > Default."""
    if cli_val is not None:
        return cli_val
    return os.getenv(env_key, default)

os.environ["LOG_LEVEL"] = "WARNING"

# Scenario A: CLI argument provided (takes precedence)
level_a = resolve_config(cli_val="DEBUG", env_key="LOG_LEVEL", default="INFO")
print(f"Scenario A (CLI override):     {level_a}")

# Scenario B: No CLI argument provided (falls back to environment variable)
level_b = resolve_config(cli_val=None, env_key="LOG_LEVEL", default="INFO")
print(f"Scenario B (Environment var):  {level_b}")

# Scenario C: Neither provided (falls back to default)
level_c = resolve_config(cli_val=None, env_key="UNDEFINED_KEY", default="INFO")
print(f"Scenario C (Default fallback): {level_c}")
```

#### Step-by-Step Explanation:
1. Implements strict precedence: CLI arguments override environment variables, which override defaults.
2. Provides predictable configuration resolution across all environments.

#### Expected Output:
```text
Scenario A (CLI override):     DEBUG
Scenario B (Environment var):  WARNING
Scenario C (Default fallback): INFO
```

---

## 4. Key Takeaways & Best Practices

1. Never commit `.env` files to source control; always add `.env` to `.gitignore` and supply a `.env.example` template.
2. Validate and cast environment variables to concrete types (`int`, `bool`, `Path`) during application startup.
3. Mask sensitive API keys and database credentials in logs and exception tracebacks.
