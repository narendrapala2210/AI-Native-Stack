## 1. Conceptual Deep-Dive: File System & Deserialization Risks

### 1. Path Traversal (Dot-Dot-Slash Attacks)
Applications that accept filenames from user input (e.g. file downloads, avatar uploads) can allow attackers to navigate out of the designated directory using relative path sequences (`../` or `..\`), exposing sensitive system files like `/etc/passwd`.

### 2. Insecure Deserialization (`pickle` Vulnerabilities)
Python's built-in `pickle` module serializes arbitrary Python object graphs. During unpickling (`pickle.loads`), it automatically invokes the `__reduce__` method, which can execute arbitrary callable functions (including `os.system` and `subprocess.Popen`) during deserialization.

> [!CAUTION]
> Never unpickle untrusted data from network requests, user uploads, or shared caches. `pickle` is not secure against maliciously crafted data.

```
Attacker Payload:
b"\x80\x04\x95...\x8c\x02os\x94\x8c\x06system\x94..."
            |
            V pickle.loads()
Executes: os.system("arbitrary_command") during deserialization!
```

## 2. Insecure vs. Secure Comparison

| Vulnerability | Vulnerable Pattern | Secure Pattern |
|---|---|---|
| Path Traversal | `open(base_dir + "/" + filename)` | `path.resolve().is_relative_to(base_dir)` |
| Deserialization | `pickle.loads(untrusted_bytes)` | `json.loads()` or schema-validated Pydantic / MsgPack |
| Insecure YAML | `yaml.load(data, Loader=Loader)` | `yaml.safe_load(data)` |

## 3. Practical Code Examples with Step-by-Step Explanations

### Example 1: Defending Against Path Traversal with `pathlib.Path.resolve`
Validate that requested file paths stay inside the intended base directory.

```python
from pathlib import Path

BASE_STORAGE_DIR = Path("/var/app/uploads").resolve()

def safe_open_user_file(requested_filename: str, base_dir: Path) -> Path:
    # Resolve requested path to an absolute path, normalizing dots
    target_path = (base_dir / requested_filename).resolve()

    # Verify target path is strictly contained within base_dir
    try:
        # Python 3.9+ is_relative_to
        if not target_path.is_relative_to(base_dir):
            raise PermissionError("Path traversal attack detected!")
    except AttributeError:
        # Fallback for Python < 3.9
        if base_dir not in target_path.parents and target_path != base_dir:
            raise PermissionError("Path traversal attack detected!")

    return target_path

# Normal file access
valid_path = safe_open_user_file("report.pdf", BASE_STORAGE_DIR)
print(f"Valid path permitted: {valid_path}")

# Malicious path traversal attempt
malicious_input = "../../etc/passwd"
try:
    safe_open_user_file(malicious_input, BASE_STORAGE_DIR)
except PermissionError as exc:
    print(f"Defended against traversal attack: {exc}")
```

#### Step-by-Step Explanation:
1. `(base_dir / user_input).resolve()` normalizes relative dot segments (`../`) into an absolute path.
2. `target_path.is_relative_to(base_dir)` verifies the resolved path starts within `base_dir`.
3. If the path navigates outside the folder, access is blocked before opening the file.

#### Expected Output:
```text
Valid path permitted: .../var/app/uploads/report.pdf
Defended against traversal attack: Path traversal attack detected!
```

### Example 2: The Dangers of `pickle` and Secure Alternatives
Demonstrate why `pickle` cannot be used with untrusted data and how to use `json` instead.

```python
import json

# How attackers construct exploit payloads with pickle:
class MaliciousExploit:
    def __reduce__(self):
        # __reduce__ returns a callable and arguments to execute during unpickling
        import os
        return (os.system, ("echo [VULNERABILITY] Arbitrary command executed!",))

# SECURE ALTERNATIVE: Use strict data-only formats like JSON
safe_data = {
    "user_id": 105,
    "role": "editor",
    "permissions": ["read", "write"],
}

# Serialize to JSON string
serialized = json.dumps(safe_data)

# Deserialize safely: JSON contains only raw data, never executable instructions
deserialized = json.loads(serialized)
print(f"Safely deserialized JSON data: {deserialized}")
```

#### Step-by-Step Explanation:
1. `pickle` executes callable instructions returned by `__reduce__` during deserialization.
2. Standard data interchange formats like JSON, MessagePack, and Protocol Buffers represent only data structures, eliminating code execution risks.

#### Expected Output:
```text
Safely deserialized JSON data: {'user_id': 105, 'role': 'editor', 'permissions': ['read', 'write']}
```

### Example 3: Safe YAML Deserialization with `safe_load`
Prevent arbitrary object instantiation when parsing YAML configuration files.

```python
# Demonstrating the difference between PyYAML load modes:
insecure_yaml = """
# Dangerous: creates arbitrary Python objects
!!python/object/apply:os.system ["echo Hacked!"]
"""

explanation = """
When parsing YAML in Python:
1. NEVER use `yaml.load(stream, Loader=yaml.Loader)`
2. ALWAYS use `yaml.safe_load(stream)`

`safe_load` restricts parsing to standard YAML data types
(lists, maps, scalars) and rejects custom Python tags.
"""

print(explanation.strip())
```

#### Step-by-Step Explanation:
1. PyYAML's default loader supports Python object tags (`!!python/object`), allowing attackers to run arbitrary code.
2. `yaml.safe_load()` disables Python object tag evaluation, parsing only standard data types.

#### Expected Output:
```text
When parsing YAML in Python:
1. NEVER use `yaml.load(stream, Loader=yaml.Loader)`
2. ALWAYS use `yaml.safe_load(stream)`
...
```

## 4. Key Takeaways & Best Practices

1. Always use `Path.resolve().is_relative_to(base_dir)` to defend against path traversal attacks.
2. Never deserialize untrusted network data using `pickle`; use JSON, Pydantic, or Protocol Buffers.
3. Always use `yaml.safe_load()` instead of `yaml.load()` when parsing YAML configurations.
