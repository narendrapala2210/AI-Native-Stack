## 1. Conceptual Deep-Dive: Built-in Testing Mechanics

Python ships with two distinct built-in testing frameworks in the standard library:
1. **`unittest` (xUnit style)**:
   - Object-oriented test suites inspired by JUnit.
   - Core constructs: `TestCase`, `TestSuite`, `TestRunner`, and `TestResult`.
   - Fixture lifecycle: `setUp()`, `tearDown()`, `setUpClass()`, `tearDownClass()`.
2. **`doctest` (Documentation-driven testing)**:
   - Embeds interactive Python sessions directly into docstrings (`>>>`).
   - Verifies that docstring code snippets remain accurate and act as live, regression-tested documentation.

```
       +-----------------------+
       |   unittest.TestCase   |
       +-----------------------+
                   |
     +-------------+-------------+
     |                           |
setUp() / tearDown()    assert* Methods
(Per-test isolation)    (assertEqual, assertRaises, etc.)
```

## 2. Assertion Matrix & Test Lifecycle

| Method | Check Condition | Use Case |
|---|---|---|
| `assertEqual(a, b)` | `a == b` | Value equality check |
| `assertIs(a, b)` | `a is b` | Identity & singleton validation |
| `assertTrue(x)` / `assertFalse(x)` | `bool(x)` | Boolean state flags |
| `assertRaises(exc)` | Context manager / callable raises `exc` | Defensive error checking |
| `assertAlmostEqual(a, b, places=N)` | `round(a - b, N) == 0` | Floating-point numerical validation |

## 3. Practical Code Examples with Step-by-Step Explanations

### Example 1: Comprehensive `unittest.TestCase` with Fixture Lifecycle
Demonstrate stateful testing with setUp, assertions, and teardown.

```python
import unittest

class BankAccount:
    def __init__(self, owner: str, initial_balance: float = 0.0):
        if initial_balance < 0:
            raise ValueError("Initial balance cannot be negative")
        self.owner = owner
        self.balance = initial_balance

    def deposit(self, amount: float) -> float:
        if amount <= 0:
            raise ValueError("Deposit must be positive")
        self.balance += amount
        return self.balance

    def withdraw(self, amount: float) -> float:
        if amount > self.balance:
            raise RuntimeError("Insufficient funds")
        self.balance -= amount
        return self.balance

class TestBankAccount(unittest.TestCase):
    def setUp(self):
        """Runs prior to each test method."""
        self.account = BankAccount("Alice", 100.0)

    def tearDown(self):
        """Runs after each test method."""
        self.account = None

    def test_deposit_success(self):
        new_bal = self.account.deposit(50.0)
        self.assertEqual(new_bal, 150.0)
        self.assertEqual(self.account.balance, 150.0)

    def test_insufficient_funds_raises(self):
        with self.assertRaises(RuntimeError) as ctx:
            self.account.withdraw(200.0)
        self.assertIn("Insufficient funds", str(ctx.exception))

if __name__ == "__main__":
    suite = unittest.TestLoader().loadTestsFromTestCase(TestBankAccount)
    runner = unittest.TextTestRunner(verbosity=2)
    runner.run(suite)
```

#### Step-by-Step Explanation:
1. `setUp()` executes before every single test method, guaranteeing an isolated `BankAccount` instance with 100.0 balance.
2. `self.assertRaises(RuntimeError)` captures expected failure exceptions inside a context manager, permitting error message inspection via `ctx.exception`.
3. `unittest.TextTestRunner` programmatically executes the test suite.

#### Expected Output:
```text
test_deposit_success (__main__.TestBankAccount) ... ok
test_insufficient_funds_raises (__main__.TestBankAccount) ... ok

----------------------------------------------------------------------
Ran 2 tests in 0.001s

OK
```

### Example 2: Doctest for Executable Code Documentation
Verify documentation snippets automatically using `doctest`.

```python
import doctest

def calculate_compound_interest(principal: float, rate: float, periods: int) -> float:
    """Calculates final amount with compound interest.

    Formula: A = P * (1 + r) ** n

    >>> calculate_compound_interest(1000.0, 0.05, 1)
    1050.0
    >>> round(calculate_compound_interest(1000.0, 0.05, 2), 2)
    1102.5
    >>> calculate_compound_interest(-50, 0.05, 1)
    Traceback (most recent call last):
        ...
    ValueError: Principal must be non-negative
    """
    if principal < 0:
        raise ValueError("Principal must be non-negative")
    return principal * ((1.0 + rate) ** periods)

if __name__ == "__main__":
    results = doctest.testmod(verbose=True)
    print(f"\nDoctest Results: Failed={results.failed}, Attempted={results.attempted}")
```

#### Step-by-Step Explanation:
1. `>>>` denotes interactive prompt lines within the docstring.
2. `Traceback (most recent call last): ...` matches exception outputs, where `...` acts as an ellipsis wildcard.
3. `doctest.testmod()` parses the module docstrings, evaluates the examples, and reports pass/fail tallies.

#### Expected Output:

### Example 3: Test Discovery and SubTest Matrix
Demonstrate `subTest` for parameter-driven data matrix testing without aborting the test suite on early failure.

```python
import unittest

def parse_iso_date(date_str: str) -> tuple[int, int, int]:
    parts = date_str.split("-")
    if len(parts) != 3:
        raise ValueError(f"Invalid format: {date_str}")
    return int(parts[0]), int(parts[1]), int(parts[2])

class TestDateParser(unittest.TestCase):
    def test_valid_dates(self):
        test_matrix = [
            ("2026-01-01", (2026, 1, 1)),
            ("2025-12-31", (2025, 12, 31)),
            ("2000-02-29", (2000, 2, 29)),
        ]
        for input_str, expected in test_matrix:
            with self.subTest(date_input=input_str):
                self.assertEqual(parse_iso_date(input_str), expected)

if __name__ == "__main__":
    unittest.main(verbosity=2)
```

#### Step-by-Step Explanation:
1. Standard loops inside test methods fail on the first assertion failure, concealing subsequent results.
2. `self.subTest(...)` treats each iteration as an independent sub-test, recording failures individually while running all items.

#### Expected Output:
```text
test_valid_dates (__main__.TestDateParser) ... ok

----------------------------------------------------------------------
Ran 1 test in 0.001s

OK
```

---

## 4. Key Takeaways & Best Practices

1. Use `doctest` to guarantee that user-facing library documentation and README examples do not decay.
2. Use `subTest` for table-driven unit tests when you want full test suite visibility across parameterized payloads.
3. Keep `setUp()` minimal and fast to maintain microsecond execution speeds across thousands of unit tests.
