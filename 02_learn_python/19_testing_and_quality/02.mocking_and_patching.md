## 1. Conceptual Deep-Dive: Test Doubles and `unittest.mock`

When testing complex software, dependencies like network APIs, databases, message brokers, or system clocks introduce non-determinism and latency. **Mocking** replaces real dependencies with controllable test doubles.

Core constructs in `unittest.mock`:
- **`Mock`**: A generic dummy object that tracks call history, arguments, and return values.
- **`MagicMock`**: A subclass of `Mock` that automatically implements Python magic dunder methods (`__iter__`, `__enter__`, `__len__`, `__getitem__`).
- **`patch`**: A context manager or decorator that dynamically intercepts symbol lookups during test execution and restores the original object upon completion.

```
+-----------------------------------------------------------+
|                      patch Decorator                      |
|  1. Intercepts target module attribute                    |
|  2. Injects MagicMock during test run                     |
|  3. Reverts attribute to original state on test teardown  |
+-----------------------------------------------------------+
```

---

## 2. Mock Assertion & Configuration Guide

| Attribute / Method | Description |
|---|---|
| `mock.return_value = X` | Fixed value returned on every invocation |
| `mock.side_effect = [A, B, C]` | Returns sequential items or raises exceptions if given an Exception class |
| `mock.assert_called_once()` | Verifies exactly one invocation occurred |
| `mock.assert_called_with(*args, **kwargs)` | Asserts invocation arguments match expected values |
| `patch.object(target, attribute)` | Patches specific attribute on an in-memory class or object |

## 3. Practical Code Examples with Step-by-Step Explanations

### Example 1: Basic `MagicMock` Call Inspection and Side Effects
Inspect mock interactions and dynamic exceptions.

```python
from unittest.mock import MagicMock

def fetch_exchange_rate(service_client, currency: str) -> float:
    return service_client.get_rate(currency)

# Instantiate mock
mock_client = MagicMock()
mock_client.get_rate.return_value = 1.085

# Test execution
rate = fetch_exchange_rate(mock_client, "EUR")
print(f"Fetched rate: {rate}")

# Assert calls
mock_client.get_rate.assert_called_once_with("EUR")
print("Assertion passed: get_rate was called once with 'EUR'")

# Demonstrate side_effect exception
mock_client.get_rate.side_effect = ConnectionError("Gateway Timeout")
try:
    fetch_exchange_rate(mock_client, "JPY")
except ConnectionError as exc:
    print(f"Captured expected mock side-effect: {exc}")
```

#### Step-by-Step Explanation:
1. `mock_client.get_rate.return_value` defines the deterministic output for any call.
2. `assert_called_once_with("EUR")` confirms our code passed the exact expected parameter.
3. Assigning an exception class to `side_effect` forces the mock to raise on call, testing error recovery branches.

#### Expected Output:
```text
Fetched rate: 1.085
Assertion passed: get_rate was called once with 'EUR'
Captured expected mock side-effect: Gateway Timeout
```

### Example 2: Patching Network HTTP Calls with `@patch`
Patch external `urllib.request` calls to test API clients without network traffic.

```python
import urllib.request
import json
from unittest.mock import patch, MagicMock

def get_user_status(user_id: int) -> str:
    url = f"https://api.example.com/users/{user_id}"
    with urllib.request.urlopen(url) as response:
        data = json.loads(response.read().decode("utf-8"))
        return data["status"]

# Test using patch as context manager
with patch("urllib.request.urlopen") as mock_urlopen:
    # Build fake HTTP response mock with context management support
    fake_response = MagicMock()
    fake_response.read.return_value = b'{"user_id": 42, "status": "active"}'
    fake_response.__enter__.return_value = fake_response
    mock_urlopen.return_value = fake_response

    status = get_user_status(42)
    print(f"Mocked User Status: {status}")
    mock_urlopen.assert_called_once_with("https://api.example.com/users/42")

print("Patching reverted successfully. Real urllib.request.urlopen restored.")
```

#### Step-by-Step Explanation:
1. `patch("urllib.request.urlopen")` targets where the function is looked up.
2. `fake_response.__enter__.return_value = fake_response` simulates Python's context manager protocol (`with urllib.request.urlopen(...)`).
3. Exiting the `with patch(...)` context automatically restores the original function, eliminating test pollution.

#### Expected Output:
```text
Mocked User Status: active
Patching reverted successfully. Real urllib.request.urlopen restored.
```

### Example 3: `patch.object` and `autospec=True` for Type Safety
Prevent mock drift by using autospeccing against real object signatures.

```python
from unittest.mock import patch, create_autospec

class PaymentGateway:
    def process_charge(self, customer_id: str, amount_cents: int) -> str:
        # Real production implementation talks to payment network
        return "charge_real_12345"

# Auto-spec creates a mock conforming strictly to the class's method signatures
strict_mock = create_autospec(PaymentGateway, instance=True)

# Calling with valid parameters succeeds
strict_mock.process_charge.return_value = "charge_mock_9999"
result = strict_mock.process_charge("cust_404", 5000)
print(f"Auto-specced result: {result}")

# Calling with invalid parameter signature fails at test time!
try:
    # Invalid argument count (missing amount_cents)
    strict_mock.process_charge("cust_404")
except TypeError as e:
    print(f"Caught signature violation error: {e}")
```

#### Step-by-Step Explanation:
1. Standard mocks accept any method name and any arguments, which can hide breaking API changes.
2. `create_autospec(..., instance=True)` copies the exact method signature of `PaymentGateway`.
3. Invoking `process_charge` with incorrect parameters immediately raises `TypeError`, catching integration bugs during unit tests.

#### Expected Output:
```text
Auto-specced result: charge_mock_9999
Caught signature violation error: missing a required argument: 'amount_cents'
```

---

## 4. Key Takeaways & Best Practices

1. **Where to patch**: Patch where an object is *looked up*, not where it is *defined*.
2. Always use `autospec=True` with `patch` or `create_autospec` to prevent tests from passing against outdated method signatures.
3. Keep mock boundaries at system edges (external I/O, clock, database); avoid mocking internal domain entities.
