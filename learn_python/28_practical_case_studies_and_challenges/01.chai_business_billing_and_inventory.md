## 1. Project Overview & Business Domain

In this capstone case study (inspired by retail enterprise systems and real-world beverage point-of-sale platforms), we build a complete, modular **Point-of-Sale (POS) Billing & Inventory Management Engine**:
- **Menu & Recipe Management**: Object-oriented models tracking unit costs, retail prices, and recipe ingredients.
- **Inventory Stock Deduction**: Atomic stock validation and real-time inventory deductions.
- **Dynamic Pricing & Taxation**: Multi-tier volume discounts, coupon application, and regional sales tax calculation.
- **Receipt & Ledger Persistence**: Generating structured human-readable text receipts and appending transaction records to JSON ledger logs.

```
+-----------------------------------------------------------+
|               Chai Business System Flow                   |
|                                                           |
| 1. Customer Order ---> [ Order Processor ]                |
|                              |                            |
|                              +---> [ Stock Verifier ]     |
|                              |            |               |
|                              |            V (Has stock?)  |
|                              +---> [ Pricing & Tax ]      |
|                              |            |               |
|                              |            V               |
|                              +---> [ Deduct Inventory ]   |
|                              |            |               |
|                              |            V               |
|                              +---> [ Render Receipt ]     |
|                              |            |               |
|                              V            V               |
|                      JSON Transaction Ledger              |
+-----------------------------------------------------------+
```

## 3. Practical Code Examples with Step-by-Step Explanations

### Example 1: Object-Oriented Inventory Management & Stock Check
Build the core data models and stock management engine with atomic checks.

```python
from dataclasses import dataclass, field

@dataclass(frozen=True)
class MenuItem:
    sku: str
    name: str
    price: float
    # Ingredients needed per unit: e.g. {"tea_leaves_g": 10, "milk_ml": 150, "sugar_g": 15}
    recipe: dict[str, float] = field(default_factory=dict)

class InventoryManager:
    def __init__(self, initial_stock: dict[str, float]):
        self._stock = initial_stock.copy()

    def has_sufficient_stock(self, item: MenuItem, quantity: int) -> bool:
        for ingredient, required_per_unit in item.recipe.items():
            total_required = required_per_unit * quantity
            if self._stock.get(ingredient, 0.0) < total_required:
                return False
        return True

    def deduct_stock(self, item: MenuItem, quantity: int):
        if not self.has_sufficient_stock(item, quantity):
            raise ValueError(f"Insufficient stock to prepare {quantity}x {item.name}")
        for ingredient, required_per_unit in item.recipe.items():
            self._stock[ingredient] -= required_per_unit * quantity

    def get_stock_report(self) -> dict[str, float]:
        return self._stock.copy()

# Initialize inventory
raw_materials = {
    "tea_leaves_g": 500.0,
    "milk_ml": 2000.0,
    "sugar_g": 1000.0,
    "spices_g": 100.0
}
inventory = InventoryManager(raw_materials)

masala_chai = MenuItem(
    sku="CHAI-01",
    name="Masala Chai",
    price=3.50,
    recipe={"tea_leaves_g": 10.0, "milk_ml": 100.0, "sugar_g": 10.0, "spices_g": 2.0}
)

print(f"Can fulfill 10 Masala Chais: {inventory.has_sufficient_stock(masala_chai, 10)}")
inventory.deduct_stock(masala_chai, 10)
print(f"Remaining stock after 10 chais: {inventory.get_stock_report()}")
```

#### Step-by-Step Explanation:
1. `MenuItem` uses `frozen=True` dataclass semantics to guarantee immutability across the catalog.
2. `has_sufficient_stock()` verifies that all required raw materials are present before altering state.
3. `deduct_stock()` atomically reduces inventory counts when an order is confirmed.

#### Expected Output:
```text
Can fulfill 10 Masala Chais: True
Remaining stock after 10 chais: {'tea_leaves_g': 400.0, 'milk_ml': 1000.0, 'sugar_g': 900.0, 'spices_g': 80.0}
```

### Example 2: Dynamic Pricing, Discount Rules & Taxation
Calculate subtotals, apply tiered customer discounts, and compute tax.

```python
class BillingEngine:
    TAX_RATE = 0.085  # 8.5% sales tax

    @staticmethod
    def calculate_bill(order_items: list[tuple[MenuItem, int]], discount_code: str = None) -> dict:
        subtotal = 0.0
        line_items = []

        for item, qty in order_items:
            line_total = item.price * qty
            subtotal += line_total
            line_items.append({
                "name": item.name,
                "qty": qty,
                "unit_price": item.price,
                "total": line_total
            })

        # Apply discount logic
        discount_pct = 0.0
        if discount_code == "CHAI10":
            discount_pct = 0.10
        elif subtotal >= 50.0:  # Volume discount for large orders
            discount_pct = 0.15

        discount_amount = subtotal * discount_pct
        taxable_amount = subtotal - discount_amount
        tax_amount = taxable_amount * BillingEngine.TAX_RATE
        grand_total = taxable_amount + tax_amount

        return {
            "lines": line_items,
            "subtotal": round(subtotal, 2),
            "discount_amount": round(discount_amount, 2),
            "tax_amount": round(tax_amount, 2),
            "grand_total": round(grand_total, 2)
        }

ginger_chai = MenuItem("CHAI-02", "Ginger Chai", 4.00)
order = [(masala_chai, 5), (ginger_chai, 10)]

bill = BillingEngine.calculate_bill(order, discount_code="CHAI10")
print(f"Subtotal:       ${bill['subtotal']:.2f}")
print(f"Discount (15%): -${bill['discount_amount']:.2f} (Volume tier beat coupon!)")
print(f"Sales Tax:      ${bill['tax_amount']:.2f}")
print(f"Grand Total:    ${bill['grand_total']:.2f}")
```

#### Step-by-Step Explanation:
1. Iterates through the order items to compute line totals and cumulative subtotal.
2. Evaluates discount precedence (orders $\ge \$50$ receive 15% volume discount over the 10% coupon).
3. Applies sales tax to the discounted taxable base, returning rounded financial values.

#### Expected Output:
```text
Subtotal:       $57.50
Discount (15%): -$8.62 (Volume tier beat coupon!)
Sales Tax:      $4.15
Grand Total:    $53.03
```

### Example 3: Receipt Formatting & Transaction Ledger Export
Generate a professional customer receipt and append transaction records to a JSON file.

```python
import json
from datetime import datetime

class ReceiptPrinter:
    @staticmethod
    def format_receipt(bill_data: dict, order_id: str) -> str:
        lines = []
        lines.append("=" * 40)
        lines.append(f"{'ROYAL CHAI COMPANY':^40}")
        lines.append(f"{'Order ID: ' + order_id:^40}")
        lines.append(f"{datetime.now().strftime('%Y-%m-%d %H:%M:%S'):^40}")
        lines.append("=" * 40)
        lines.append(f"{'Item':<18}{'Qty':>4}  {'Price':>7} {'Total':>7}")
        lines.append("-" * 40)

        for line in bill_data["lines"]:
            name = line["name"][:17]
            lines.append(f"{name:<18}{line['qty']:>4}  ${line['unit_price']:>6.2f} ${line['total']:>6.2f}")

        lines.append("-" * 40)
        lines.append(f"{'Subtotal:':<28} ${bill_data['subtotal']:>9.2f}")
        lines.append(f"{'Discount:':<28}-${bill_data['discount_amount']:>9.2f}")
        lines.append(f"{'Tax (8.5%):':<28} ${bill_data['tax_amount']:>9.2f}")
        lines.append("=" * 40)
        lines.append(f"{'GRAND TOTAL:':<28} ${bill_data['grand_total']:>9.2f}")
        lines.append("=" * 40)
        lines.append(f"{'Thank you for your visit!':^40}")
        lines.append("=" * 40)
        return "\n".join(lines)

receipt_text = ReceiptPrinter.format_receipt(bill, "ORD-8821")
print(receipt_text)

# Append to ledger
ledger_record = {
    "order_id": "ORD-8821",
    "timestamp": datetime.now().isoformat(),
    "grand_total": bill["grand_total"]
}
print(f"\nLedger Transaction Logged: {json.dumps(ledger_record)}")
```

#### Step-by-Step Explanation:
1. Uses string alignment format specifiers (`^40`, `<18`, `>4`, `>6.2f`) to construct structured receipt layouts.
2. Formats all monetary calculations to 2 decimal places.
3. Produces clean JSON logs suitable for streaming to audit trails or accounting software.

#### Expected Output:
```text
========================================
           ROYAL CHAI COMPANY           
           Order ID: ORD-8821           
          2026-09-14 14:...             
========================================
Item                 Qty    Price   Total
----------------------------------------
Masala Chai            5  $  3.50 $ 17.50
Ginger Chai           10  $  4.00 $ 40.00
----------------------------------------
Subtotal:                    $    57.50
Discount:                   -$     8.62
Tax (8.5%):                  $     4.15
========================================
GRAND TOTAL:                 $    53.03
========================================
       Thank you for your visit!        
========================================

Ledger Transaction Logged: {"order_id": "ORD-8821", "timestamp": "...", "grand_total": 53.03}
```

## 4. Key Takeaways & Enterprise Best Practices

1. Separate inventory validation logic from financial calculation engines to adhere to the Single Responsibility Principle (SRP).
2. Use immutable data representations (`dataclasses(frozen=True)`) for product definitions to prevent accidental catalog tampering during transactions.
3. In production systems handling currency, use `decimal.Decimal` instead of floating-point numbers to prevent binary rounding inaccuracies.
