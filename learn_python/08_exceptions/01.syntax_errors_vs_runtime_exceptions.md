## 📖 Concept Overview
Errors in Python fall into two major categories:

---

### 1. Syntax Errors (Parsing Errors)
Occur when code violates Python grammatical rules. The CPython parser detects syntax errors **during the initial compilation phase BEFORE any code begins executing**:
- Examples: Missing colons, unmatched quotes, invalid indentation, misspelled keywords.
```python
# SyntaxError: invalid syntax (missing colon)
if True
    print("Hello")
```

---

### 2. Runtime Exceptions
Occur when code is syntactically valid, but an error condition arises **during execution**:
- Examples: Division by zero (`ZeroDivisionError`), accessing missing key (`KeyError`), index out of bounds (`IndexError`), type mismatches (`TypeError`).
```python
# Syntactically valid, but raises ZeroDivisionError at runtime:
print(10 / 0)
```

### 3. The Exception Class Hierarchy: BaseException vs. Exception
All built-in and user-defined exceptions form an inheritance tree rooted at `BaseException`. Understanding the distinction between `BaseException` and `Exception` is crucial for writing robust software:

```text
BaseException
├── SystemExit            (Triggered by sys.exit() to terminate process)
├── KeyboardInterrupt     (Triggered by user pressing Ctrl+C)
├── GeneratorExit         (Triggered when a generator or coroutine closes)
└── Exception             (Root of all standard application exceptions)
    ├── ArithmeticError   (ZeroDivisionError, OverflowError)
    ├── LookupError       (IndexError, KeyError)
    ├── ValueError        (Invalid argument values)
    ├── TypeError         (Incompatible operand types)
    └── CustomApplicationError (Inherits from Exception!)
```

> [!WARNING]
> **Anti-Pattern Warning**: Never write `except BaseException:` or bare `except:`. This intercepts `KeyboardInterrupt` (preventing users from stopping runaway scripts with Ctrl+C) and `SystemExit` (preventing clean container or orchestrator shutdowns). Always catch `Exception` or concrete derived exception types.

## 📋 Common Built-in Exceptions Reference

| Exception | Common Trigger Condition | Example |
| :--- | :--- | :--- |
| `ZeroDivisionError` | Division or modulo by numeric zero | `10 / 0` |
| `ValueError` | Right type, but inappropriate value | `int("abc")` |
| `TypeError` | Operation applied to incompatible type | `'str' + 5` |
| `IndexError` | Sequence index out of bounds | `[1, 2][5]` |
| `KeyError` | Mapping key absent from dictionary | `{}[ 'missing' ]` |
| `NameError` | Identifier not found in any LEGB scope | `print(unknown_var)` |

## 🛠️ Practical Hands-On & Real-World Examples

### Example 1: Differentiating Compile-Time Syntax Errors from Runtime Exceptions
Demonstrate that a syntax error prevents any code from executing, whereas a runtime exception executes prior valid statements.

```python
def demonstrate_runtime_flow():
    print("Step 1: Application initialization starting...")
    print("Step 2: Connecting to primary data stream...")
    
    # Syntactically sound, but triggers runtime ZeroDivisionError:
    denominator = 0
    try:
        ratio = 100 / denominator
    except ZeroDivisionError as err:
        print(f"[RECOVERED] Runtime exception caught: {err}")
        
    print("Step 3: Execution resumed successfully!")

demonstrate_runtime_flow()
```

#### Step-by-Step Explanation:
1. Steps 1 and 2 execute normally.
2. The runtime error is trapped and handled, allowing Step 3 to complete.

#### Expected Output:
```text
Step 1: Application initialization starting...
Step 2: Connecting to primary data stream...
[RECOVERED] Runtime exception caught: division by zero
Step 3: Execution resumed successfully!
```

### Example 2: Common Exception Tracing & Diagnostics Catalog
Trigger and inspect the error messages of common Python built-in runtime exceptions.

```python
def catalog_common_exceptions():
    # 1. ValueError
    try:
        num = int("forty-two")
    except ValueError as e:
        print(f"1. ValueError caught : {e}")

    # 2. TypeError
    try:
        res = "Score: " + 100
    except TypeError as e:
        print(f"2. TypeError caught  : {e}")

    # 3. IndexError
    try:
        item = ["apple"][3]
    except IndexError as e:
        print(f"3. IndexError caught : {e}")

    # 4. KeyError
    try:
        val = {"id": 1}["email"]
    except KeyError as e:
        print(f"4. KeyError caught   : Key {e} not found in dictionary.")

catalog_common_exceptions()
```

#### Step-by-Step Explanation:
1. Categorizes the most frequent runtime errors encountered by Python developers.
2. Demonstrates capturing the exception object using `as e`.

#### Expected Output:
```text
1. ValueError caught : invalid literal for int() with base 10: 'forty-two'
2. TypeError caught  : can only concatenate str (not "int") to str
3. IndexError caught : list index out of range
4. KeyError caught   : Key 'email' not found in dictionary.
```

### Example 3: Safe Attribute & Method Inspection
Shield against `AttributeError` when interacting with dynamic objects of unknown structure.

```python
def execute_plugin_hook(plugin_obj: any):
    print(f"Inspecting object of type: {type(plugin_obj).__name__}")
    
    try:
        # Attempt to call 'execute' hook
        plugin_obj.execute()
    except AttributeError:
        print(f"[SHIELDED] Plugin '{type(plugin_obj).__name__}' does not define an 'execute()' method!")

class AudioPlugin:
    def execute(self):
        print("Playing audio stream...")

class GenericData:
    pass

execute_plugin_hook(AudioPlugin())
execute_plugin_hook(GenericData())
```

#### Step-by-Step Explanation:
1. `GenericData()` does not define `execute()`.
2. Catching `AttributeError` shields the plugin manager from crashing.

#### Expected Output:
```text
Inspecting object of type: AudioPlugin
Playing audio stream...
Inspecting object of type: GenericData
[SHIELDED] Plugin 'GenericData' does not define an 'execute()' method!
```
