# 02. Relational & Comparison Operators

## 📖 Concept Overview
Relational operators compare two values or expressions and return a boolean result: **`True`** or **`False`**.

### 1. Comparison Operators
- **Equal To (`==`)**: `True` if values are equal (`5 == 5` -> `True`).
- **Not Equal To (`!=`)**: `True` if values are distinct (`5 != 3` -> `True`).
- **Greater Than (`>`)**: `True` if left > right (`10 > 5` -> `True`).
- **Less Than (`<`)**: `True` if left < right (`3 < 7` -> `True`).
- **Greater Than or Equal (`>=`)**: `True` if left $\ge$ right (`5 >= 5` -> `True`).
- **Less Than or Equal (`<=`)**: `True` if left $\le$ right (`4 <= 5` -> `True`).

---

### 2. Comparing Strings (Lexicographical Comparison)
Strings are compared character-by-character based on their underlying **Unicode values (`ord()`)**:
- `"Apple" < "Banana"` is `True` because `'A'` (65) < `'B'` (66).
- `"apple" > "Apple"` is `True` because `'a'` (97) > `'A'` (65).
- Capital letters are always considered smaller than lowercase letters in Python!

---

### 3. Chained Comparisons (Pythonic Multi-Comparison)
Python allows chained comparisons in a single mathematical notation:
```python
# Instead of: 18 <= age and age <= 65
if 18 <= age <= 65:
    print("Eligible working age")
```
Python evaluates this as `(18 <= age) and (age <= 65)`, evaluating `age` only once.

---

## 📋 Summary & Comparison Reference

| Operator | Meaning | Example | Result |
| :---: | :--- | :--- | :---: |
| `==` | Value equality | `[1, 2] == [1, 2]` | `True` |
| `!=` | Value inequality | `10 != 10` | `False` |
| `<` | Less than | `'A' < 'a'` | `True` |
| `>=` | Greater or equal | `15 >= 15` | `True` |
| `a < b < c` | Chained range | `10 < 15 < 20` | `True` |

## 🛠️ Practical Hands-On & Real-World Examples

### Example 1: Multi-Tier Tax Bracket Classifier with Chained Comparisons
Use chained comparisons to assign individual income brackets cleanly.

```python
def classify_tax_bracket(annual_income: float) -> str:
    # Pythonic chained comparisons:
    if annual_income < 0:
        return "INVALID_INCOME"
    elif annual_income <= 15_000:
        return "BRACKET_0 (0% Tax)"
    elif 15_000 < annual_income <= 50_000:
        return "BRACKET_1 (10% Tax)"
    elif 50_000 < annual_income <= 100_000:
        return "BRACKET_2 (20% Tax)"
    else:
        return "BRACKET_3 (30% Top Bracket)"

incomes = [12_000, 35_000, 75_000, 150_000]
for inc in incomes:
    print(f"Income ${inc:>7,}: {classify_tax_bracket(inc)}")
```

**Step-by-Step Explanation**:
1. Chained comparisons like `50_000 < annual_income <= 100_000` replicate mathematical intervals $(50000, 100000]$.
2. Avoids repetitive variable references.

**Expected Console Output**:
```text
Income $ 12,000: BRACKET_0 (0% Tax)
Income $ 35,000: BRACKET_1 (10% Tax)
Income $ 75,000: BRACKET_2 (20% Tax)
Income $150,000: BRACKET_3 (30% Top Bracket)
```

### Example 2: Lexicographical Version Number Comparator
Compare software release version strings using element-wise tuple comparisons.

```python
def is_upgrade_available(current_version: str, remote_version: str) -> bool:
    # Parse version strings '2.4.1' into integer tuples (2, 4, 1)
    curr_tuple = tuple(int(x) for x in current_version.split("."))
    rem_tuple = tuple(int(x) for x in remote_version.split("."))
    
    # Python compares tuples element-by-element
    return rem_tuple > curr_tuple

print("Upgrade available from 2.4.0 to 2.4.1? :", is_upgrade_available("2.4.0", "2.4.1"))
print("Upgrade available from 3.0.0 to 2.9.9? :", is_upgrade_available("3.0.0", "2.9.9"))
print("Upgrade available from 1.10.0 to 1.9.0? :", is_upgrade_available("1.10.0", "1.9.0"))
```

**Step-by-Step Explanation**:
1. Plain string comparison fails: `"1.10.0" < "1.9.0"` because `'1'` < `'9'`.
2. Converting to integer tuples `(1, 10, 0) > (1, 9, 0)` correctly evaluates multi-digit semantic versioning.

**Expected Console Output**:
```text
Upgrade available from 2.4.0 to 2.4.1? : True
Upgrade available from 3.0.0 to 2.9.9? : False
Upgrade available from 1.10.0 to 1.9.0? : False
```

### Example 3: Bounding Box Collision Detector in 2D Space
Determine whether two rectangular game entities overlap using chained coordinate comparisons.

```python
def check_bounding_box_collision(box_a: dict, box_b: dict) -> bool:
    # box format: {"x": left, "y": top, "w": width, "h": height}
    a_left = box_a["x"]
    a_right = box_a["x"] + box_a["w"]
    a_top = box_a["y"]
    a_bottom = box_a["y"] + box_a["h"]
    
    b_left = box_b["x"]
    b_right = box_b["x"] + box_b["w"]
    b_top = box_b["y"]
    b_bottom = box_b["y"] + box_b["h"]
    
    # Boxes do NOT collide if one is completely to the left, right, above, or below
    no_overlap = (a_right < b_left or a_left > b_right or a_bottom < b_top or a_top > b_bottom)
    return not no_overlap

player = {"x": 10, "y": 10, "w": 30, "h": 30}
obstacle_1 = {"x": 25, "y": 25, "w": 20, "h": 20}  # Overlaps
obstacle_2 = {"x": 80, "y": 80, "w": 20, "h": 20}  # Outside

print("Player collides with Obstacle 1?:", check_bounding_box_collision(player, obstacle_1))
print("Player collides with Obstacle 2?:", check_bounding_box_collision(player, obstacle_2))
```

**Step-by-Step Explanation**:
1. Uses relational operators to determine relative spatial coordinates.
2. Inverts the disjoint condition to verify bounding box collision.

**Expected Console Output**:
```text
Player collides with Obstacle 1?: True
Player collides with Obstacle 2?: False
```
