# 01. Arithmetic Operators & Precedence (BODMAS)

## 📖 Concept Overview
Arithmetic operators perform mathematical calculations on numeric operands (`int` and `float`).

### 1. Arithmetic Operators
- **Addition (`+`)**: Adds two operands (`10 + 5` -> `15`).
- **Subtraction (`-`)**: Subtracts right operand from left (`10 - 5` -> `5`).
- **Multiplication (`*`)**: Multiplies two operands (`10 * 5` -> `50`).
- **True Division (`/`)**: Divides left by right; **always returns a `float`** (`10 / 2` -> `5.0`).
- **Floor Division (`//`)**: Divides and truncates fractional part to the next lowest integer (`13 // 5` -> `2`, `-13 // 5` -> `-3`).
- **Modulus (`%`)**: Returns remainder of division (`13 % 5` -> `3`).
- **Exponentiation (`**`)**: Raises base to power (`2 ** 4` -> `16`). Supports fractional exponents for roots (`25 ** 0.5` -> `5.0`).

---

### 2. Operator Precedence & BODMAS / PEMDAS
Python evaluates expressions following strict precedence rules:
1. **Parentheses `()`**: Highest priority (evaluates innermost first).
2. **Exponentiation `**`**: Right-to-left associativity (`2 ** 3 ** 2` = `2 ** 9` = `512`).
3. **Unary Operators `+x`, `-x`**.
4. **Multiplication, Division, Floor Division, Modulus `*`, `/`, `//`, `%`** (Left-to-Right).
5. **Addition and Subtraction `+`, `-`** (Left-to-Right).

---

## 📋 Summary & Precedence Reference Table

| Level | Operator | Operation | Associativity |
| :---: | :--- | :--- | :---: |
| **1** | `()` | Parentheses grouping | Inside-out |
| **2** | `**` | Exponentiation (Power) | **Right-to-Left** |
| **3** | `+x`, `-x` | Unary positive / negative | Right-to-Left |
| **4** | `*`, `/`, `//`, `%` | Multiply, Divide, Floor, Remainder | Left-to-Right |
| **5** | `+`, `-` | Addition, Subtraction | Left-to-Right |

## 🛠️ Practical Hands-On & Real-World Examples

### Example 1: Calculating Compound Interest & Loan Amortization
Apply exponentiation and precedence rules to compute financial loan repayment schedules.

```python
def calculate_compound_growth(principal: float, annual_rate_pct: float, years: int, compounds_per_year: int = 12) -> float:
    # Formula: A = P * (1 + r/n)**(n*t)
    r = annual_rate_pct / 100.0
    n = compounds_per_year
    t = years
    
    # Precedence ensures (r / n) evaluates first, then + 1, then exponent (n * t)
    total_amount = principal * ((1 + r / n) ** (n * t))
    return round(total_amount, 2)

initial_investment = 10_000.00
rate = 7.5
term_years = 5

future_value = calculate_compound_growth(initial_investment, rate, term_years)
print(f"Principal: ${initial_investment:,.2f}")
print(f"Annual Interest Rate: {rate}%")
print(f"Future Value after {term_years} years: ${future_value:,.2f}")
```

**Step-by-Step Explanation**:
1. Demonstrates `**` exponentiation in economic formula modeling.
2. Parentheses enforce evaluation order before multiplication with `principal`.

**Expected Console Output**:
```text
Principal: $10,000.00
Annual Interest Rate: 7.5%
Future Value after 5 years: $14,532.94
```

### Example 2: Clock Arithmetic & Modular Page Chunking
Use modulus `%` and floor division `//` to compute 24-hour time shifts and page pagination offsets.

```python
def compute_time_and_pagination():
    # 1. Modular Clock Math
    current_hour = 21  # 9 PM in 24-hr format
    elapsed_hours = 38
    future_hour = (current_hour + elapsed_hours) % 24
    print(f"Current Time: {current_hour}:00 + {elapsed_hours} hrs -> Future Time: {future_hour}:00")
    
    # 2. Pagination Offset
    total_records = 153
    page_size = 20
    total_pages = (total_records + page_size - 1) // page_size  # Ceiling division trick
    print(f"Total Records: {total_records}, Page Size: {page_size} -> Total Pages: {total_pages}")

compute_time_and_pagination()
```

**Step-by-Step Explanation**:
1. `% 24` wraps overflow hours back into valid $0-23$ daily cycles.
2. `(total + size - 1) // size` computes integer ceiling division without importing `math.ceil`.

**Expected Console Output**:
```text
Current Time: 21:00 + 38 hrs -> Future Time: 11:00
Total Records: 153, Page Size: 20 -> Total Pages: 8
```

### Example 3: Right-to-Left Exponentiation Associativity Trap
Expose the common precedence mistake when chaining exponent operators (`2 ** 3 ** 2`).

```python
def demonstrate_exponent_associativity():
    # In math and Python, exponentiation is RIGHT-to-LEFT associative:
    # 2 ** 3 ** 2 is evaluated as 2 ** (3 ** 2) = 2 ** 9 = 512
    # NOT as (2 ** 3) ** 2 = 8 ** 2 = 64!
    
    result_default = 2 ** 3 ** 2
    result_left_grouped = (2 ** 3) ** 2
    result_right_grouped = 2 ** (3 ** 2)
    
    print(f"Default expression 2 ** 3 ** 2 : {result_default}")
    print(f"Explicit (2 ** 3) ** 2         : {result_left_grouped}")
    print(f"Explicit 2 ** (3 ** 2)         : {result_right_grouped}")
    print(f"Does default equal right group?: {result_default == result_right_grouped}")

demonstrate_exponent_associativity()
```

**Step-by-Step Explanation**:
1. Explains why Python evaluates chained powers from right to left.
2. Stresses using explicit parentheses in complex formulas to ensure clarity.

**Expected Console Output**:
```text
Default expression 2 ** 3 ** 2 : 512
Explicit (2 ** 3) ** 2         : 64
Explicit 2 ** (3 ** 2)         : 512
Does default equal right group?: True
```
