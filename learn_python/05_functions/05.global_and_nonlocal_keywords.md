## 📖 Concept Overview
By default, Python treats any variable assigned inside a function body as **local** to that function. If you need to rebind or modify a variable in an outer scope, Python provides two keywords:
1. **`global`**: Rebinds a variable in the **module-level Global scope**.
2. **`nonlocal`**: Rebinds a variable in the **nearest Enclosing function scope** (used in closures).

---

### 1. The `global` Keyword
Declares that an identifier belongs to the top-level module namespace, allowing in-place reassignment from within a function:
```python
counter = 0

def increment():
    global counter
    counter += 1  # Modifies the global counter variable!

increment()
print(counter)    # 1
```

---

### 2. The `nonlocal` Keyword
Introduced in Python 3 (PEP 3104), `nonlocal` allows an inner nested function to rebind identifiers in outer enclosing functions without affecting the global scope:
```python
def make_counter():
    count = 0
    def step():
        nonlocal count
        count += 1
        return count
    return step

counter_a = make_counter()
print(counter_a())  # 1
print(counter_a())  # 2
```

---

## 📋 Summary & Scope Modification Reference

| Keyword | Target Scope Modified | Common Use Case |
| :--- | :--- | :--- |
| `global x` | Top-level module namespace | Modifying module-level state / singletons (use sparingly). |
| `nonlocal x` | Nearest enclosing function | Stateful closures, factories, decorators, state machines. |

## 🛠️ Practical Hands-On & Real-World Examples

### Example 1: Global Application State Coordinator
Demonstrate modifying global telemetry metrics from distributed worker functions using the `global` declaration.

```python
TOTAL_REQUESTS_SERVED = 0
TOTAL_BYTES_TRANSFERRED = 0

def serve_client_request(payload_bytes: int):
    global TOTAL_REQUESTS_SERVED, TOTAL_BYTES_TRANSFERRED
    
    # Update global metrics directly
    TOTAL_REQUESTS_SERVED += 1
    TOTAL_BYTES_TRANSFERRED += payload_bytes
    print(f"Request served ({payload_bytes} bytes). Global Requests: {TOTAL_REQUESTS_SERVED}")

print("Initial Global Requests:", TOTAL_REQUESTS_SERVED)
serve_client_request(1024)
serve_client_request(2048)
print(f"Final Totals: {TOTAL_REQUESTS_SERVED} requests, {TOTAL_BYTES_TRANSFERRED} bytes transferred.")
```

#### Step-by-Step Explanation:
1. Without `global`, `TOTAL_REQUESTS_SERVED += 1` raises `UnboundLocalError`.
2. Declaring `global` instructs the compiler to bind assignments to the module namespace.

#### Expected Output:
```text
Initial Global Requests: 0
Request served (1024 bytes). Global Requests: 1
Request served (2048 bytes). Global Requests: 2
Final Totals: 2 requests, 3072 bytes transferred.
```

### Example 2: Stateful Closure Rate-Limiter using `nonlocal`
Create an API token bucket rate-limiter using a stateful closure that retains and updates tokens via `nonlocal`.

```python
import time

def create_rate_limiter(max_tokens: int, refill_rate_per_sec: float):
    tokens = max_tokens
    last_check = time.perf_counter()
    
    def try_consume(tokens_requested: int = 1) -> bool:
        nonlocal tokens, last_check
        
        now = time.perf_counter()
        elapsed = now - last_check
        last_check = now
        
        # Refill tokens based on elapsed time
        tokens = min(max_tokens, tokens + elapsed * refill_rate_per_sec)
        
        if tokens >= tokens_requested:
            tokens -= tokens_requested
            print(f"[PERMITTED] {tokens_requested} token(s) consumed. Remaining tokens: {tokens:.2f}")
            return True
        else:
            print(f"[RATE LIMITED] Request rejected! Tokens available: {tokens:.2f}")
            return False
            
    return try_consume

limiter = create_rate_limiter(max_tokens=3, refill_rate_per_sec=1.0)

print("Attempt 1:", limiter(1))
print("Attempt 2:", limiter(1))
print("Attempt 3:", limiter(1))
print("Attempt 4:", limiter(1))  # Should be rate limited!
```

#### Step-by-Step Explanation:
1. `tokens` and `last_check` are preserved inside the closure environment across function calls.
2. `nonlocal tokens, last_check` allows the inner `try_consume` function to update state between requests without polluting the global namespace.

#### Expected Output:
```text
[PERMITTED] 1 token(s) consumed. Remaining tokens: 2.00
Attempt 1: True
[PERMITTED] 1 token(s) consumed. Remaining tokens: 1.00
Attempt 2: True
[PERMITTED] 1 token(s) consumed. Remaining tokens: 0.00
Attempt 3: True
[RATE LIMITED] Request rejected! Tokens available: 0.00
Attempt 4: False
```

### Example 3: Multi-Level Enclosing Scope Chain Resolution
Demonstrate how `nonlocal` resolves to the nearest enclosing scope without skipping intermediate function levels.

```python
def level_1():
    msg = "L1"
    
    def level_2():
        msg = "L2"
        
        def level_3():
            nonlocal msg
            # Modifies msg in level_2, NOT level_1!
            msg = "L3_MODIFIED"
            
        print(f"Level 2 msg before level_3 call: {msg}")
        level_3()
        print(f"Level 2 msg after level_3 call : {msg}")
        
    level_2()
    print(f"Level 1 msg remains untouched  : {msg}")

level_1()
```

#### Step-by-Step Explanation:
1. `nonlocal msg` in `level_3` binds to the nearest enclosing variable in `level_2`.
2. The outer variable `msg` in `level_1` is completely shielded and unaffected.

#### Expected Output:
```text
Level 2 msg before level_3 call: L2
Level 2 msg after level_3 call : L3_MODIFIED
Level 1 msg remains untouched  : L1
```
