# 02. Positional, Keyword & Default Arguments

## 📖 Concept Overview
Python provides flexible mechanisms for passing data into functions:

---

### 1. Positional Arguments
Arguments mapped to parameters based on their order / position:
```python
def describe_pet(animal_type, pet_name):
    print(f"I have a {animal_type} named {pet_name}.")

describe_pet("dog", "Rover")  # animal_type="dog", pet_name="Rover"
```

---

### 2. Keyword Arguments
Arguments passed explicitly by parameter name (`name=value`). Order does not matter:
```python
describe_pet(pet_name="Whiskers", animal_type="cat")
```
> [!IMPORTANT]
> **Positional arguments must ALWAYS precede keyword arguments** in a function call!
> `describe_pet("dog", pet_name="Rover")` is valid.
> `describe_pet(animal_type="dog", "Rover")` raises `SyntaxError: positional argument follows keyword argument`.

---

### 3. Default Arguments
Parameters assigned a fallback default value in the function definition:
```python
def connect_database(host, port=5432, timeout=30):
    print(f"Connecting to {host}:{port} with timeout {timeout}s")

connect_database("db.internal")            # port=5432, timeout=30
connect_database("db.internal", port=5433) # port=5433, timeout=30
```

---

### 4. The Dangerous Mutable Default Argument Pitfall
In Python, **default parameter values are evaluated ONCE when the function is defined**, NOT every time the function is called!
If you use a mutable object (like a list or dictionary) as a default argument, all subsequent calls share the exact same object in memory!

```python
# BUGGY PATTERN:
def append_to(element, target_list=[]):
    target_list.append(element)
    return target_list

print(append_to(1))  # [1]
print(append_to(2))  # [1, 2] <-- Unexpected shared state!
```

#### The Idiomatic Python Solution:
Always use **`None`** as the default value for mutable arguments:
```python
# CLEAN & SAFE PATTERN:
def append_to(element, target_list=None):
    if target_list is None:
        target_list = []
    target_list.append(element)
    return target_list
```

---

## 📋 Summary & Arguments Reference

| Argument Type | Definition Syntax | Call Syntax | Behavior |
| :--- | :--- | :--- | :--- |
| **Positional** | `def f(a, b):` | `f(10, 20)` | Bound by sequential position. |
| **Keyword** | `def f(a, b):` | `f(b=20, a=10)` | Bound by explicit name; position-independent. |
| **Default** | `def f(a, b=100):` | `f(50)` | Uses default `100` if `b` is omitted. |
| **Mutable Default** | `def f(a=None):` | `f()` | Guard with `if a is None: a = []`. |

## 🛠️ Practical Hands-On & Real-World Examples

### Example 1: Demonstrating and Fixing the Mutable Default Trap
Directly expose the memory identity of default parameters across multiple calls.

```python
def buggy_cart_builder(item_name: str, cart: list = []):
    cart.append(item_name)
    print(f"Buggy Cart (ID: {id(cart)}): {cart}")
    return cart

def safe_cart_builder(item_name: str, cart: list = None):
    if cart is None:
        cart = []  # Allocates a fresh list on every invocation!
    cart.append(item_name)
    print(f"Safe Cart  (ID: {id(cart)}): {cart}")
    return cart

print("=== Testing Buggy Cart (Shared Mutable Default) ===")
buggy_cart_builder("Book")
buggy_cart_builder("Laptop")

print("\n=== Testing Safe Cart (None Sentinel Default) ===")
safe_cart_builder("Book")
safe_cart_builder("Laptop")
```

**Step-by-Step Explanation**:
1. `buggy_cart_builder` exhibits identical memory IDs across calls because `[]` was instantiated once when Python parsed the `def` statement.
2. `safe_cart_builder` creates a fresh list on each call where no cart was supplied.

**Expected Console Output**:
```text
=== Testing Buggy Cart (Shared Mutable Default) ===
Buggy Cart (ID: 140723456789120): ['Book']
Buggy Cart (ID: 140723456789120): ['Book', 'Laptop']

=== Testing Safe Cart (None Sentinel Default) ===
Safe Cart  (ID: 140723456789500): ['Book']
Safe Cart  (ID: 140723456789600): ['Laptop']
```

### Example 2: Configurable HTTP Request Client Factory
Build an API client function with multiple optional default headers, timeouts, and authorization modes.

```python
def make_api_request(
    endpoint: str,
    method: str = "GET",
    timeout_sec: int = 10,
    retry_count: int = 3,
    headers: dict | None = None
) -> dict:
    # Safe default header initialization
    active_headers = {"User-Agent": "PythonClient/2.0"}
    if headers:
        active_headers.update(headers)
        
    print(f"Sending [{method.upper()}] to '{endpoint}' | Timeout: {timeout_sec}s | Retries: {retry_count}")
    print(f"  Headers: {active_headers}")
    
    return {"status": 200, "endpoint": endpoint, "method": method}

# Call 1: All defaults
make_api_request("/api/v1/health")

# Call 2: Overriding method and headers via keyword arguments
make_api_request(
    "/api/v1/orders",
    method="POST",
    headers={"Authorization": "Bearer TOKEN_XYZ123"}
)
```

**Step-by-Step Explanation**:
1. Required parameter `endpoint` must be passed first.
2. Sensible defaults (`method="GET"`, `timeout_sec=10`) keep standard calls concise.
3. Keyword argument overrides provide custom flexibility.

**Expected Console Output**:
```text
Sending [GET] to '/api/v1/health' | Timeout: 10s | Retries: 3
  Headers: {'User-Agent': 'PythonClient/2.0'}
Sending [POST] to '/api/v1/orders' | Timeout: 10s | Retries: 3
  Headers: {'User-Agent': 'PythonClient/2.0', 'Authorization': 'Bearer TOKEN_XYZ123'}
```

### Example 3: Positional-Only and Keyword-Only Parameters (PEP 570 / PEP 3102)
Enforce clean API design using `/` (positional-only) and `*` (keyword-only) syntax markers.

```python
# Parameters before '/' MUST be passed positionally.
# Parameters after '*' MUST be passed with keyword names!
def configure_cache(cache_name: str, capacity: int, /, *, evict_policy: str = "LRU", ttl_seconds: int = 3600):
    print(f"Cache '{cache_name}' (Capacity: {capacity}) initialized.")
    print(f"  Policy: {evict_policy} | TTL: {ttl_seconds}s")

# Valid call:
configure_cache("SessionStore", 1000, evict_policy="FIFO", ttl_seconds=600)

# Demonstrating syntax enforcement:
# configure_cache(cache_name="SessionStore", 1000) -> Raises TypeError (positional-only!)
# configure_cache("SessionStore", 1000, "FIFO")    -> Raises TypeError (keyword-only!)
```

**Step-by-Step Explanation**:
1. `/` enforces that `cache_name` and `capacity` cannot be called via keyword names, preventing caller coupling to internal parameter names.
2. `*` forces subsequent parameters (`evict_policy`, `ttl_seconds`) to be explicitly named by the caller.

**Expected Console Output**:
```text
Cache 'SessionStore' (Capacity: 1000) initialized.
  Policy: FIFO | TTL: 600s
```
