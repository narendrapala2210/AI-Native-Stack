# 06. Function Call Stack & Execution Frames

## 📖 Concept Overview
When a Python program calls a function, CPython allocates a **Call Stack Frame (Execution Frame)**. The call stack operates on a **Last-In, First-Out (LIFO)** data structure.

### 1. Frame Lifecycle
1. **Invocation (Push)**: When function `A()` calls `B()`, a new execution frame for `B()` is pushed onto the call stack. The frame holds local variables, parameter bindings, and bytecode instruction pointers.
2. **Execution**: Execution of `A()` is paused while `B()` executes.
3. **Return (Pop)**: When `B()` finishes and returns, its frame is popped off the stack and deallocated. Execution resumes in `A()` immediately following the call site.

---

### 2. Inspecting the Call Stack (`inspect` module)
Python allows live inspection of current call stack frames via the `inspect` standard library module:
```python
import inspect

def inner():
    current_frame = inspect.currentframe()
    print("Current Function Name:", current_frame.f_code.co_name)
    print("Calling Function Name:", current_frame.f_back.f_code.co_name)

def outer():
    inner()

outer()
```

## 🛠️ Practical Hands-On & Real-World Examples

### Example 1: Live Call Stack Frame Introspector
Traverse the call stack backwards to display the active call chain and caller filenames/line numbers.

```python
import inspect

def inspect_stack_hierarchy():
    stack = inspect.stack()
    print("=== Active Call Stack Trace (Top to Bottom) ===")
    for idx, frame_info in enumerate(stack):
        print(f"Frame #{idx}: Function '{frame_info.function}' at Line {frame_info.lineno}")

def service_c():
    inspect_stack_hierarchy()

def service_b():
    service_c()

def service_a():
    service_b()

service_a()
```

**Step-by-Step Explanation**:
1. `inspect.stack()` captures a snapshot of all active frames currently on the runtime call stack.
2. Shows how `service_a` -> `service_b` -> `service_c` form a nested LIFO stack.

**Expected Console Output**:
```text
=== Active Call Stack Trace (Top to Bottom) ===
Frame #0: Function 'inspect_stack_hierarchy' at Line 5
Frame #1: Function 'service_c' at Line 10
Frame #2: Function 'service_b' at Line 13
Frame #3: Function 'service_a' at Line 16
Frame #4: Function '<module>' at Line 18
```

### Example 2: Profiling Stack Depth and Recursion Limits
Inspect Python's default stack limit (`sys.getrecursionlimit()`) and demonstrate how the stack overflows on runaway execution.

```python
import sys

def measure_stack_boundary(depth: int = 1):
    if depth > 5:
        print(f"Reached Target Depth: {depth}. Unwinding stack...")
        return
    print(f"Pushing Frame #{depth} onto Call Stack...")
    measure_stack_boundary(depth + 1)
    print(f"Popped Frame #{depth} from Call Stack.")

print(f"CPython Default Max Stack Depth Limit: {sys.getrecursionlimit()}")
measure_stack_boundary()
```

**Step-by-Step Explanation**:
1. Visualizes push and pop order as recursion dives in and returns.
2. Highlights that Python allocates memory per frame, enforcing `sys.getrecursionlimit()` (default 1000) to prevent OS stack overflow crashes.

**Expected Console Output**:
```text
CPython Default Max Stack Depth Limit: 1000
Pushing Frame #1 onto Call Stack...
Pushing Frame #2 onto Call Stack...
Pushing Frame #3 onto Call Stack...
Pushing Frame #4 onto Call Stack...
Pushing Frame #5 onto Call Stack...
Reached Target Depth: 6. Unwinding stack...
Popped Frame #5 from Call Stack.
Popped Frame #4 from Call Stack.
Popped Frame #3 from Call Stack.
Popped Frame #2 from Call Stack.
Popped Frame #1 from Call Stack.
```

### Example 3: Contextual Caller Logging (Diagnostic Utility)
Build an audit logger that automatically discovers the name of whichever function called it.

```python
import inspect

def audit_log(message: str):
    # inspect.currentframe().f_back gets the caller's frame!
    caller_frame = inspect.currentframe().f_back
    caller_name = caller_frame.f_code.co_name
    line_no = caller_frame.f_lineno
    print(f"[AUDIT] [{caller_name}:{line_no}] {message}")

def order_checkout_service():
    audit_log("Validating customer cart items...")
    audit_log("Charging credit card token...")

def inventory_sync_service():
    audit_log("Decrementing warehouse stock...")

order_checkout_service()
inventory_sync_service()
```

**Step-by-Step Explanation**:
1. `f_back` accesses the previous frame on the stack.
2. `f_code.co_name` extracts the caller function's name dynamically without needing hardcoded strings.

**Expected Console Output**:
```text
[AUDIT] [order_checkout_service:10] Validating customer cart items...
[AUDIT] [order_checkout_service:11] Charging credit card token...
[AUDIT] [inventory_sync_service:14] Decrementing warehouse stock...
```
