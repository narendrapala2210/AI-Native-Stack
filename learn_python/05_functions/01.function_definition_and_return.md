# 01. Function Definition & Return Values

## 📖 Concept Overview
A **Function** is a named, reusable block of code designed to perform a specific task. Functions embody the DRY (**Don't Repeat Yourself**) software engineering principle.

### 1. Defining and Calling Functions
- Defined using the **`def`** keyword, followed by the function name, parentheses `()`, and a colon `:`.
- Optional parameters are placed inside parentheses.
- A function is executed (called/invoked) using its identifier followed by parentheses.

```python
def greet_user(username):
    print(f"Hello, {username}!")

greet_user("Teja")  # Function call
```

---

### 2. Returning Values (`return`)
The **`return`** statement terminates function execution immediately and sends a result value back to the caller:
```python
def calculate_area(width, height):
    return width * height

result = calculate_area(10, 5)
print(result)  # 50
```
- **Code After Return Is Dead Code**: Any statements placed after a `return` statement in the same execution block will never be executed.
- **Implicit Return**: If a function terminates without encountering an explicit `return` statement, Python automatically returns **`None`**.

---

### 3. Returning Multiple Values (Tuple Packing)
A Python function can return multiple values separated by commas. Python automatically packs them into a **single tuple**, which the caller can unpack in one line:
```python
def get_min_max(numbers):
    return min(numbers), max(numbers)  # Implicit tuple packing

lowest, highest = get_min_max([4, 1, 8, 9, 2])  # Unpacking
```

## 🛠️ Practical Hands-On & Real-World Examples

### Example 1: Multi-Metric Statistical Summary Generator
Compute average, median, and spread from a numeric series, returning them as an unpacked multi-value tuple.

```python
def compute_dataset_statistics(numbers: list[float]) -> tuple[float, float, float]:
    if not numbers:
        return 0.0, 0.0, 0.0
        
    sorted_nums = sorted(numbers)
    count = len(sorted_nums)
    
    # 1. Mean
    mean_val = sum(sorted_nums) / count
    
    # 2. Median
    mid = count // 2
    if count % 2 == 1:
        median_val = sorted_nums[mid]
    else:
        median_val = (sorted_nums[mid - 1] + sorted_nums[mid]) / 2.0
        
    # 3. Range Spread
    range_spread = sorted_nums[-1] - sorted_nums[0]
    
    # Return multiple values (packed as tuple)
    return round(mean_val, 2), round(median_val, 2), round(range_spread, 2)

readings = [12.5, 18.0, 15.2, 22.4, 14.1, 16.8, 19.5]
mean, median, spread = compute_dataset_statistics(readings)

print(f"Readings Count: {len(readings)}")
print(f"Mean (Average): {mean}")
print(f"Median Value  : {median}")
print(f"Range Spread  : {spread}")
```

**Step-by-Step Explanation**:
1. Returns three values: `mean_val, median_val, range_spread`.
2. Caller unpacks the resulting tuple directly into `mean, median, spread`.

**Expected Console Output**:
```text
Readings Count: 7
Mean (Average): 16.93
Median Value  : 16.8
Range Spread  : 9.9
```

### Example 2: Dead Code & Early Return Pattern in Validation
Demonstrate how early `return` statements exit execution immediately, bypassing dead code.

```python
def validate_and_process_payment(account_balance: float, payment_amount: float) -> str:
    print(f"Initiating payment of ${payment_amount:.2f}...")
    
    if payment_amount <= 0:
        return "[FAILED] Invalid transaction: amount must be strictly greater than $0."
        print("This line is dead code and will NEVER run!")
        
    if payment_amount > account_balance:
        return f"[FAILED] Insufficient funds: available balance is only ${account_balance:.2f}."
        
    # Successful execution path
    new_balance = account_balance - payment_amount
    return f"[SUCCESS] Transaction approved. Remaining balance: ${new_balance:.2f}."

print(validate_and_process_payment(500.0, -20.0))
print(validate_and_process_payment(500.0, 750.0))
print(validate_and_process_payment(500.0, 150.0))
```

**Step-by-Step Explanation**:
1. Early returns exit immediately upon detecting invalid parameters.
2. Demonstrates that statements following `return` inside the same conditional scope are ignored.

**Expected Console Output**:
```text
Initiating payment of $-20.00...
[FAILED] Invalid transaction: amount must be strictly greater than $0.
Initiating payment of $750.00...
[FAILED] Insufficient funds: available balance is only $500.00.
Initiating payment of $150.00...
[SUCCESS] Transaction approved. Remaining balance: $350.00.
```

### Example 3: Pure vs Impure Functions Demonstration
Demonstrate the difference between a **pure function** (no side effects, returns a fresh object) and an **impure function** (mutates input arguments in-place).

```python
# Pure Function: Does not modify original list; returns transformed new copy
def append_timestamp_pure(event_log: list[str], event: str) -> list[str]:
    # Creates and returns a new list
    return event_log + [f"[2026-09-14] {event}"]

# Impure Function: Mutates the caller's list directly in-place
def append_timestamp_impure(event_log: list[str], event: str) -> None:
    event_log.append(f"[2026-09-14] {event}")

original_audit_trail = ["INIT_DATABASE", "CONNECT_POOL"]

print("=== 1. Calling Pure Function ===")
new_trail = append_timestamp_pure(original_audit_trail, "USER_LOGIN")
print("Original Trail Untouched:", original_audit_trail)
print("New Pure Output Returned:", new_trail)

print("\n=== 2. Calling Impure Function ===")
append_timestamp_impure(original_audit_trail, "ADMIN_ACCESS")
print("Original Trail Mutated In-Place:", original_audit_trail)
```

**Step-by-Step Explanation**:
1. Pure functions avoid modifying caller state, reducing concurrency bugs.
2. Impure functions modify the heap object directly, which can lead to unexpected side effects across large codebases.

**Expected Console Output**:
```text
=== 1. Calling Pure Function ===
Original Trail Untouched: ['INIT_DATABASE', 'CONNECT_POOL']
New Pure Output Returned: ['INIT_DATABASE', 'CONNECT_POOL', '[2026-09-14] USER_LOGIN']

=== 2. Calling Impure Function ===
Original Trail Mutated In-Place: ['INIT_DATABASE', 'CONNECT_POOL', '[2026-09-14] ADMIN_ACCESS']
```
