## 1. Conceptual Deep-Dive: Python Packages

A **package** is a directory containing Python modules and an optional `__init__.py` file:
1. **The Role of `__init__.py`**:
   - Marks a directory as a regular Python package.
   - Executes automatically when the package is imported (`import mypackage`).
   - Used for package-level initialization, importing public sub-modules, and defining API facades.
2. **Controlling Exports with `__all__`**:
   - A list of string identifiers defining what symbols are exported when a consumer executes `from package import *`.
   - Prevents accidental exposure of internal helper functions and imported modules.
3. **Relative Imports**:
   - Intra-package imports using dot notation:
     - `from . import sibling_module`: Current package directory.
     - `from .sibling_module import helper`: Sibling module in current directory.
     - `from ..parent_package import config`: Parent directory.
   - **Crucial Rule**: Relative imports work ONLY when modules are executed as part of a package (`python -m pkg.module`), NEVER when run directly as standalone scripts!

## 🛠️ Practical Hands-On & Real-World Examples

### Example 1: Defining Package Public API Surface with `__all__`
Construct a clean public facade exporting only authorized symbols.

```python
# Simulating the contents of a package's __init__.py

__all__ = ["ClientSession", "create_session"]

# Public exposed classes & functions
class ClientSession:
    def __init__(self, token: str): self.token = token

def create_session(token: str) -> ClientSession:
    return ClientSession(token)

# Private internal helper (NOT included in __all__!)
def _internal_crypto_hash(val: str) -> str:
    return f"HASHED_{val}"

def test_package_exports():
    print("Exported Public Symbols (__all__):", __all__)
    print("Is ClientSession public?        ", "ClientSession" in __all__)
    print("Is _internal_crypto_hash public?", "_internal_crypto_hash" in __all__)

test_package_exports()
```

#### Step-by-Step Explanation:
1. Consumers executing `from mypackage import *` will receive `ClientSession` and `create_session`.
2. `_internal_crypto_hash` remains hidden from star-imports.

#### Expected Output:
```text
Exported Public Symbols (__all__): ['ClientSession', 'create_session']
Is ClientSession public?         True
Is _internal_crypto_hash public? False
```

### Example 2: Simulating Package Namespace Resolution
Demonstrate nested package namespace navigation programmatically.

```python
class MockSubModule:
    def __init__(self, name: str):
        self.name = name
    def execute(self):
        return f"Executed from {self.name}"

class MockPackage:
    def __init__(self, package_name: str):
        self.package_name = package_name
        # Sub-modules exposed on the package namespace
        self.auth = MockSubModule(f"{package_name}.auth")
        self.billing = MockSubModule(f"{package_name}.billing")

def test_package_hierarchy():
    cloud_sdk = MockPackage("cloud_sdk")

    print(cloud_sdk.auth.execute())
    print(cloud_sdk.billing.execute())

test_package_hierarchy()
```

#### Step-by-Step Explanation:
1. High-level packages organize sub-modules hierarchically, providing unified top-level access points (`cloud_sdk.auth`).

#### Expected Output:
```text
Executed from cloud_sdk.auth
Executed from cloud_sdk.billing
```

### Example 3: Namespace Packages (PEP 420)
Explain and verify PEP 420 implicit namespace packages (packages without `__init__.py`).

```python
from pathlib import Path

def explain_namespace_packages():
    print("PEP 420 Namespace Packages Overview:")
    print("1. Allow splitting a single logical package (e.g. 'company.tools') across multiple distinct directories or pip packages.")
    print("2. Do NOT contain an __init__.py file in the parent directory.")
    print("3. Python traverses all sys.path directories to find matching sub-packages.")

explain_namespace_packages()
```

#### Step-by-Step Explanation:
1. Introduced in Python 3.3, namespace packages enable monorepos and multi-repository distribution for large organizations.

#### Expected Output:
```text
PEP 420 Namespace Packages Overview:
1. Allow splitting a single logical package (e.g. 'company.tools') across multiple distinct directories or pip packages.
2. Do NOT contain an __init__.py file in the parent directory.
3. Python traverses all sys.path directories to find matching sub-packages.
```
