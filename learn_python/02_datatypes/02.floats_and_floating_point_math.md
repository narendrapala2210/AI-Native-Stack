# 02. Floats & Floating-Point Math

## 📖 Concept Overview
In Python, **floating-point numbers (`float`)** represent real numbers with decimal points. CPython implements floats using the **IEEE 754 double-precision standard** (64 bits of memory: 1 sign bit, 11 exponent bits, and 52 mantissa bits).

### 1. The Classic Floating-Point Representation Trap
Computers internally use binary (base 2). Many decimal fractions (base 10) cannot be represented cleanly in binary:
```python
print(0.1 + 0.2)
# Output: 0.30000000000000004
```
Because $0.1$ and $0.2$ are repeating fractions in binary, slight precision approximations occur.
> [!WARNING]
> **Never compare two floating-point numbers using strict equality (`==`)!**
> ```python
> (0.1 + 0.2) == 0.3  # False!
> ```
> Instead, use `math.isclose()` to check equality within a tolerable delta:
> ```python
> import math
> math.isclose(0.1 + 0.2, 0.3)  # True!
> ```

### 2. Special Floating-Point Values: `inf` and `nan`
Python floats support special IEEE values:
- **Infinity (`inf` / `-inf`)**: Represents unbounded magnitudes (e.g. `float("inf")` or `float("-inf")`).
- **Not a Number (`nan`)**: Represents undefined mathematical operations (e.g. `float("nan")`).
> Note: `nan == nan` is **always `False`**. Use `math.isnan(x)` to verify NaN.

### 3. Exact Decimal Math: `decimal.Decimal`
For monetary transactions where fractional cents must be strictly preserved without floating-point artifacts, Python includes the `decimal` standard library module:
```python
from decimal import Decimal
total = Decimal("0.1") + Decimal("0.2")
print(total)  # Decimal('0.3')
```

## 🛠️ Practical Hands-On & Real-World Examples

### Example 1: Financial Ledger with `decimal.Decimal` vs `float`
Demonstrate how compounding floating-point rounding errors cause financial drift, and resolve it using `Decimal`.

```python
from decimal import Decimal

def simulate_bank_ledger():
    # Simulate adding 10 cents (0.10) 100,000 times
    transactions_count = 100_000
    
    # 1. Using standard float
    float_balance = 0.0
    for _ in range(transactions_count):
        float_balance += 0.10
        
    # 2. Using Decimal
    decimal_balance = Decimal("0.00")
    ten_cents = Decimal("0.10")
    for _ in range(transactions_count):
        decimal_balance += ten_cents
        
    expected_total = 10000.00
    print("=== Financial Balance Comparison ===")
    print(f"Expected Balance: ${expected_total:,.2f}")
    print(f"Float Balance   : ${float_balance:,.8f} (Error: {float_balance - expected_total:+.8f})")
    print(f"Decimal Balance : ${decimal_balance} (Error: {decimal_balance - Decimal('10000.00')})")

simulate_bank_ledger()
```

**Step-by-Step Explanation**:
1. Because `0.10` has a tiny residual error in 64-bit IEEE float, compounding it 100,000 times creates visible financial drift.
2. `Decimal("0.10")` initialized from a string maintains precise base-10 arithmetic, yielding an exact balance.

**Expected Console Output**:
```text
=== Financial Balance Comparison ===
Expected Balance: $10,000.00
Float Balance   : $10,000.00000000188356 (Error: +0.00000000188356)
Decimal Balance : $10000.00 (Error: 0.00)
```

### Example 2: Safe Floating-Point Geolocation Distance Comparator
Compute whether a GPS coordinate is within a target boundary using `math.isclose()` to avoid floating-point equality pitfalls.

```python
import math

def is_at_waypoint(current_lat: float, current_lon: float, target_lat: float, target_lon: float, tolerance_degrees: float = 1e-4) -> bool:
    # Use math.isclose to evaluate proximity within absolute tolerance
    lat_match = math.isclose(current_lat, target_lat, abs_tol=tolerance_degrees)
    lon_match = math.isclose(current_lon, target_lon, abs_tol=tolerance_degrees)
    return lat_match and lon_match

waypoint_lat = 37.774929
waypoint_lon = -122.419416

# Drone telemetry reading with minor sensor jitter
drone_lat = 37.774935
drone_lon = -122.419410

print("=== Drone GPS Waypoint Check ===")
print("Direct equality check (==)     :", (drone_lat == waypoint_lat and drone_lon == waypoint_lon))
print("Proximity check (math.isclose):", is_at_waypoint(drone_lat, drone_lon, waypoint_lat, waypoint_lon))
```

**Step-by-Step Explanation**:
1. Direct equality `==` fails even if the coordinates differ by a fraction of a millimeter.
2. `math.isclose(..., abs_tol=1e-4)` provides a realistic, configurable radius for sensor tolerances.

**Expected Console Output**:
```text
=== Drone GPS Waypoint Check ===
Direct equality check (==)     : False
Proximity check (math.isclose): True
```

### Example 3: Handling Corrupt Sensor Data (`NaN` and `Infinity`)
Build a data cleaning pipeline that filters out corrupted IEEE floating-point values (`nan`, `inf`, `-inf`) before computing statistical averages.

```python
import math

def clean_sensor_telemetry(raw_measurements: list[float]) -> dict:
    valid_readings = []
    corrupted_count = 0
    
    for reading in raw_measurements:
        # Check if value is NaN or Infinite
        if math.isnan(reading) or math.isinf(reading):
            corrupted_count += 1
        else:
            valid_readings.append(reading)
            
    avg_value = sum(valid_readings) / len(valid_readings) if valid_readings else 0.0
    
    return {
        "total_received": len(raw_measurements),
        "valid_count": len(valid_readings),
        "corrupt_dropped": corrupted_count,
        "clean_average": round(avg_value, 2)
    }

telemetry_stream = [
    24.5, 
    25.1, 
    float("nan"),    # Corrupt sensor transmission
    24.8, 
    float("inf"),    # Electrical surge overflow
    23.9, 
    float("-inf")    # Voltage drop underflow
]

report = clean_sensor_telemetry(telemetry_stream)
print("Telemetry Cleaning Report:")
for k, v in report.items():
    print(f"  {k:<16}: {v}")
```

**Step-by-Step Explanation**:
1. `float("nan")` and `float("inf")` represent corrupt sensor inputs.
2. If passed to `sum()`, any `NaN` or `inf` contaminates the entire calculation.
3. `math.isnan()` and `math.isinf()` detect and discard unviable telemetry.

**Expected Console Output**:
```text
Telemetry Cleaning Report:
  total_received  : 7
  valid_count     : 4
  corrupt_dropped : 3
  clean_average   : 24.58
```
