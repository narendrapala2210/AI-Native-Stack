# 09. Tuples: Immutability, Unpacking & Namedtuples

## 📖 Concept Overview
A **Tuple (`tuple`)** is an ordered, **immutable** sequence of objects. Once created, a tuple's elements cannot be added, modified, replaced, or deleted.

### 1. Defining Tuples & The Trailing Comma Requirement
Tuples are enclosed in parentheses `()`:
```python
coords = (12.5, 77.2)
empty_tup = ()
```
> [!WARNING]
> To define a tuple containing a **single element**, a trailing comma is **mandatory**:
> ```python
> not_a_tuple = ("apple")   # type: str (just grouped string)
> valid_tuple = ("apple",)  # type: tuple!
> ```

---

### 2. Why Use Tuples Instead of Lists?
1. **Data Integrity (Immutability)**: Ensures constant values (e.g. database connection coordinates, months) cannot be accidentally altered.
2. **Performance & Memory Efficiency**: Tuples allocate a single fixed memory block. They take fewer bytes than lists and do not over-allocate headroom for dynamic resizing.
3. **Dictionary Keys & Sets**: Because tuples are immutable (provided they contain hashable items), **tuples can be used as dictionary keys and set elements**. Lists cannot!

---

### 3. Tuple Packing and Unpacking
- **Packing**: Combining values into a tuple without parentheses:
  ```python
  point = 10, 20, 30  # Packed tuple (10, 20, 30)
  ```
- **Unpacking**: Extracting tuple elements into individual variables:
  ```python
  x, y, z = point
  print(x, y, z)  # 10 20 30
  ```
- **Extended Unpacking with `*` (Starred Expression)**:
  ```python
  first, *middle, last = (1, 2, 3, 4, 5)
  print(first)   # 1
  print(middle)  # [2, 3, 4]
  print(last)    # 5
  ```

---

### 4. `collections.namedtuple`
Provides human-readable field access in addition to index positions:
```python
from collections import namedtuple
Point = namedtuple("Point", ["x", "y"])
p = Point(10, 20)
print(p.x, p.y)  # 10 20
```

---

## 📋 Summary & Reference Table

| Feature | Tuple (`tuple`) | List (`list`) |
| :--- | :--- | :--- |
| **Mutability** | **Immutable** (read-only) | **Mutable** (dynamic modifications) |
| **Syntax** | `(1, 2, 3)` or `1, 2, 3` | `[1, 2, 3]` |
| **Single Item Syntax** | `(42,)` (comma required) | `[42]` |
| **Memory Footprint** | Lower memory overhead | Higher memory overhead (dynamic headroom) |
| **Usable as Dict Key?**| **Yes** (if elements are hashable) | **No** (raises `TypeError: unhashable type`) |
| **Methods** | `count()`, `index()` | `append()`, `extend()`, `insert()`, `pop()`, etc. |

## 🛠️ Practical Hands-On & Real-World Examples

### Example 1: High-Performance Composite Dictionary Keys
Use immutable coordinate tuples as dictionary keys to implement a high-speed geospatial spatial index.

```python
def build_geo_spatial_cache():
    # Tuples are hashable -> Can serve as dictionary keys!
    # (Latitude, Longitude) rounded to 2 decimals (~1.1 km grid)
    geo_weather_cache: dict[tuple[float, float], dict] = {}
    
    # Ingest station readings
    geo_weather_cache[(37.77, -122.42)] = {"city": "San Francisco", "temp_c": 18.5}
    geo_weather_cache[(40.71, -74.01)]  = {"city": "New York", "temp_c": 22.0}
    geo_weather_cache[(51.51, -0.13)]   = {"city": "London", "temp_c": 16.2}
    
    # Query location
    lookup_coord = (37.77, -122.42)
    reading = geo_weather_cache.get(lookup_coord)
    
    print(f"Queried Key: {lookup_coord}")
    print(f"Found City : {reading['city']} with Temperature: {reading['temp_c']}°C")

build_geo_spatial_cache()
```

**Step-by-Step Explanation**:
1. Trying to use a list `[37.77, -122.42]` as a key raises `TypeError: unhashable type: 'list'`.
2. Using a tuple `(37.77, -122.42)` allows instant $O(1)$ hash map lookups.

**Expected Console Output**:
```text
Queried Key: (37.77, -122.42)
Found City : San Francisco with Temperature: 18.5°C
```

### Example 2: Extended Unpacking for Event Log Analytics
Process multi-variable event telemetry logs using starred tuple unpacking to separate headers, dynamic payload bodies, and trailing checksums.

```python
def parse_network_packet_stream(packet_records: list[tuple]):
    for record in packet_records:
        # Extended unpacking:
        # First element -> Timestamp
        # Middle elements -> Arbitrary payload sensor bytes
        # Last element -> Integrity Checksum
        timestamp, device_id, *sensor_data, checksum = record
        
        avg_reading = sum(sensor_data) / len(sensor_data) if sensor_data else 0.0
        print(f"Device: {device_id} at {timestamp}")
        print(f"  Payload Read Count : {len(sensor_data)}")
        print(f"  Average Sensor Val : {avg_reading:.2f}")
        print(f"  Checksum Verified  : {checksum}")

packets = [
    ("2026-09-14 12:00:01", "DEV-01", 24.1, 24.5, 24.3, 24.8, "CHECKSUM_VALID"),
    ("2026-09-14 12:00:02", "DEV-02", 10.2, 10.8, "CHECKSUM_VALID")
]

parse_network_packet_stream(packets)
```

**Step-by-Step Explanation**:
1. `*sensor_data` dynamically gathers variable numbers of readings into a list.
2. `checksum` automatically binds to the trailing element regardless of how many payload readings were passed.

**Expected Console Output**:
```text
Device: DEV-01 at 2026-09-14 12:00:01
  Payload Read Count : 4
  Average Sensor Val : 24.43
  Checksum Verified  : CHECKSUM_VALID
Device: DEV-02 at 2026-09-14 12:00:02
  Payload Read Count : 2
  Average Sensor Val : 10.50
  Checksum Verified  : CHECKSUM_VALID
```

### Example 3: Memory Footprint Benchmark (Tuples vs Lists)
Compare memory allocation overhead between tuples and lists when storing 10,000 spatial vector points.

```python
import sys

def compare_tuple_and_list_memory():
    sample_list = [10, 20, 30]
    sample_tuple = (10, 20, 30)
    
    print("=== Single Object Overhead ===")
    print(f"Memory for [10, 20, 30] (list) : {sys.getsizeof(sample_list)} bytes")
    print(f"Memory for (10, 20, 30) (tuple): {sys.getsizeof(sample_tuple)} bytes")
    
    # Allocate 10,000 coordinates
    count = 10_000
    list_of_lists = [[x, x + 1, x + 2] for x in range(count)]
    list_of_tuples = [(x, x + 1, x + 2) for x in range(count)]
    
    total_list_bytes = sum(sys.getsizeof(item) for item in list_of_lists)
    total_tuple_bytes = sum(sys.getsizeof(item) for item in list_of_tuples)
    
    print("
=== 10,000 Coordinates Memory Footprint ===")
    print(f"Total size (lists) : {total_list_bytes:,} bytes")
    print(f"Total size (tuples): {total_tuple_bytes:,} bytes")
    savings = (total_list_bytes - total_tuple_bytes) / total_list_bytes * 100
    print(f"Memory Savings with Tuples: {savings:.1f}%")

compare_tuple_and_list_memory()
```

**Step-by-Step Explanation**:
1. `sys.getsizeof()` verifies tuples require significantly fewer bytes than lists.
2. Demonstrates why data science and backend systems choose tuples for immutable records.

**Expected Console Output**:
```text
=== Single Object Overhead ===
Memory for [10, 20, 30] (list) : 88 bytes
Memory for (10, 20, 30) (tuple): 64 bytes

=== 10,000 Coordinates Memory Footprint ===
Total size (lists) : 880,000 bytes
Total size (tuples): 640,000 bytes
Memory Savings with Tuples: 27.3%
```
