# 11. Dictionaries: Keys, Values & Views

## 📖 Concept Overview
In Python, a **Dictionary (`dict`)** is an unordered (insertion-ordered in Python 3.7+), mutable collection of **key-value pairs**. Each key maps directly to an associated value.

### 1. Dictionary Creation & Syntax
Dictionaries are defined with curly braces `{}` containing `key: value` pairs, or via the `dict()` constructor:
```python
user = {
    "id": 101,
    "name": "Teja",
    "role": "Lead Architect",
    "is_active": True
}
```

---

### 2. The Strict Rule of Dictionary Keys
1. **Keys Must Be Unique**: A dictionary cannot contain duplicate keys. Assigning to an existing key overwrites its previous value.
2. **Keys Must Be Immutable & Hashable**:
   A key must implement `__hash__()` and remain unchanged throughout its lifecycle.
   - **Valid Keys**: Strings, integers, floats, booleans, and tuples (containing only immutable elements).
   - **Invalid Keys**: Lists, dictionaries, or sets. Attempting to use a list as a key raises `TypeError: unhashable type: 'list'`.
3. **Values Can Be Anything**: Values can be of any data type—mutable or immutable, duplicate or unique.

---

### 3. Accessing & Modifying Dictionary Entries
- **Bracket Notation (`dict[key]`)**: Retrieves value. Raises **`KeyError`** if key does not exist!
- **`dict.get(key, default=None)`**: Safely retrieves value without crashing. Returns `default` if key is missing.
- **Adding / Updating**:
  ```python
  user["email"] = "teja@cloud.dev"  # Adds new key
  user["role"] = "Director"         # Updates existing key
  ```
- **Deleting**: `del user["role"]` or `popped = user.pop("role")`.

---

### 4. Dynamic Dictionary Views
Python provides three dynamic view objects:
- **`dict.keys()`**: Returns a view of all keys.
- **`dict.values()`**: Returns a view of all values.
- **`dict.items()`**: Returns a view of `(key, value)` tuple pairs.
> [!NOTE]
> Dictionary views are dynamic: if the underlying dictionary changes, the view immediately reflects the changes!

```python
# Iterating through dictionary key-value pairs
for key, value in user.items():
    print(f"{key} -> {value}")
```

---

## 📋 Summary & Reference Table

| Operation | Syntax | Description |
| :--- | :--- | :--- |
| **Lookup (Safe)** | `dict.get("k", default)` | Returns value or fallback; prevents `KeyError`. |
| **Lookup (Direct)** | `dict["k"]` | Fast access; raises `KeyError` if absent. |
| **Membership** | `'name' in dict` | Checks if key exists in dictionary in $O(1)$ time. |
| **Key View** | `dict.keys()` | Dynamic view of all keys. |
| **Value View** | `dict.values()` | Dynamic view of all values. |
| **Item View** | `dict.items()` | Dynamic view of `(key, value)` pairs. |

## 🛠️ Practical Hands-On & Real-World Examples

### Example 1: In-Memory Multi-Tier Application Configuration Cache
Implement an application settings registry that manages environment configurations and provides safe defaults.

```python
class ConfigurationRegistry:
    def __init__(self):
        self._settings: dict[str, any] = {}

    def set_config(self, key: str, value: any):
        self._settings[key.strip().lower()] = value

    def get_config(self, key: str, default: any = None) -> any:
        # Use dict.get to avoid KeyErrors
        return self._settings.get(key.strip().lower(), default)

    def display_active_settings(self):
        print(f"{'Setting Key':<20} | {'Active Value':<20} | {'Type'}")
        print("-" * 55)
        for k, v in self._settings.items():
            print(f"{k:<20} | {str(v):<20} | {type(v).__name__}")

config = ConfigurationRegistry()
config.set_config("DB_HOST", "db-cluster.internal.net")
config.set_config("DB_PORT", 5432)
config.set_config("ENABLE_SSL", True)
config.set_config("POOL_SIZE", 25)

config.display_active_settings()
print(f"
Lookup 'DB_PORT': {config.get_config('db_port')}")
print(f"Lookup Missing 'TIMEOUT' (with default): {config.get_config('timeout', 30)}")
```

**Step-by-Step Explanation**:
1. Normalizes configuration keys to lowercase strings.
2. Uses `.get(..., default)` to guarantee missing settings return safe defaults without terminating execution.
3. Iterates over `.items()` to inspect the runtime configuration state.

**Expected Console Output**:
```text
Setting Key          | Active Value         | Type
-------------------------------------------------------
db_host              | db-cluster.internal.net | str
db_port              | 5432                 | int
enable_ssl           | True                 | bool
pool_size            | 25                   | int

Lookup 'DB_PORT': 5432
Lookup Missing 'TIMEOUT' (with default): 30
```

### Example 2: Fast Word Frequency Counter & Inverted Index
Read raw text, tokenize words, and build an inverted index mapping words to their frequency counts.

```python
def compute_word_frequencies(document_text: str) -> dict[str, int]:
    # Clean text and split
    words = document_text.lower().replace(".", "").replace(",", "").split()
    
    frequency_map: dict[str, int] = {}
    for word in words:
        # If word in map, increment; else initialize to 0 + 1
        frequency_map[word] = frequency_map.get(word, 0) + 1
        
    return frequency_map

corpus = "Python is powerful and Python is fast. Learning Python is fun."
freqs = compute_word_frequencies(corpus)

print("Word Frequency Inverted Index:")
# Sort by frequency descending
sorted_by_freq = sorted(freqs.items(), key=lambda x: x[1], reverse=True)
for word, count in sorted_by_freq:
    print(f"  '{word:<10}': {count} occurrences")
```

**Step-by-Step Explanation**:
1. `frequency_map.get(word, 0) + 1` is the canonical Python idiom for tallying frequencies without throwing `KeyError`.
2. Sorts `freqs.items()` dynamically to rank the most frequent terms.

**Expected Console Output**:
```text
Word Frequency Inverted Index:
  'python    ': 3 occurrences
  'is        ': 3 occurrences
  'powerful  ': 1 occurrences
  'and       ': 1 occurrences
  'fast      ': 1 occurrences
  'learning  ': 1 occurrences
  'fun       ': 1 occurrences
```

### Example 3: Dynamic View Reflection & Live Mutability Demonstration
Demonstrate how dictionary views (`keys()`, `values()`) are dynamic live windows into underlying dictionary data.

```python
def demonstrate_dynamic_views():
    inventory = {"Apples": 50, "Bananas": 30, "Oranges": 20}
    
    # Extract views
    inv_keys = inventory.keys()
    inv_values = inventory.values()
    
    print("=== Initial State ===")
    print(f"Keys View  : {list(inv_keys)}")
    print(f"Total Units: {sum(inv_values)}")
    
    # Mutate the dictionary by adding a new product and updating an existing count
    inventory["Mangoes"] = 40
    inventory["Apples"] += 25
    
    print("
=== Post Mutation (Without Re-querying Views!) ===")
    print(f"Keys View Automatically Updated  : {list(inv_keys)}")
    print(f"Total Units Automatically Updated: {sum(inv_values)}")

demonstrate_dynamic_views()
```

**Step-by-Step Explanation**:
1. `inv_keys` and `inv_values` are not static snapshots; they are live views pointing to the dictionary's internal hash table.
2. Modifying `inventory` updates the views automatically without any re-assignment.

**Expected Console Output**:
```text
=== Initial State ===
Keys View  : ['Apples', 'Bananas', 'Oranges']
Total Units: 100

=== Post Mutation (Without Re-querying Views!) ===
Keys View Automatically Updated  : ['Apples', 'Bananas', 'Oranges', 'Mangoes']
Total Units Automatically Updated: 165
```
