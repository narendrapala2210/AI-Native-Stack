## 1. Conceptual Deep-Dive: Behavioral Design Patterns

Behavioral patterns characterize the ways in which classes or objects interact and distribute responsibility:
1. **Strategy Pattern**:
   - Defines a family of algorithms, encapsulates each one, and makes them interchangeable.
   - Strategy lets the algorithm vary independently from clients that use it.
2. **Observer Pattern (Publish-Subscribe)**:
   - Defines a one-to-many dependency between objects so that when one object changes state, all its dependents are notified automatically.
3. **Command Pattern**:
   - Encapsulates a request as an object, thereby letting you parameterize clients with different requests, queue or log requests, and support undoable operations.

## 🛠️ Practical Hands-On & Real-World Examples

### Example 1: Dynamic Shipping Pricing Strategy
Compute shipping fees using interchangeable pricing algorithm strategies.

```python
from typing import Protocol

class ShippingStrategy(Protocol):
    def calculate(self, weight_kg: float) -> float: ...

class StandardGroundStrategy:
    def calculate(self, weight_kg: float) -> float:
        return 5.00 + (weight_kg * 1.50)

class ExpressAirStrategy:
    def calculate(self, weight_kg: float) -> float:
        return 15.00 + (weight_kg * 4.00)

class OrderCalculator:
    def __init__(self, strategy: ShippingStrategy):
        self.strategy = strategy

    def compute_shipping(self, weight_kg: float) -> float:
        return self.strategy.calculate(weight_kg)

def test_strategy():
    calc = OrderCalculator(StandardGroundStrategy())
    print(f"Ground Shipping (10kg): ${calc.compute_shipping(10):.2f}")

    # Switch algorithm dynamically at runtime!
    calc.strategy = ExpressAirStrategy()
    print(f"Express Shipping (10kg): ${calc.compute_shipping(10):.2f}")

test_strategy()
```

#### Step-by-Step Explanation:
1. `OrderCalculator` delegates calculation to the plugged-in strategy object.

#### Expected Output:
```text
Ground Shipping (10kg): $20.00
Express Shipping (10kg): $55.00
```

### Example 2: Real-Time Event Dispatcher (Observer / Pub-Sub Pattern)
Implement an event bus notifying multiple subscriber listeners.

```python
class EventDispatcher:
    def __init__(self):
        self._listeners = {}

    def subscribe(self, event_type: str, listener_callable):
        self._listeners.setdefault(event_type, []).append(listener_callable)

    def publish(self, event_type: str, event_data: dict):
        print(f"[EVENT BUS] Publishing event '{event_type}'...")
        for listener in self._listeners.get(event_type, []):
            listener(event_data)

def email_subscriber(data): print(f"  [Email Listener] Dispatched alert to {data['email']}")
def sms_subscriber(data):   print(f"  [SMS Listener] Dispatched text to {data.get('phone')}")

def test_observer():
    bus = EventDispatcher()
    bus.subscribe("order.created", email_subscriber)
    bus.subscribe("order.created", sms_subscriber)

    bus.publish("order.created", {"order_id": 9921, "email": "dev@corp.com", "phone": "+1-555-0199"})

test_observer()
```

#### Step-by-Step Explanation:
1. Publishers and subscribers are decoupled; new listeners can register without changing publisher logic.

#### Expected Output:
```text
[EVENT BUS] Publishing event 'order.created'...
  [Email Listener] Dispatched alert to dev@corp.com
  [SMS Listener] Dispatched text to +1-555-0199
```

### Example 3: Undoable Action Queue with the Command Pattern
Implement reversible actions with an undo/redo stack.

```python
class Command(Protocol):
    def execute(self) -> None: ...
    def undo(self) -> None: ...

class TextDocument:
    def __init__(self):
        self.text = ""

class AppendTextCommand:
    def __init__(self, doc: TextDocument, text_to_append: str):
        self.doc = doc
        self.text_to_append = text_to_append

    def execute(self):
        self.doc.text += self.text_to_append

    def undo(self):
        self.doc.text = self.doc.text[:-len(self.text_to_append)]

def test_command():
    doc = TextDocument()
    history = []

    # 1. Execute Command 1
    c1 = AppendTextCommand(doc, "Hello ")
    c1.execute()
    history.append(c1)

    # 2. Execute Command 2
    c2 = AppendTextCommand(doc, "World!")
    c2.execute()
    history.append(c2)

    print("Document text after commands:", repr(doc.text))

    # 3. Undo last command
    last_cmd = history.pop()
    last_cmd.undo()
    print("Document text after undo:    ", repr(doc.text))

test_command()
```

#### Step-by-Step Explanation:
1. Encapsulating actions inside `Command` objects enables transactional undo histories.

#### Expected Output:
```text
Document text after commands: 'Hello World!'
Document text after undo:     'Hello '
```
