## 1. Conceptual Deep-Dive: Python's Gradual Typing System

Python is a dynamically-typed language, but since PEP 484 (Python 3.5), it supports **Gradual Typing** via type annotations:
1. **Runtime Inaction**:
   - Type annotations are completely ignored by the CPython interpreter at runtime; they do not alter execution speeds or throw type errors automatically.
   - They are consumed by static type checkers (`mypy`, `pyright`), IDE auto-completion engines, and validation libraries (`Pydantic`).
2. **Modern Built-in Generics (PEP 585 — Python 3.9+)**:
   - No longer need to import `from typing import List, Dict, Set, Tuple`.
   - Use standard built-in types directly: `list[str]`, `dict[str, int]`, `set[float]`, `tuple[int, str]`.
3. **Modern Union Syntax (PEP 604 — Python 3.10+)**:
   - Replace `Union[int, str]` with the pipe operator: `int | str`.
   - Replace `Optional[str]` with: `str | None`.

## 🛠️ Practical Hands-On & Real-World Examples

### Example 1: Modern Type Annotations with Unions and Optionals
Define fully type-hinted service functions using modern Python 3.10+ syntax.

```python
def search_product_catalog(
    query: str,
    categories: list[str] | None = None,
    max_results: int = 10
) -> dict[str, list[dict[str, str | float]]]:
    # Simulate catalog search
    catalog_results = [
        {"id": "PROD-101", "name": "4K Ultra Display", "price": 389.99},
        {"id": "PROD-102", "name": "Ergonomic Desk", "price": 450.00}
    ]
    return {"matches": catalog_results[:max_results]}

def test_type_annotated_function():
    # Introspect runtime annotations
    annotations = search_product_catalog.__annotations__
    print("Function Annotations Introspection:")
    for param, type_hint in annotations.items():
        print(f"  {param:<12} => {type_hint}")

test_type_annotated_function()
```

#### Step-by-Step Explanation:
1. `categories: list[str] | None` clearly specifies that `None` is acceptable.
2. `__annotations__` retains the declared types for reflection and schema generation.

#### Expected Output:
```text
Function Annotations Introspection:
  query        => <class 'str'>
  categories   => list[str] | None
  max_results  => <class 'int'>
  return       => dict[str, list[dict[str, str | float]]]
```

### Example 2: Type Aliases (PEP 613 & Python 3.12 `type` Statement)
Define clear semantic domain aliases for complex nested type structures.

```python
# Modern Python 3.12+ type alias statement: type JsonValue = ...
from typing import TypeAlias

UserId: TypeAlias = int
Coordinates: TypeAlias = tuple[float, float]
UserRegistry: TypeAlias = dict[UserId, Coordinates]

def lookup_user_location(user_id: UserId, registry: UserRegistry) -> Coordinates | None:
    return registry.get(user_id)

def test_type_aliases():
    db: UserRegistry = {
        1001: (37.7749, -122.4194),
        1002: (40.7128, -74.0060)
    }

    loc = lookup_user_location(1001, db)
    print(f"Resolved Coordinates for User 1001: {loc}")

test_type_aliases()
```

#### Step-by-Step Explanation:
1. `TypeAlias` improves code readability by replacing complex nested types with domain terms.

#### Expected Output:
```text
Resolved Coordinates for User 1001: (37.7749, -122.4194)
```

### Example 3: Runtime Type Validation Inspection with `typing.get_type_hints`
Resolve stringified annotations and evaluate forward references using `typing.get_type_hints`.

```python
from typing import get_type_hints

class ServerConfig:
    host: str
    port: int
    timeout: float = 30.0

def test_type_hints_extraction():
    # Extract resolved type hints from class
    hints = get_type_hints(ServerConfig)
    
    print("Resolved Class Type Hints:")
    for field, field_type in hints.items():
        print(f"  Field '{field}': {field_type.__name__}")

test_type_hints_extraction()
```

#### Step-by-Step Explanation:
1. `get_type_hints()` safely evaluates forward references and returns standard type objects.

#### Expected Output:
```text
Resolved Class Type Hints:
  Field 'host': str
  Field 'port': int
  Field 'timeout': float
```
