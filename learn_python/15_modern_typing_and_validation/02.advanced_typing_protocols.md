## 1. Conceptual Deep-Dive: Advanced Type Constructs

Python provides specialized typing primitives for advanced application patterns:
1. **`typing.Callable[[ArgTypes], ReturnType]`**:
   - Annotates functions, callbacks, and callable objects.
   - Example: `Callable[[int, int], str]`.
2. **`typing.Literal["val1", "val2"]`**:
   - Restricts an argument to specific string, integer, or enum literal values.
3. **`typing.TypedDict`**:
   - A dictionary with a fixed set of typed keys.
   - Validates at static type-check time while remaining a standard Python `dict` at runtime.
4. **`typing.Protocol` (Structural Subtyping)**:
   - Python's static duck typing mechanism (PEP 544).
   - Any class implementing the declared methods matches the protocol automatically without inheritance.

## 🛠️ Practical Hands-On & Real-World Examples

### Example 1: Callback Signature Validation with `typing.Callable`
Type-hint asynchronous callback pipelines cleanly.

```python
from typing import Callable

# Handler callback type: takes event_id (str) and payload (dict), returns bool
EventHandler: type = Callable[[str, dict], bool]

def register_listener(event_name: str, handler: EventHandler):
    print(f"Registered handler for event: '{event_name}'")
    # Simulate trigger
    success = handler("EVT-100", {"status": "ACTIVE"})
    print(f"Handler execution status: {success}")

def my_sample_handler(event_id: str, payload: dict) -> bool:
    print(f"  [HANDLER] Processing {event_id} with data: {payload}")
    return True

register_listener("user.signup", my_sample_handler)
```

#### Step-by-Step Explanation:
1. `Callable[[str, dict], bool]` enforces that handlers accept the expected parameters and return a boolean.

#### Expected Output:
```text
Registered handler for event: 'user.signup'
  [HANDLER] Processing EVT-100 with data: {'status': 'ACTIVE'}
Handler execution status: True
```

### Example 2: Structured Mappings with `TypedDict` and `Literal`
Model strictly shaped API payloads using `TypedDict` and constrained `Literal` fields.

```python
from typing import TypedDict, Literal

Environment: type = Literal["development", "staging", "production"]

class DatabasePayload(TypedDict):
    host: str
    port: int
    env: Environment
    ssl_enabled: bool

def connect_database(payload: DatabasePayload):
    print(f"Connecting to {payload['host']}:{payload['port']} ({payload['env']})")

def test_typed_dict():
    # Valid typed dictionary
    cfg: DatabasePayload = {
        "host": "db.cloud.internal",
        "port": 5432,
        "env": "production",
        "ssl_enabled": True
    }
    connect_database(cfg)

test_typed_dict()
```

#### Step-by-Step Explanation:
1. `Literal[...]` prevents invalid environment strings (e.g. `"prod"` instead of `"production"`).
2. `TypedDict` provides IDE autocomplete and type verification on dictionary keys.

#### Expected Output:
```text
Connecting to db.cloud.internal:5432 (production)
```

### Example 3: Structural Duck Typing with `typing.Protocol`
Define an interface for file-like objects using `Protocol`.

```python
from typing import Protocol

class ClosableReader(Protocol):
    def read(self, size: int = -1) -> bytes: ...
    def close(self) -> None: ...

# Custom class without any inheritance!
class NetworkStream:
    def read(self, size: int = -1) -> bytes:
        return b"NETWORK_DATA"
    def close(self) -> None:
        print("NetworkStream closed.")

def consume_stream(stream: ClosableReader):
    data = stream.read(100)
    print("Read from stream:", data)
    stream.close()

def test_protocol_duck_typing():
    ns = NetworkStream()
    # Matches ClosableReader structurally!
    consume_stream(ns)

test_protocol_duck_typing()
```

#### Step-by-Step Explanation:
1. `consume_stream` accepts any class providing `read()` and `close()`, enabling loose coupling.

#### Expected Output:
```text
Read from stream: b'NETWORK_DATA'
NetworkStream closed.
```
