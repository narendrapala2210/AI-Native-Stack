## 1. Conceptual Deep-Dive: The `functools` Power Decorators

Python's standard library `functools` module includes powerful built-in decorators:
1. **`@functools.lru_cache(maxsize=128)`**:
   - Implements a **Least Recently Used (LRU) Cache**.
   - Caches function results based on positional and keyword arguments.
   - When the cache reaches `maxsize`, least recently accessed items are evicted.
   - Provides `.cache_info()` (hits, misses, currsize) and `.cache_clear()`.
   - Python 3.9+ also provides `@functools.cache` (unbounded cache).
2. **`@functools.singledispatch`**:
   - Enables **Function Overloading** based on the type of the first argument.
   - Transforms a single function into a generic dispatch dispatcher, registering specialized implementations using `@func.register(TargetType)`.

## 🛠️ Practical Hands-On & Real-World Examples

### Example 1: Memoizing Recursive DP with `@functools.lru_cache`
Optimize exponential recursive Fibonacci calculations down to $O(n)$ linear time.

```python
import functools
import time

# Without cache: O(2^n) exponential disaster
# With lru_cache: O(n) linear memoization!
@functools.lru_cache(maxsize=128)
def fib_memoized(n: int) -> int:
    if n <= 1:
        return n
    return fib_memoized(n - 1) + fib_memoized(n - 2)

def test_lru_cache():
    start = time.perf_counter()
    ans = fib_memoized(35)
    elapsed = (time.perf_counter() - start) * 1000

    print(f"Fibonacci(35) = {ans} (Calculated in {elapsed:.3f}ms)")
    
    # Inspect cache performance metrics
    info = fib_memoized.cache_info()
    print(f"Cache Statistics: Hits={info.hits}, Misses={info.misses}, Size={info.currsize}/{info.maxsize}")

test_lru_cache()
```

#### Step-by-Step Explanation:
1. Each intermediate subproblem (`fib(34)`, `fib(33)`) is computed exactly once and stored in the LRU hash table.
2. `fib_memoized.cache_info()` reports hit and miss statistics.

#### Expected Output:
```text
Fibonacci(35) = 9227465 (Calculated in ~0.05ms)
Cache Statistics: Hits=33, Misses=36, Size=36/128
```

### Example 2: Type-Driven Function Overloading with `@functools.singledispatch`
Implement a polymorphic data serializer handling diverse data structures cleanly.

```python
import functools
from datetime import datetime, date

@functools.singledispatch
def format_data(arg):
    # Default fallback
    return f"[GENERIC] {str(arg)}"

@format_data.register(int)
@format_data.register(float)
def _(arg: int | float):
    return f"[NUMBER] {arg:,.2f}"

@format_data.register(str)
def _(arg: str):
    return f"[STRING] '{arg.strip()}'"

@format_data.register(list)
def _(arg: list):
    formatted_items = [format_data(x) for x in arg]
    return f"[LIST (len={len(arg)})] -> {', '.join(formatted_items)}"

@format_data.register(datetime)
def _(arg: datetime):
    return f"[DATETIME] {arg.isoformat()}"

def test_singledispatch():
    print(format_data(12450.5))
    print(format_data("   user_session_token   "))
    print(format_data(datetime(2026, 9, 14, 12, 0, 0)))
    print(format_data([100, "hello", True]))

test_singledispatch()
```

#### Step-by-Step Explanation:
1. `singledispatch` inspects `type(arg)` dynamically.
2. Dispatches to the registered handler without long `if isinstance(...)` chains.

#### Expected Output:
```text
[NUMBER] 12,450.50
[STRING] 'user_session_token'
[DATETIME] 2026-09-14T12:00:00
[LIST (len=3)] -> [NUMBER] 100.00, [STRING] 'hello', [GENERIC] True
```

### Example 3: Total Ordering Generator with `@functools.total_ordering`
Generate all six rich comparison dunders (`<`, `<=`, `>`, `>=`, `==`, `!=`) by defining only `__eq__` and `__lt__`.

```python
import functools

@functools.total_ordering
class TaskItem:
    def __init__(self, priority: int, name: str):
        self.priority = priority
        self.name = name

    def __eq__(self, other):
        if not isinstance(other, TaskItem): return False
        return self.priority == other.priority

    def __lt__(self, other):
        if not isinstance(other, TaskItem): return NotImplemented
        return self.priority < other.priority

def test_total_ordering():
    t1 = TaskItem(1, "Fix typo")
    t2 = TaskItem(5, "Deploy production hotfix")

    # total_ordering generates <=, >, >= automatically!
    print(f"t1 < t2  : {t1 < t2}")
    print(f"t1 <= t2 : {t1 <= t2}")
    print(f"t1 > t2  : {t1 > t2}")
    print(f"t1 >= t2 : {t1 >= t2}")

test_total_ordering()
```

#### Step-by-Step Explanation:
1. Implementing all 6 comparison dunders manually is tedious.
2. `@total_ordering` infers `>=, <=, >` mathematically from `__lt__` and `__eq__`.

#### Expected Output:
```text
t1 < t2  : True
t1 <= t2 : True
t1 > t2  : False
t1 >= t2 : False
```
