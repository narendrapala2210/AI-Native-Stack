# 03. Logical Operators & Short-Circuit Evaluation

## 📖 Concept Overview
Logical operators combine or invert boolean values:
- **`and`**: Returns `True` only if **both** operands are truthy.
- **`or`**: Returns `True` if **at least one** operand is truthy.
- **`not`**: Inverts the truth value of the operand (`not True` -> `False`).

---

### 1. Truth Tables
```text
  A       B     | A and B | A or B
----------------+---------+--------
 True    True   |  True   |  True
 True    False  |  False  |  True
 False   True   |  False  |  True
 False   False  |  False  |  False
```

---

### 2. Short-Circuit Evaluation
In Python, `and` and `or` perform **short-circuit evaluation**:
- **For `and`**: If the first operand is falsy, Python stops and returns that first operand immediately without evaluating the second operand (because the result cannot be True).
- **For `or`**: If the first operand is truthy, Python stops and returns that first operand immediately without evaluating the second operand.

```python
# The right operand is never executed, preventing a ZeroDivisionError crash!
x = 0
if x != 0 and (10 / x > 2):
    print("Success")
```

---

## 📋 Summary & Logical Operators Reference

| Expression | Evaluates To | Short-Circuit Rule |
| :--- | :--- | :--- |
| `A and B` | First falsy operand, or `B` | If `A` is falsy, returns `A` without evaluating `B`. |
| `A or B` | First truthy operand, or `B` | If `A` is truthy, returns `A` without evaluating `B`. |
| `not A` | `True` if `A` is falsy, `False` otherwise | Unary inversion operator. |

## 🛠️ Practical Hands-On & Real-World Examples

### Example 1: Shielding Against Attribute & Division Errors via Short-Circuiting
Demonstrate short-circuit evaluation protecting code from crashes when accessing nullable object attributes.

```python
def process_user_profile(user: dict | None):
    # Short-circuiting shields against TypeError or KeyError:
    # If user is None, user is not None evaluates to False -> immediately exits!
    if user is not None and "subscription" in user and user["subscription"]["is_active"]:
        print(f"Granted Premium Streaming to: {user['name']}")
    else:
        print("Access Restricted: User has no active subscription.")

process_user_profile({"name": "Alice", "subscription": {"is_active": True}})
process_user_profile(None)
```

**Step-by-Step Explanation**:
1. If `user is None`, evaluating `user["subscription"]` would raise `TypeError: 'NoneType' object is not subscriptable`.
2. The `and` operator halts on `user is not None`, making defensive programming concise.

**Expected Console Output**:
```text
Granted Premium Streaming to: Alice
Access Restricted: User has no active subscription.
```

### Example 2: Multi-Criteria Fraud Detection Engine
Evaluate credit card transactions against risk rules using complex `and`, `or`, and `not` logical combinations.

```python
def evaluate_transaction_risk(amount: float, is_foreign_ip: bool, is_new_device: bool, card_holder_notified: bool) -> str:
    # High Risk Condition:
    # High value transaction AND (unrecognized foreign IP OR new unverified device) AND NOT already approved
    is_high_risk = (amount > 5_000.00) and (is_foreign_ip or is_new_device) and (not card_holder_notified)
    
    # Low Risk Condition:
    # Domestic IP AND familiar device
    is_trusted = (not is_foreign_ip) and (not is_new_device)
    
    if is_high_risk:
        return "ACTION_BLOCKED: High Risk Fraud Suspected. SMS Verification Triggered."
    elif is_trusted:
        return "ACTION_APPROVED: Trusted Customer Profile."
    else:
        return "ACTION_MANUAL_REVIEW: Flagged for Secondary Inspection."

print(evaluate_transaction_risk(8_500.00, True, True, False))
print(evaluate_transaction_risk(150.00, False, False, False))
print(evaluate_transaction_risk(600.00, True, False, True))
```

**Step-by-Step Explanation**:
1. Combines grouping parentheses to enforce business logic boundaries.
2. Evaluates security states without nested `if` trees.

**Expected Console Output**:
```text
ACTION_BLOCKED: High Risk Fraud Suspected. SMS Verification Triggered.
ACTION_APPROVED: Trusted Customer Profile.
ACTION_MANUAL_REVIEW: Flagged for Secondary Inspection.
```

### Example 3: Fallback Configuration Resolver using `or` Chaining
Resolve missing application configurations across local flags, environment variables, and hardcoded defaults.

```python
def resolve_database_host(cli_flag: str | None, env_var: str | None, default_host: str = "localhost") -> str:
    # Short-circuits to the first non-empty / truthy string!
    active_host = cli_flag or env_var or default_host
    return active_host

print("Test 1 (CLI passed) :", resolve_database_host("192.168.1.50", "staging-db.net"))
print("Test 2 (Env passed) :", resolve_database_host(None, "staging-db.net"))
print("Test 3 (Fallback)   :", resolve_database_host(None, None))
```

**Step-by-Step Explanation**:
1. If `cli_flag` is truthy, returns immediately.
2. If `cli_flag` is falsy (`None` or `""`), evaluates `env_var`.
3. If both are falsy, returns `default_host`.

**Expected Console Output**:
```text
Test 1 (CLI passed) : 192.168.1.50
Test 2 (Env passed) : staging-db.net
Test 3 (Fallback)   : localhost
```
