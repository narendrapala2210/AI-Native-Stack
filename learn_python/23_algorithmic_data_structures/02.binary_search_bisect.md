## 1. Conceptual Deep-Dive: Bisection Mechanics

Finding an element in an unsorted list requires an $O(N)$ linear scan. When a list is pre-sorted, **Binary Search** reduces the search space by half at each step, achieving $O(\log N)$ time complexity.

Python's `bisect` module implements binary search in compiled C:
- **`bisect_left(a, x)`**: Returns the leftmost insertion index for `x` to maintain sorted order. If `x` already exists in `a`, the index points *before* existing occurrences.
- **`bisect_right(a, x)`** (alias `bisect`): Returns the rightmost insertion index. If `x` already exists in `a`, the index points *after* existing occurrences.
- **`insort_left(a, x)`** / **`insort_right(a, x)`**: Inserts `x` into `a` in sorted order ($O(\log N)$ search, followed by $O(N)$ array shift).

```
Sorted Array: [ 10,  20,  20,  20,  30 ]
Index:          0    1    2    3    4

bisect_left(arr, 20)  -> Returns index 1 (before the 20s)
bisect_right(arr, 20) -> Returns index 4 (after the 20s)
```

---

## 2. API Quick Reference

| Function | Condition for Duplicate Values | Return Behavior |
|---|---|---|
| `bisect_left(a, x)` | Points before duplicates | Useful for checking element existence and lower bounds |
| `bisect_right(a, x)` | Points after duplicates | Useful for numeric range partitioning and upper bounds |
| `insort(a, x)` | Inserts using `bisect_right` | Keeps list continuously sorted |

## 3. Practical Code Examples with Step-by-Step Explanations

### Example 1: Numeric Grade and Tier Partitioning
Map continuous numeric values into discrete categories using `bisect`.

```python
import bisect

# Breakpoints must be strictly sorted
BREAKPOINTS = [60, 70, 80, 90]
GRADES = ["F", "D", "C", "B", "A"]

def get_letter_grade(score: float) -> str:
    # bisect_right returns insertion index (0 to 4)
    idx = bisect.bisect_right(BREAKPOINTS, score)
    return GRADES[idx]

scores_to_test = [55, 60, 75, 89.5, 90, 98]
print("Grade Allocations:")
for s in scores_to_test:
    print(f"  Score {s:4.1f} -> Grade {get_letter_grade(s)}")
```

#### Step-by-Step Explanation:
1. Breakpoints define interval buckets:
   - `< 60` -> Index `0` (`F`)
   - `60 <= score < 70` -> Index `1` (`D`)
   - `70 <= score < 80` -> Index `2` (`C`)
   - `80 <= score < 90` -> Index `3` (`B`)
   - `>= 90` -> Index `4` (`A`)
2. `bisect_right` replaces lengthy `if/elif/else` ladders with a clean $O(\log K)$ table lookup.

#### Expected Output:
```text
Grade Allocations:
  Score 55.0 -> Grade F
  Score 60.0 -> Grade D
  Score 75.0 -> Grade C
  Score 89.5 -> Grade B
  Score 90.0 -> Grade A
  Score 98.0 -> Grade A
```

### Example 2: Exact Value Existence Check via `bisect_left`
Perform an $O(\log N)$ exact-match lookup on a sorted collection.

```python
import bisect

def binary_search_contains(sorted_list: list, target) -> int | None:
    idx = bisect.bisect_left(sorted_list, target)
    # Check if index is within bounds and matches target exactly
    if idx < len(sorted_list) and sorted_list[idx] == target:
        return idx
    return None

data = [102, 205, 309, 412, 550, 672, 890, 999]

# Successful lookup
found_idx = binary_search_contains(data, 412)
print(f"Value 412 found at index: {found_idx}")

# Unsuccessful lookup
missing_idx = binary_search_contains(data, 500)
print(f"Value 500 found: {missing_idx}")
```

#### Step-by-Step Explanation:
1. `bisect_left` returns the index where `target` should be placed.
2. If `idx < len(data)` and `data[idx] == target`, the element is present.
3. This delivers $O(\log N)$ lookups without creating an auxiliary hash set.

#### Expected Output:
```text
Value 412 found at index: 3
Value 500 found: None
```

### Example 3: Searching by Object Key via the `key` Parameter (Python 3.10+)
Perform binary search on collections of complex objects without custom comparator wrappers.

```python
import bisect

class UserRecord:
    def __init__(self, user_id: int, username: str):
        self.user_id = user_id
        self.username = username

    def __repr__(self):
        return f"User({self.user_id}, {self.username!r})"

# Pre-sorted by user_id
users = [
    UserRecord(10, "alice"),
    UserRecord(25, "bob"),
    UserRecord(40, "charlie"),
    UserRecord(85, "dave"),
]

# Use key parameter to search by user_id directly
target_id = 40
idx = bisect.bisect_left(users, target_id, key=lambda u: u.user_id)

if idx < len(users) and users[idx].user_id == target_id:
    print(f"Found record: {users[idx]}")
```

#### Step-by-Step Explanation:
1. Python 3.10+ introduced the `key` parameter to `bisect` functions.
2. It extracts the comparison key from each element without requiring custom `__lt__` methods on the class.

#### Expected Output:
```text
Found record: User(40, 'charlie')
```

## 4. Key Takeaways & Best Practices

1. The underlying list **must be sorted** before invoking any `bisect` functions; calling `bisect` on an unsorted list produces undefined results without warning.
2. `insort` preserves sorting order on insertion, but insertion remains an $O(N)$ operation due to array element shifts.
3. Use the `key` argument in Python 3.10+ to search complex objects by attribute or property.
