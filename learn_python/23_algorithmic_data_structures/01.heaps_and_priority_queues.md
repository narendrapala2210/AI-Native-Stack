## 1. Conceptual Deep-Dive: Min-Heap Invariant

A **Binary Heap** is a complete binary tree that satisfies the **Heap Property**:
- **Min-Heap (Python `heapq` default)**: Every parent node is smaller than or equal to both of its children (`heap[k] <= heap[2*k+1]` and `heap[k] <= heap[2*k+2]`).
- The smallest element is always located at root index `heap[0]`.
- Array-based layout: Left child of index $k$ is $2k + 1$; right child is $2k + 2$; parent is $\lfloor(k - 1) / 2\rfloor$.

Complexity Guarantees:
- Find Minimum (`heap[0]`): $O(1)$
- Insert Element (`heappush`): $O(\log N)$
- Pop Minimum (`heappop`): $O(\log N)$
- Transform List into Heap (`heapify`): $O(N)$ (linear time algorithm)

```
Binary Tree Min-Heap View:
             10 (heap[0])
           /    \
         20      15
        /  \    /  \
       30  40  50  25

Contiguous Python List Layout:
[10, 20, 15, 30, 40, 50, 25]
```

## 2. Core `heapq` Operations Matrix

| Function | Time Complexity | Description |
|---|---|---|
| `heapify(list)` | $O(N)$ | Transforms an arbitrary list into a valid min-heap in place |
| `heappush(heap, item)` | $O(\log N)$ | Adds item while preserving the min-heap invariant |
| `heappop(heap)` | $O(\log N)$ | Pops and returns the smallest element |
| `heappushpop(heap, item)` | $O(\log N)$ | Pushes new item first, then pops and returns smallest |
| `heapreplace(heap, item)` | $O(\log N)$ | Pops smallest first, then pushes new item (more efficient than pop+push) |
| `nlargest(k, iterable)` | $O(N \log k)$ | Extracts top $k$ largest elements |
| `nsmallest(k, iterable)` | $O(N \log k)$ | Extracts top $k$ smallest elements |

## 3. Practical Code Examples with Step-by-Step Explanations

### Example 1: Priority Task Queue with Tie-Breaking
Build a task scheduler where tasks execute in priority order with deterministic FIFO tie-breaking.

```python
import heapq
import itertools

class PriorityQueue:
    def __init__(self):
        self._heap = []
        self._counter = itertools.count()  # Unique tie-breaker sequence

    def push(self, task: str, priority: int):
        # Tuple ordering: (priority, entry_count, task)
        # Entry count guarantees stability if priorities match
        count = next(self._counter)
        heapq.heappush(self._heap, (priority, count, task))

    def pop(self) -> str:
        if not self._heap:
            raise IndexError("Pop from empty priority queue")
        priority, count, task = heapq.heappop(self._heap)
        return task

    def is_empty(self) -> bool:
        return len(self._heap) == 0

pq = PriorityQueue()
pq.push("Write Unit Tests", priority=3)
pq.push("Fix Critical Production Outage", priority=1)
pq.push("Update Documentation", priority=3)
pq.push("Refactor Auth Module", priority=2)

print("Execution Order (Lowest Priority Number = Highest Urgency):")
while not pq.is_empty():
    print(f"  -> {pq.pop()}")
```

#### Step-by-Step Explanation:
1. `heapq` compares tuple elements sequentially: `priority`, then `count`, then `task`.
2. The sequence counter prevents Python from comparing task strings when priorities are identical.
3. This guarantees stable FIFO behavior for tasks sharing the same priority level.

#### Expected Output:
```text
Execution Order (Lowest Priority Number = Highest Urgency):
  -> Fix Critical Production Outage
  -> Refactor Auth Module
  -> Write Unit Tests
  -> Update Documentation
```

### Example 2: Merging Multiple Sorted Streams (`heapq.merge`)
Merge pre-sorted logs or data streams with $O(K)$ working memory where $K$ is the number of streams.

```python
import heapq

# Multiple sorted log sequences (e.g. from distributed server nodes)
node_a_logs = [(1001, "Node A: Start"), (1005, "Node A: Process"), (1010, "Node A: Done")]
node_b_logs = [(1002, "Node B: Start"), (1004, "Node B: Health Check"), (1009, "Node B: Finish")]
node_c_logs = [(1003, "Node C: Ping"), (1008, "Node C: Pong")]

# heapq.merge yields items in unified sorted order without loading all streams into RAM
merged_stream = heapq.merge(node_a_logs, node_b_logs, node_c_logs, key=lambda x: x[0])

print("Unified Chronological Log Stream:")
for timestamp, msg in merged_stream:
    print(f"  [{timestamp}] {msg}")
```

#### Step-by-Step Explanation:
1. `heapq.merge` maintains an internal min-heap of size $K$ (one element per input stream).
2. It yields the global next minimum with $O(\log K)$ time per element, enabling efficient streaming of gigabyte-scale sorted files.

#### Expected Output:
```text
Unified Chronological Log Stream:
  [1001] Node A: Start
  [1002] Node B: Start
  [1003] Node C: Ping
  [1004] Node B: Health Check
  [1005] Node A: Process
  [1008] Node C: Pong
  [1009] Node B: Finish
  [1010] Node A: Done
```

### Example 3: Running Top-$K$ Filtering (`nlargest` vs Full Sort)
Extract top elements without the overhead of sorting the entire collection.

```python
import heapq
import random

# Generate 100,000 transaction amounts
random.seed(42)
transactions = [round(random.uniform(10.0, 5000.0), 2) for _ in range(100_000)]

# Extract top 3 largest transactions
top_3 = heapq.nlargest(3, transactions)
print(f"Top 3 largest transactions: {top_3}")

# Extract bottom 3 smallest transactions
bottom_3 = heapq.nsmallest(3, transactions)
print(f"Top 3 smallest transactions: {bottom_3}")
```

#### Step-by-Step Explanation:
1. Full sort (`sorted(list)[:k]`) takes $O(N \log N)$ time.
2. `heapq.nlargest(k, list)` runs in $O(N \log k)$ time, which is substantially faster when $k \ll N$.

#### Expected Output:
```text
Top 3 largest transactions: [4999.98, 4999.93, 4999.88] (or similar)
Top 3 smallest transactions: [10.05, 10.08, 10.12] (or similar)
```

## 4. Key Takeaways & Best Practices

1. Python's `heapq` is strictly a min-heap; to build a max-heap, invert values (e.g. multiply numeric priorities by `-1`).
2. Always use `heapify()` to convert an existing list into a heap in linear $O(N)$ time instead of iteratively pushing elements.
3. Use `heapq.merge()` to merge pre-sorted files or streams with constant memory overhead.
