## 1. Conceptual Deep-Dive: Professional CLI Development

While `sys.argv` provides raw command-line tokens as a list of strings, manually parsing flags, validating types, handling defaults, and generating help manuals is tedious and error-prone.

Python's built-in `argparse` module generates production-grade command-line interfaces:
1. **`ArgumentParser`**:
   - Manages program description, epilog, and auto-generated `--help` / `-h` screens.
2. **Positional Arguments**:
   - Mandatory parameters identified by position (`parser.add_argument("filename")`).
3. **Optional Flags**:
   - Identified by prefix dashes (`-v`, `--verbose`, `--port`).
   - Supports default values, type validation (`type=int`, `type=pathlib.Path`), and choices restrictions (`choices=['json', 'csv']`).
   - Boolean flags use `action="store_true"` or `action="store_false"`.
4. **Subparsers (Git-Style Subcommands)**:
   - Enables multi-action commands like `git commit`, `git push`, or `docker run` using `parser.add_subparsers()`.

## 🛠️ Practical Hands-On & Real-World Examples

### Example 1: Full-Featured Data Processing CLI Tool
Build a command-line utility with positional arguments, optional flags, choices, and default parameters.

```python
import argparse

def create_cli_parser() -> argparse.ArgumentParser:
    parser = argparse.ArgumentParser(
        prog="dataprep",
        description="Enterprise Data Preprocessing & Validation CLI Tool",
        epilog="Copyright 2026 AI Full Stack Systems"
    )

    # 1. Mandatory positional argument
    parser.add_argument("input_file", help="Path to input dataset file (CSV/JSON)")

    # 2. Optional flag with type and default
    parser.add_argument(
        "-b", "--batch-size",
        type=int,
        default=64,
        help="Batch size for processing records (default: 64)"
    )

    # 3. Constrained choices
    parser.add_argument(
        "--format",
        choices=["csv", "json", "parquet"],
        default="json",
        help="Target output serialization format"
    )

    # 4. Boolean toggle flag
    parser.add_argument(
        "--dry-run",
        action="store_true",
        help="Simulate execution without modifying destination database"
    )

    return parser

def test_parser():
    parser = create_cli_parser()

    # Simulate passing arguments programmatically: ['dataset.csv', '--batch-size', '128', '--dry-run']
    args = parser.parse_args(["dataset.csv", "-b", "128", "--format", "parquet", "--dry-run"])

    print("Parsed CLI Arguments:")
    print(f"  Input File : {args.input_file}")
    print(f"  Batch Size : {args.batch_size} (Type: {type(args.batch_size).__name__})")
    print(f"  Format     : {args.format}")
    print(f"  Dry Run?   : {args.dry_run}")

test_parser()
```

#### Step-by-Step Explanation:
1. `parser.parse_args()` automatically converts `--batch-size` into an `int`, verifies `--format` is among allowed choices, and sets boolean `args.dry_run = True`.
2. Automatically generates a complete `--help` manual.

#### Expected Output:
```text
Parsed CLI Arguments:
  Input File : dataset.csv
  Batch Size : 128 (Type: int)
  Format     : parquet
  Dry Run?   : True
```

### Example 2: Multi-Command Architecture with Subparsers (Git-Style CLI)
Design a database management CLI supporting distinct `init` and `migrate` subcommands.

```python
import argparse

def build_subcommand_cli():
    parser = argparse.ArgumentParser(prog="dbmanager", description="Database Migration CLI")
    subparsers = parser.add_subparsers(dest="subcommand", required=True, help="Available subcommands")

    # 1. 'init' subcommand
    init_parser = subparsers.add_parser("init", help="Initialize empty database schema")
    init_parser.add_argument("--db-url", default="sqlite:///dev.db", help="Target database connection URL")

    # 2. 'migrate' subcommand
    migrate_parser = subparsers.add_parser("migrate", help="Apply pending database migrations")
    migrate_parser.add_argument("--revision", default="head", help="Target migration revision")
    migrate_parser.add_argument("--sql", action="store_true", help="Output raw SQL instead of executing")

    return parser

def test_subcommands():
    parser = build_subcommand_cli()

    # Simulate running: dbmanager migrate --revision rev_104 --sql
    args = parser.parse_args(["migrate", "--revision", "rev_104", "--sql"])
    print(f"Executed Subcommand: '{args.subcommand}'")
    print(f"Target Revision    : {args.revision}")
    print(f"Raw SQL Mode       : {args.sql}")

test_subcommands()
```

#### Step-by-Step Explanation:
1. `add_subparsers()` creates namespaces for distinct subcommands.
2. Each subcommand possesses its own isolated arguments and help screens.

#### Expected Output:
```text
Executed Subcommand: 'migrate'
Target Revision    : rev_104
Raw SQL Mode       : True
```

### Example 3: Custom Value Validator and Path Resolver
Enforce custom validation logic (e.g. valid positive port numbers) directly during parsing.

```python
import argparse

def port_number_type(value: str) -> int:
    port = int(value)
    if not (1 <= port <= 65535):
        raise argparse.ArgumentTypeError(f"Invalid network port: {port}. Port must be between 1 and 65535.")
    return port

def build_server_cli():
    parser = argparse.ArgumentParser(prog="webserver")
    parser.add_argument("--port", type=port_number_type, default=8080, help="Listening TCP port")
    return parser

def test_custom_validator():
    parser = build_server_cli()

    # Valid port
    args1 = parser.parse_args(["--port", "443"])
    print(f"Configured valid port: {args1.port}")

    # Invalid port triggers clean error
    try:
        parser.parse_args(["--port", "99999"])
    except SystemExit:
        print("Caught ArgumentParser rejection on out-of-range port.")

test_custom_validator()
```

#### Step-by-Step Explanation:
1. Passing a custom callable to `type=` allows real-time input sanitization.
2. Raising `argparse.ArgumentTypeError` cleanly halts invalid execution without unhandled tracebacks.

#### Expected Output:
```text
Configured valid port: 443
usage: webserver [-h] [--port PORT]
webserver: error: argument --port: Invalid network port: 99999. Port must be between 1 and 65535.
Caught ArgumentParser rejection on out-of-range port.
```
