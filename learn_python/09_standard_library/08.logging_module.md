## 1. Conceptual Deep-Dive: Enterprise Logging Architecture

Using `print()` statements for diagnostic telemetry in production is an anti-pattern: prints cannot be filtered by severity, lack timestamps and module provenance, and cannot be directed to rotating files or remote aggregators.

Python's built-in `logging` module provides a thread-safe, hierarchical logging framework:
1. **Log Levels (Hierarchy of Severity)**:
   - `DEBUG` (10): Detailed diagnostic information.
   - `INFO` (20): Confirmation that events are progressing as expected.
   - `WARNING` (30): Indication that something unexpected occurred, or approaching capacity.
   - `ERROR` (40): Due to a more serious problem, software was unable to execute a function.
   - `CRITICAL` (50): Severe failure; application may be unable to continue running.
2. **Core Components**:
   - **Loggers**: The application interface (`logging.getLogger(__name__)`).
   - **Handlers**: Direct log records to destinations (`StreamHandler` for console, `FileHandler` for disk, `RotatingFileHandler` for size limits).
   - **Formatters**: Define text layout (`%(asctime)s [%(levelname)s] %(name)s: %(message)s`).
   - **Filters**: Fine-grained logic determining whether a log record is processed.

## 🛠️ Practical Hands-On & Real-World Examples

### Example 1: Multi-Handler Configuration (Console Stream + Rotating File)
Configure a production logger routing human-readable output to console and debug traces to disk.

```python
import logging
from logging.handlers import RotatingFileHandler
import os

def setup_app_logger(logger_name: str) -> logging.Logger:
    logger = logging.getLogger(logger_name)
    logger.setLevel(logging.DEBUG)  # Capture all events at root logger

    # Avoid duplicate handlers if function re-invoked
    if logger.handlers:
        return logger

    # 1. Console Handler: Shows INFO and above
    console_handler = logging.StreamHandler()
    console_handler.setLevel(logging.INFO)
    console_formatter = logging.Formatter('[%(levelname)s] %(message)s')
    console_handler.setFormatter(console_formatter)

    # 2. File Handler: Captures DEBUG and above with rotating 1MB files
    log_file = "service_runtime.log"
    file_handler = RotatingFileHandler(log_file, maxBytes=1024*1024, backupCount=3)
    file_handler.setLevel(logging.DEBUG)
    file_formatter = logging.Formatter('%(asctime)s | %(levelname)-8s | %(name)s | %(message)s')
    file_handler.setFormatter(file_formatter)

    logger.addHandler(console_handler)
    logger.addHandler(file_handler)
    return logger

def test_logger():
    log = setup_app_logger("payment_service")
    log.debug("Initializing TLS socket connection...")  # Goes only to file!
    log.info("Payment service worker spawned successfully.")
    log.warning("Memory pool threshold reached 82%.")
    log.error("Failed to connect to gateway timeout after 3 retries.")

    # Cleanup log file
    if os.path.exists("service_runtime.log"):
        with open("service_runtime.log") as f:
            print("\n--- Disk File Contents ---")
            print(f.read().strip())
        os.remove("service_runtime.log")

test_logger()
```

#### Step-by-Step Explanation:
1. `StreamHandler` filters records so terminal operators only see clean high-level `INFO` messages.
2. `RotatingFileHandler` stores verbose `DEBUG` traces on disk without exhausting hard drive space.

#### Expected Output:
```text
[INFO] Payment service worker spawned successfully.
[WARNING] Memory pool threshold reached 82%.
[ERROR] Failed to connect to gateway timeout after 3 retries.

--- Disk File Contents ---
... | DEBUG    | payment_service | Initializing TLS socket connection...
... | INFO     | payment_service | Payment service worker spawned successfully.
... | WARNING  | payment_service | Memory pool threshold reached 82%.
... | ERROR    | payment_service | Failed to connect to gateway timeout after 3 retries.
```

### Example 2: Automatic Exception Traceback Capture with `logger.exception()`
Capture unexpected crashes with full stack trace introspection without crashing the process.

```python
import logging

logging.basicConfig(level=logging.INFO, format='%(levelname)s: %(message)s')
logger = logging.getLogger("worker")

def process_batch_job(dividend: int, divisor: int):
    try:
        result = dividend / divisor
        logger.info(f"Processed task successfully: {dividend} / {divisor} = {result}")
    except ZeroDivisionError:
        # logger.exception() logs with ERROR level and automatically appends the sys.exc_info() traceback!
        logger.exception("Task processing failed with mathematical fault!")

process_batch_job(10, 2)
process_batch_job(10, 0)
```

#### Step-by-Step Explanation:
1. `logger.exception()` eliminates the need to manually import `traceback`.
2. Automatically extracts the active exception and logs the complete stack trace cleanly.

#### Expected Output:
```text
INFO: Processed task successfully: 10 / 2 = 5.0
ERROR: Task processing failed with mathematical fault!
Traceback (most recent call last):
  ...
ZeroDivisionError: division by zero
```

### Example 3: Contextual Custom Log Filter Attaching Correlation IDs
Inject distributed tracing correlation IDs (`trace_id`) into log formatters automatically.

```python
import logging

class TraceIdFilter(logging.Filter):
    def __init__(self, trace_id: str):
        super().__init__()
        self.trace_id = trace_id

    def filter(self, record):
        # Attach attribute to the LogRecord object dynamically
        record.trace_id = self.trace_id
        return True

def test_tracing_filter():
    logger = logging.getLogger("trace_logger")
    logger.setLevel(logging.INFO)
    logger.handlers.clear()

    handler = logging.StreamHandler()
    formatter = logging.Formatter('[TraceID: %(trace_id)s] %(levelname)s: %(message)s')
    handler.setFormatter(formatter)
    logger.addHandler(handler)

    # Attach correlation filter for User Session A
    trace_filter = TraceIdFilter("req-9982-uuid")
    logger.addFilter(trace_filter)

    logger.info("Incoming GraphQL mutation received.")
    logger.info("Database transaction committed.")

test_tracing_filter()
```

#### Step-by-Step Explanation:
1. `logging.Filter.filter()` intercepts log records before they are formatted.
2. Injects `record.trace_id` dynamically, enabling cloud log aggregation search across microservices.

#### Expected Output:
```text
[TraceID: req-9982-uuid] INFO: Incoming GraphQL mutation received.
[TraceID: req-9982-uuid] INFO: Database transaction committed.
```
