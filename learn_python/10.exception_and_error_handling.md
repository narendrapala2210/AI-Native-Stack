# 10. Robust Exception & Error Handling

### 10.1 Built-in Exception Hierarchy

All built-in exceptions inherit from `BaseException`. Normal application code should almost always catch `Exception`, not `BaseException`, to avoid intercepting system exits or keyboard interrupts.

```
BaseException
 ├── BaseExceptionGroup (Python 3.11+)
 ├── GeneratorExit
 ├── KeyboardInterrupt (Ctrl+C)
 ├── SystemExit (sys.exit())
 └── Exception (Standard application errors)
      ├── ArithmeticError (ZeroDivisionError, OverflowError)
      ├── AssertionError
      ├── AttributeError
      ├── BufferError
      ├── EOFError
      ├── ImportError (ModuleNotFoundError)
      ├── LookupError (IndexError, KeyError)
      ├── NameError (UnboundLocalError)
      ├── OSError (FileNotFoundError, PermissionError, ConnectionError)
      ├── RuntimeError (RecursionError)
      ├── StopIteration, StopAsyncIteration
      ├── SyntaxError (IndentationError)
      ├── TypeError
      └── ValueError (UnicodeError)
```

### 10.2 Complete Syntax: try, except, else, finally

The full exception block consists of four clauses:
1. `try`: The code that may raise an exception.
2. `except`: Handles specific exceptions when they occur.
3. `else`: Executes **ONLY** if no exception was raised in `try`.
4. `finally`: Executes **ALWAYS**, even if an exception was raised, unhandled, or if `return` was called!

```python
def process_file_data(filename: str) -> None:
    file_handle = None
    try:
        print(f"1. Attempting to open '{filename}'...")
        file_handle = open(filename, "r", encoding="utf-8")
        content = file_handle.read()
        val = int(content.strip())
        result = 100 / val
    except FileNotFoundError as fnf_err:
        print(f"Error: File '{filename}' was not found: {fnf_err}")
    except (ValueError, ZeroDivisionError) as calc_err:
        print(f"Error parsing or calculating data: {calc_err}")
    except Exception as generic_err:
        print(f"Unexpected error: {type(generic_err).__name__}: {generic_err}")
    else:
        # Executes only when NO exception was raised in try block
        print(f"Success! Calculated result: {result}")
    finally:
        # Executes unconditionally (cleanup tasks)
        if file_handle and not file_handle.closed:
            file_handle.close()
            print("Cleanup: File handle closed.")
        print("4. Execution flow finished.")
```

### 10.3 Raising Exceptions & Custom Exception Hierarchies

Always create application-specific exception hierarchies inheriting from `Exception`.

```python
class ApplicationError(Exception):
    """Base exception for entire application domain."""
    def __init__(self, message: str, error_code: str = "GENERIC_ERROR"):
        super().__init__(message)
        self.error_code = error_code

class InsufficientBalanceError(ApplicationError):
    """Raised when an account does not have enough funds."""
    def __init__(self, current_balance: float, requested_amount: float):
        super().__init__(
            f"Insufficient funds: Current balance is ${current_balance:.2f}, but requested ${requested_amount:.2f}.",
            error_code="INSUFFICIENT_FUNDS"
        )
        self.current_balance = current_balance
        self.requested_amount = requested_amount

def withdraw(balance: float, amount: float) -> float:
    if amount > balance:
        raise InsufficientBalanceError(balance, amount)
    return balance - amount

try:
    withdraw(50.0, 120.0)
except InsufficientBalanceError as err:
    print(f"[{err.error_code}] {err}")
```

### 10.4 Exception Chaining (`raise ... from ...`)

Exception chaining preserves the original traceback when re-raising a higher-level exception.

```python
import sqlite3

class DatabaseConnectionError(Exception):
    pass

def query_user_records(db_path: str):
    try:
        conn = sqlite3.connect(db_path)
        cursor = conn.cursor()
        cursor.execute("SELECT * FROM non_existent_table")
    except sqlite3.OperationalError as original_error:
        # Explicit chaining using 'from' links original cause to new exception
        raise DatabaseConnectionError("Failed to query user database") from original_error

# Suppressing context:
# raise NewError("Clean message") from None
```

### 10.5 Python 3.11+ Exception Groups & `except*`

In Python 3.11+, multiple concurrent exceptions can be bundled into an `ExceptionGroup` and handled selectively using `except*`.

```python
def validate_payload(data: dict):
    errors = []
    if "username" not in data:
        errors.append(ValueError("Missing 'username'"))
    if "age" not in data or not isinstance(data["age"], int):
        errors.append(TypeError("'age' must be an integer"))

    if errors:
        raise ExceptionGroup("Validation failed with multiple errors", errors)

try:
    validate_payload({"email": "test@test.com"})
except* ValueError as eg_val:
    for e in eg_val.exceptions:
        print("Handled Value Error:", e)
except* TypeError as eg_type:
    for e in eg_type.exceptions:
        print("Handled Type Error:", e)
```

### 10.6 Context Managers & the `with` Statement (`contextlib`)

Context managers guarantee resource cleanup via `__enter__` and `__exit__`.

```python
import contextlib
import time

# 1. Custom Class Context Manager
class ManagedResource:
    def __enter__(self):
        print("Resource acquired.")
        return self

    def __exit__(self, exc_type, exc_val, exc_tb):
        print("Resource safely released.")
        # Returning True suppresses the exception if one occurred
        if exc_type is ZeroDivisionError:
            print("Suppressed division by zero!")
            return True
        return False

with ManagedResource():
    print("Working inside context...")

# 2. Generator Context Manager using @contextlib.contextmanager
@contextlib.contextmanager
def timed_block(label: str):
    start = time.perf_counter()
    try:
        yield
    finally:
        elapsed = time.perf_counter() - start
        print(f"[{label}] elapsed: {elapsed:.6f}s")

with timed_block("Data Transformation"):
    sum(x * x for x in range(500_000))

# 3. contextlib.suppress and ExitStack
with contextlib.suppress(FileNotFoundError):
    import os
    os.remove("non_existent_temp_file.tmp")
```

### Example 1: Transactional Atomic File Writer Context Manager
Ensures that if writing fails midway, the original file is never corrupted; changes are written to a temp file and moved atomically on success.

```python
import os
import contextlib
from pathlib import Path

@contextlib.contextmanager
def atomic_file_writer(file_path: Path):
    temp_path = file_path.with_suffix(file_path.suffix + ".tmp")
    try:
        with open(temp_path, "w", encoding="utf-8") as f:
            yield f  # Allow client to write to temp file
        # Replace atomically only if no exceptions were raised
        temp_path.replace(file_path)
        print(f"[ATOMIC WRITE] Successfully committed to {file_path}")
    except Exception as e:
        if temp_path.exists():
            temp_path.unlink()  # Rollback changes by deleting temp file
        print(f"[ATOMIC WRITE ROLLBACK] Write failed due to: {e}. Original file preserved.")
        raise

target = Path("config.json")
try:
    with atomic_file_writer(target) as f:
        f.write('{"status": "OK", "version": 1}')
    print("Content:", target.read_text())
    
    # Test failure rollback
    with atomic_file_writer(target) as f:
        f.write('{"corrupted": true}')
        raise RuntimeError("Disk write failed midway!")
except RuntimeError:
    pass

print("Content after failed write:", target.read_text())  # Still untouched!
target.unlink(missing_ok=True)
```

### Example 2: Multi-Service Health Checker with `ExceptionGroup` (Python 3.11+)
Collect multiple distinct failures across parallel checks and handle them individually with `except*`.

```python
def check_database():
    raise ConnectionError("Database cluster unreachable")

def check_cache():
    raise TimeoutError("Redis cache timed out")

def check_auth_token():
    raise PermissionError("Auth secret expired")

def run_health_checks():
    failures = []
    checks = [check_database, check_cache, check_auth_token]
    for check in checks:
        try:
            check()
        except Exception as err:
            failures.append(err)
    if failures:
        raise ExceptionGroup("Multiple system health checks failed", failures)

try:
    run_health_checks()
except* ConnectionError as eg_conn:
    print("[HANDLED CONNECTION ERROR]", eg_conn.exceptions)
except* TimeoutError as eg_time:
    print("[HANDLED TIMEOUT ERROR]", eg_time.exceptions)
except* PermissionError as eg_perm:
    print("[HANDLED AUTH ERROR]", eg_perm.exceptions)
```

### Example 3: Banking Security Shield with Explicit Chaining
Wrap internal database exceptions into high-level domain exceptions while preserving trace context.

```python
class BankingServiceError(Exception):
    # Domain-level exception
    pass

class DatabaseDriverError(Exception):
    # Internal driver error
    pass

def execute_sql_transfer(amount):
    raise DatabaseDriverError("Deadlock detected in row 409")

def transfer_funds(from_acc: str, to_acc: str, amount: float):
    try:
        execute_sql_transfer(amount)
    except DatabaseDriverError as db_err:
        # Explicitly chain with 'from' to preserve underlying cause
        raise BankingServiceError(f"Failed to transfer ${amount:.2f} from {from_acc} to {to_acc}") from db_err

try:
    transfer_funds("ACC-1", "ACC-2", 500.0)
except BankingServiceError as bse:
    print(f"[SHIELDED ERROR]: {bse}")
    print(f"  Underlying cause was: {bse.__cause__}")
```
