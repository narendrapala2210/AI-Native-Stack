## 1. Conceptual Deep-Dive: C Struct Alignment & Packing

When interacting with native system libraries, network hardware, filesystems, or binary file formats (e.g. PNG, WAV, ZIP), data is represented as packed binary structs rather than JSON or text.

The `struct` module translates between Python values and C structs represented as Python `bytes`:
- **Format Characters**: Specify numeric type, bit width, and sign (e.g. `i` for 4-byte integer, `f` for 4-byte float).
- **Byte Order & Endianness**: Controls endianness representation:
  - `>`: Big-endian (Network standard order).
  - `<`: Little-endian (Standard x86 / ARM CPU architecture).
  - `=`: Native byte order with standard alignment.
  - `!`: Network endianness (same as `>`).

```
Struct Format "!H I f" (Total 10 Bytes):
+--------------------+-------------------------+-------------------------+
|  2 Bytes: Unsigned |  4 Bytes: Unsigned Int  |  4 Bytes: IEEE-754      |
|  Short (Opcode)    |  (Sequence ID)          |  Single-Precision Float |
+--------------------+-------------------------+-------------------------+
```

## 2. Common Struct Format Specifiers

| Specifier | C Type | Python Type | Standard Size |
|---|---|---|---|
| `b` / `B` | `signed char` / `unsigned char` | `int` | 1 byte |
| `h` / `H` | `short` / `unsigned short` | `int` | 2 bytes |
| `i` / `I` | `int` / `unsigned int` | `int` | 4 bytes |
| `q` / `Q` | `long long` / `unsigned long long` | `int` | 8 bytes |
| `f` / `d` | `float` / `double` | `float` | 4 bytes / 8 bytes |
| `?` | `_Bool` | `bool` | 1 byte |
| `s` | `char[]` (e.g. `10s` for 10-byte string) | `bytes` | Variable |

## 3. Practical Code Examples with Step-by-Step Explanations

### Example 1: Packing & Unpacking a Custom Binary Network Header
Pack a fixed binary header containing opcode, sequence ID, and timestamp.

```python
import struct
import time

# Format: Network Big-Endian (!)
# H = unsigned short (2 bytes), I = unsigned int (4 bytes), d = double (8 bytes)
HEADER_FORMAT = "!H I d"
HEADER_SIZE = struct.calcsize(HEADER_FORMAT)
print(f"Computed struct size: {HEADER_SIZE} bytes")

opcode = 0x0102      # 2 bytes
sequence_id = 42940  # 4 bytes
timestamp = time.time()  # 8 bytes

# Pack values into binary bytes
packed_bytes = struct.pack(HEADER_FORMAT, opcode, sequence_id, timestamp)
print(f"Packed binary payload ({len(packed_bytes)} bytes): {packed_bytes.hex()}")

# Unpack back to Python types
unpacked_opcode, unpacked_seq, unpacked_time = struct.unpack(HEADER_FORMAT, packed_bytes)
print(f"Unpacked: Opcode=0x{unpacked_opcode:04X}, Seq={unpacked_seq}, Time={unpacked_time:.2f}")
```

#### Step-by-Step Explanation:
1. `struct.calcsize("!H I d")` determines the exact byte count required for the format (2 + 4 + 8 = 14 bytes).
2. `struct.pack()` encodes integers and floating-point values into network byte order (`!`).
3. `struct.unpack()` reverses the transformation, returning native Python numeric types with bit-level fidelity.

#### Expected Output:
```text
Computed struct size: 14 bytes
Packed binary payload (14 bytes): 01020000a7bc...
Unpacked: Opcode=0x0102, Seq=42940, Time=...
```

### Example 2: In-Place Unpacking with `unpack_from` and `memoryview`
Zero-copy parsing across large binary buffers.

```python
import struct

# Buffer containing multiple packed telemetry points
# Format: 4-byte int (Sensor ID), 4-byte float (Value)
POINT_FORMAT = "<If"
POINT_SIZE = struct.calcsize(POINT_FORMAT)

# Simulate 3 data points packed back-to-back
raw_buffer = bytearray()
data_to_pack = [(101, 23.5), (102, 45.2), (103, -12.8)]
for sensor_id, val in data_to_pack:
    raw_buffer.extend(struct.pack(POINT_FORMAT, sensor_id, val))

print(f"Total buffer length: {len(raw_buffer)} bytes")

# Parse in-place using unpack_from without slicing or copying memory
offset = 0
while offset < len(raw_buffer):
    sensor_id, val = struct.unpack_from(POINT_FORMAT, raw_buffer, offset)
    print(f"  Offset {offset:2d}: Sensor {sensor_id} -> {val:.2f}°C")
    offset += POINT_SIZE
```

#### Step-by-Step Explanation:
1. Slicing bytearrays (`raw_buffer[start:end]`) creates new memory copies on each slice.
2. `struct.unpack_from()` reads data directly from an existing buffer at a specified byte `offset`.
3. This zero-copy approach maintains high throughput when streaming large binary telemetry files.

#### Expected Output:
```text
Total buffer length: 24 bytes
  Offset  0: Sensor 101 -> 23.50°C
  Offset  8: Sensor 102 -> 45.20°C
  Offset 16: Sensor 103 -> -12.80°C
```

### Example 3: Parsing a WAV Audio File Header
Read real-world RIFF/WAV audio binary metadata headers.

```python
import struct

def parse_wav_header(header_bytes: bytes) -> dict:
    if len(header_bytes) < 44:
        raise ValueError("Header must be at least 44 bytes")

    # RIFF chunk descriptor: 4s I 4s
    riff_tag, file_size, wave_tag = struct.unpack("<4s I 4s", header_bytes[0:12])
    
    # fmt subchunk: 4s I H H I I H H
    fmt_tag, subchunk1_size, audio_format, num_channels, sample_rate, byte_rate, block_align, bits_per_sample = struct.unpack(
        "<4s I H H I I H H", header_bytes[12:36]
    )

    return {
        "riff_tag": riff_tag.decode("ascii"),
        "wave_tag": wave_tag.decode("ascii"),
        "channels": num_channels,
        "sample_rate": sample_rate,
        "bits_per_sample": bits_per_sample,
    }

# Synthetic 44-byte WAV header
fake_header = (
    struct.pack("<4s I 4s", b"RIFF", 36 + 1000, b"WAVE") +
    struct.pack("<4s I H H I I H H", b"fmt ", 16, 1, 2, 44100, 176400, 4, 16) +
    struct.pack("<4s I", b"data", 1000)
)

metadata = parse_wav_header(fake_header)
print("Parsed WAV Header Metadata:")
for k, v in metadata.items():
    print(f"  {k}: {v}")
```

#### Step-by-Step Explanation:
1. Canonical WAV headers use Little-Endian `<` byte ordering.
2. `struct.unpack` decomposes the raw bytes into audio channels, sample rate, and bit depth.
3. This pattern powers format decoders for audio, video, image, and network protocol packets.

#### Expected Output:
```text
Parsed WAV Header Metadata:
  riff_tag: RIFF
  wave_tag: WAVE
  channels: 2
  sample_rate: 44100
  bits_per_sample: 16
```

## 4. Key Takeaways & Best Practices

1. Always specify endianness explicitly (e.g. `>` or `<`); omitting it defaults to native alignment with compiler padding.
2. Use `struct.Struct(fmt)` instances to precompile format strings when packing or unpacking in tight loops.
3. Use `unpack_from` combined with `memoryview` or `bytearray` to parse incoming binary streams without memory allocations.
