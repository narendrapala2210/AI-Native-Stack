# 01. Classes, Objects & The `__init__` Constructor

## 📖 Concept Overview
Object-Oriented Programming (OOP) models software systems around real-world entities that bundle **state (attributes)** and **behavior (methods)** together into modular objects.

### 1. Classes vs Objects
- A **Class** is a blueprint, prototype, or schema that defines what attributes and methods its instances will possess.
- An **Object (Instance)** is a concrete manifestation created from that blueprint residing at a specific memory address.

```python
class Mobile:
    pass

phone1 = Mobile()
print(type(phone1))  # <class '__main__.Mobile'>
print(phone1)        # <__main__.Mobile object at 0x0000018...>
```

---

### 2. The `__init__()` Constructor & `self`
The **`__init__()`** method is the initialization hook called automatically whenever a new instance is instantiated.
- **`self`**: A reference to the newly created instance object currently being initialized. CPython passes `self` automatically as the first argument when an instance method is called.
- Assigning to `self.attribute_name = value` attaches attributes directly to that specific instance's namespace (`__dict__`).

```python
class Mobile:
    def __init__(self, model, price):
        self.model = model    # Instance attribute
        self.price = price    # Instance attribute

phone = Mobile("iPhone 17 Pro", 120000)
print(phone.model)  # iPhone 17 Pro
print(phone.price)  # 120000
```

---

## 📋 Summary & OOP Anatomy Reference

```text
    class ClassName:
        def __init__(self, param1, param2):
            self.param1 = param1  # Binds attribute to instance object
            self.param2 = param2
            
    # Instantiation:
    obj = ClassName("arg1", "arg2")  # Calls __init__(obj, "arg1", "arg2")
```

## 🛠️ Practical Hands-On & Real-World Examples

### Example 1: Bank Account Entity with Balance State
Implement a bank account object that maintains an independent balance, validates deposits, and handles withdrawals.

```python
class BankAccount:
    def __init__(self, account_holder: str, initial_deposit: float = 0.0):
        self.holder = account_holder
        self.balance = max(0.0, initial_deposit)
        print(f"Account created for '{self.holder}' with initial deposit: ${self.balance:.2f}")

    def deposit(self, amount: float):
        if amount > 0:
            self.balance += amount
            print(f"Deposited ${amount:.2f}. New Balance: ${self.balance:.2f}")
        else:
            print("[ERROR] Deposit amount must be positive.")

    def withdraw(self, amount: float) -> bool:
        if amount <= 0:
            print("[ERROR] Withdrawal amount must be positive.")
            return False
        if amount > self.balance:
            print(f"[FAILED] Insufficient funds: requested ${amount:.2f}, balance is ${self.balance:.2f}")
            return False
        self.balance -= amount
        print(f"Withdrew ${amount:.2f}. Remaining Balance: ${self.balance:.2f}")
        return True

acc1 = BankAccount("Suresh Kumar", 500.0)
acc1.deposit(200.0)
acc1.withdraw(600.0)
acc1.withdraw(200.0)  # Should fail
```

**Step-by-Step Explanation**:
1. `__init__` sets the initial balance and associates it with `self.holder`.
2. Methods `deposit` and `withdraw` mutate `self.balance` safely.

**Expected Console Output**:
```text
Account created for 'Suresh Kumar' with initial deposit: $500.00
Deposited $200.00. New Balance: $700.00
Withdrew $600.00. Remaining Balance: $100.00
[FAILED] Insufficient funds: requested $200.00, balance is $100.00
```

### Example 2: Instance Memory Namespace Inspection (`__dict__`)
Inspect how Python internally stores instance attributes inside the object's `__dict__` hash table.

```python
class ServerNode:
    def __init__(self, hostname: str, ip_address: str, cpu_cores: int):
        self.hostname = hostname
        self.ip = ip_address
        self.cores = cpu_cores

node_1 = ServerNode("worker-us-01", "10.0.1.15", 8)
node_2 = ServerNode("worker-eu-01", "10.0.2.20", 16)

print("=== Node 1 Internal Namespace (__dict__) ===")
print(node_1.__dict__)

# Dynamically attach an attribute to node_1 only:
node_1.has_gpu = True

print("\n=== After Dynamic Attribute Attachment ===")
print("Node 1 has_gpu:", getattr(node_1, "has_gpu", False))
print("Node 2 has_gpu:", getattr(node_2, "has_gpu", False))
```

**Step-by-Step Explanation**:
1. `node_1.__dict__` reveals that attributes are stored in a standard Python dictionary attached to the instance.
2. Dynamically assigning `node_1.has_gpu = True` updates only `node_1`'s dictionary, leaving `node_2` unaffected.

**Expected Console Output**:
```text
=== Node 1 Internal Namespace (__dict__) ===
{'hostname': 'worker-us-01', 'ip': '10.0.1.15', 'cores': 8}

=== After Dynamic Attribute Attachment ===
Node 1 has_gpu: True
Node 2 has_gpu: False
```

### Example 3: IoT Smart Light Device Controller with State Machine
Model a smart light bulb supporting power states, brightness levels, and color temperatures.

```python
class SmartLightBulb:
    def __init__(self, device_id: str, location: str):
        self.device_id = device_id
        self.location = location
        self.is_powered = False
        self.brightness_pct = 100  # 1 to 100
        self.kelvin = 2700         # Warm white

    def toggle_power(self):
        self.is_powered = not self.is_powered
        state = "ON" if self.is_powered else "OFF"
        print(f"[{self.location}] Light {self.device_id} turned {state}.")

    def set_brightness(self, level: int):
        if not self.is_powered:
            print(f"[REJECTED] Cannot adjust brightness: light in {self.location} is powered off.")
            return
        self.brightness_pct = max(1, min(100, level))
        print(f"[{self.location}] Brightness set to {self.brightness_pct}%.")

living_room_light = SmartLightBulb("LGT-001", "Living Room")
living_room_light.set_brightness(50)  # Fails: powered off
living_room_light.toggle_power()
living_room_light.set_brightness(75)
```

**Step-by-Step Explanation**:
1. Encapsulates device state (`is_powered`, `brightness_pct`, `kelvin`).
2. Guards brightness adjustment when the light is powered off.

**Expected Console Output**:
```text
[REJECTED] Cannot adjust brightness: light in Living Room is powered off.
[Living Room] Light LGT-001 turned ON.
[Living Room] Brightness set to 75%.
```
