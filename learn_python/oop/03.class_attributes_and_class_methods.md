# 03. Class Attributes & Class Methods (`@classmethod`)

## 📖 Concept Overview
Not all data belongs exclusively to individual instances:
- **Class Attributes**: Variables defined directly within the class body (outside methods). They are **shared by all instances** of the class.
- **Class Methods (`@classmethod`)**: Methods decorated with `@classmethod` that receive the **class itself (`cls`)** as the first argument instead of `self`.

---

### 1. Class Attributes vs Instance Attributes
```python
class Employee:
    company_name = "CloudTech"  # Class attribute (shared)
    
    def __init__(self, name):
        self.name = name        # Instance attribute (unique)
```
Modifying `Employee.company_name` updates the value for all instances that haven't shadowed it.

---

### 2. Class Methods as Alternative Constructors
The primary use of `@classmethod` is creating factory methods that instantiate objects from different input formats (e.g. parsing JSON strings, CSV rows, or timestamps):
```python
class Date:
    def __init__(self, year, month, day):
        self.year = year
        self.month = month
        self.day = day

    @classmethod
    def from_string(cls, date_str):
        # Parses "2026-09-14"
        y, m, d = map(int, date_str.split("-"))
        return cls(y, m, d)  # Instantiates new object!
```

---

## 📋 Summary & Reference Table

| Feature | Instance Method | Class Method (`@classmethod`) |
| :--- | :--- | :--- |
| **First Parameter** | `self` (points to instance) | `cls` (points to class) |
| **Decorator** | None | `@classmethod` |
| **Access To** | Can access instance & class state | Can access only class state |
| **Primary Use** | Standard entity behaviors | Alternative constructors, class registries |

## 🛠️ Practical Hands-On & Real-World Examples

### Example 1: Alternative Constructors for Diverse Formats (`cls`)
Implement multiple factory constructors to create user objects from JSON dictionaries and CSV strings.

```python
class UserProfile:
    def __init__(self, user_id: int, username: str, email: str):
        self.user_id = user_id
        self.username = username
        self.email = email

    @classmethod
    def from_csv_row(cls, csv_line: str):
        # Format: '101,alex99,alex@cloud.io'
        uid, uname, uemail = csv_line.strip().split(",")
        return cls(int(uid), uname.strip(), uemail.strip())

    @classmethod
    def from_dict(cls, data: dict):
        return cls(int(data["id"]), data["user"], data["email"])

    def display(self):
        print(f"User #{self.user_id}: {self.username} ({self.email})")

# Instantiations:
u1 = UserProfile(1, "standard_user", "std@dev.io")
u2 = UserProfile.from_csv_row("102, csv_user, csv@dev.io")
u3 = UserProfile.from_dict({"id": 103, "user": "json_user", "email": "json@dev.io"})

u1.display()
u2.display()
u3.display()
```

**Step-by-Step Explanation**:
1. `cls(...)` dynamically calls `__init__`, enabling subclass inheritance safety.
2. Simplifies ingestion from varied data sources.

**Expected Console Output**:
```text
User #1: standard_user (std@dev.io)
User #102: csv_user (csv@dev.io)
User #103: json_user (json@dev.io)
```

### Example 2: Shared Global Counter & Instance Registry
Track all currently active instances across an entire application using class attributes and class methods.

```python
class DatabaseConnection:
    active_connections = 0  # Class attribute shared across all instances
    connection_pool: list[str] = []

    def __init__(self, connection_id: str):
        self.conn_id = connection_id
        DatabaseConnection.active_connections += 1
        DatabaseConnection.connection_pool.append(connection_id)
        print(f"Opened connection: {self.conn_id}")

    def close(self):
        DatabaseConnection.active_connections -= 1
        DatabaseConnection.connection_pool.remove(self.conn_id)
        print(f"Closed connection: {self.conn_id}")

    @classmethod
    def get_pool_status(cls):
        print(f"Active Connections: {cls.active_connections}")
        print(f"Connection IDs: {cls.connection_pool}")

conn_a = DatabaseConnection("CONN-01")
conn_b = DatabaseConnection("CONN-02")
DatabaseConnection.get_pool_status()
conn_a.close()
DatabaseConnection.get_pool_status()
```

**Step-by-Step Explanation**:
1. `active_connections` increments whenever any new connection is instantiated.
2. `get_pool_status` reads class-level metrics via `cls`.

**Expected Console Output**:
```text
Opened connection: CONN-01
Opened connection: CONN-02
Active Connections: 2
Connection IDs: ['CONN-01', 'CONN-02']
Closed connection: CONN-01
Active Connections: 1
Connection IDs: ['CONN-02']
```

### Example 3: Subclassing & Polymorphic Factory Construction
Demonstrate why using `cls(...)` instead of hardcoding `ClassName(...)` inside `@classmethod` is essential for subclasses.

```python
class BaseWidget:
    def __init__(self, name: str):
        self.name = name

    @classmethod
    def create_default(cls):
        # Using cls() creates an instance of whichever class called it!
        return cls("Default_" + cls.__name__)

class ButtonWidget(BaseWidget):
    pass

class SliderWidget(BaseWidget):
    pass

b = ButtonWidget.create_default()
s = SliderWidget.create_default()

print("Instance b type:", type(b).__name__, "| Name:", b.name)
print("Instance s type:", type(s).__name__, "| Name:", s.name)
```

**Step-by-Step Explanation**:
1. `ButtonWidget.create_default()` receives `cls = ButtonWidget`.
2. Automatically instantiates the proper child class without code duplication.

**Expected Console Output**:
```text
Instance b type: ButtonWidget | Name: Default_ButtonWidget
Instance s type: SliderWidget | Name: Default_SliderWidget
```
