# 03. Booleans & Truth Value Testing

## 📖 Concept Overview
In Python, **Booleans (`bool`)** represent one of two binary states: **`True`** or **`False`**.

### 1. Booleans as Subclasses of Integers
In Python, `bool` is explicitly a subclass of `int`:
```python
print(issubclass(bool, int))  # True
print(int(True))               # 1
print(int(False))              # 0
print(True + True + False)     # 2
```
Because `True == 1` and `False == 0`, booleans can participate in arithmetic expressions, though this is discouraged in clean code unless tallying flags.

---

### 2. Truth Value Testing (Truthiness)
Any Python object can be evaluated in a boolean context (such as an `if` statement or `while` loop).

#### Values that evaluate to `False` (Falsy values):
- Constants defined to be false: `None` and `False`.
- Zero of any numeric type: `0`, `0.0`, `0j`, `Decimal(0)`, `Fraction(0, 1)`.
- Empty sequences and collections: `""` (empty str), `()` (empty tuple), `[]` (empty list), `{}` (empty dict), `set()` (empty set), `range(0)`.
- Objects of user-defined classes that define a `__bool__()` or `__len__()` method returning `0` or `False`.

#### Values that evaluate to `True` (Truthy values):
- **All other values** are considered truthy! Any non-empty string (`"Hello"`, `"False"`, `"0"`), non-zero number (`-1`, `3.14`), or populated collection evaluates to `True`.

---

## 📋 Summary & Reference Table

| Value / Expression | Truth Value | Reason |
| :--- | :--- | :--- |
| `bool(0)` / `bool(0.0)` | `False` | Numeric zero. |
| `bool("")` | `False` | Empty string sequence. |
| `bool("False")` / `bool("0")` | **`True`** | Non-empty string (length > 0)! |
| `bool([])` / `bool({})` | `False` | Empty list or dictionary. |
| `bool(None)` | `False` | `None` singleton evaluates to false. |
| `bool([0])` | **`True`** | Non-empty list containing one element (even though element itself is 0). |

## 🛠️ Practical Hands-On & Real-World Examples

### Example 1: Streamlined Pythonic Collection Verification
Demonstrate how Pythonic truthiness eliminates verbose collection length checks.

```python
def notify_pending_tasks(task_queue: list[str]):
    # Non-Pythonic (redundant): if len(task_queue) > 0:
    # Pythonic truthiness evaluation:
    if task_queue:
        print(f"Alert: {len(task_queue)} task(s) awaiting processing:")
        for idx, task in enumerate(task_queue, start=1):
            print(f"  {idx}. {task}")
    else:
        print("Queue is empty. System is idle.")

notify_pending_tasks(["Database Backup", "Index Refresh"])
notify_pending_tasks([])
```

**Step-by-Step Explanation**:
1. In `if task_queue:`, Python implicitly evaluates `bool(task_queue)`.
2. If `task_queue` has items, it evaluates to `True`; if empty, to `False`.
3. Eliminates unnecessary calls to `len(task_queue) > 0`.

**Expected Console Output**:
```text
Alert: 2 task(s) awaiting processing:
  1. Database Backup
  2. Index Refresh
Queue is empty. System is idle.
```

### Example 2: Short-Circuit Fallback Value Assignment
Use short-circuit evaluation of `or` and `and` operators to assign default fallback values cleanly.

```python
def resolve_user_display_name(raw_name: str | None, username: str) -> str:
    # If raw_name is None or empty string (""), fallback to username.
    # If username is also empty, fallback to "Anonymous Guest".
    display_name = (raw_name and raw_name.strip()) or username.strip() or "Anonymous Guest"
    return display_name

print("Case 1:", resolve_user_display_name("  Alex Smith  ", "asmith99"))
print("Case 2:", resolve_user_display_name("", "coder_raj"))
print("Case 3:", resolve_user_display_name(None, "sarah_dev"))
print("Case 4:", resolve_user_display_name(None, "   "))
```

**Step-by-Step Explanation**:
1. `raw_name and raw_name.strip()`: If `raw_name` is `None`, evaluation short-circuits to `None` without crashing on `.strip()`.
2. If falsy (empty or whitespace), the `or` operator moves to the next operand.
3. Provides a resilient multi-tier fallback chain.

**Expected Console Output**:
```text
Case 1: Alex Smith
Case 2: coder_raj
Case 3: sarah_dev
Case 4: Anonymous Guest
```

### Example 3: Custom Domain Object Truthiness (`__bool__` vs `__len__`)
Implement a shopping cart class that defines its own truthiness semantics based on total item count and minimum spending requirements.

```python
class ShoppingCart:
    def __init__(self, owner: str):
        self.owner = owner
        self.items: dict[str, float] = {}

    def add_item(self, item_name: str, price: float):
        self.items[item_name] = price

    def __bool__(self) -> bool:
        # Cart is considered 'active/truthy' only if it contains items AND total > $20.0
        total_value = sum(self.items.values())
        return len(self.items) > 0 and total_value >= 20.0

cart = ShoppingCart("Priya")
print(f"1. Fresh Cart truthiness: {bool(cart)}")

cart.add_item("Coffee Mug", 12.50)
print(f"2. Cart with $12.50 item truthiness: {bool(cart)} (below $20 minimum)")

cart.add_item("Artisan Notebook", 15.00)
print(f"3. Cart with $27.50 total truthiness: {bool(cart)} (meets criteria!)")

if cart:
    print("-> Checkout initiated: Cart meets checkout criteria!")
else:
    print("-> Checkout rejected: Minimum order value not met.")
```

**Step-by-Step Explanation**:
1. Python checks for `__bool__()` when evaluating an object in a boolean context.
2. If `__bool__()` is not defined, Python falls back to `__len__()`.
3. Allows domain entities to encapsulate their own business validation logic.

**Expected Console Output**:
```text
1. Fresh Cart truthiness: False
2. Cart with $12.50 item truthiness: False (below $20 minimum)
3. Cart with $27.50 total truthiness: True (meets criteria!)
-> Checkout initiated: Cart meets checkout criteria!
```
