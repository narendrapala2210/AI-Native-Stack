## 1. Conceptual Deep-Dive: Row-Oriented vs. Columnar Data

Modern data engineering and analytical queries rely heavily on columnar memory formats (such as Apache Arrow, Polars, and Pandas):
1. **Row-Oriented (e.g. CSV, SQLite, JSON)**:
   - Records are stored consecutively: `[ID1, Name1, Age1, ID2, Name2, Age2]`.
   - Ideal for OLTP (Online Transaction Processing): fast single-row insertion and lookup.
   - Inefficient for analytics: calculating average age requires reading all fields into memory and skipping unwanted bytes.
2. **Column-Oriented (e.g. Parquet, Arrow, Polars)**:
   - Columns are stored consecutively: `[ID1, ID2]`, `[Name1, Name2]`, `[Age1, Age2]`.
   - Ideal for OLAP (Online Analytical Processing): queries read only the required columns from disk into memory.
   - Columnar data compresses significantly better because adjacent values share the same data type.

```
Row-Oriented Layout (OLTP):
[ Row 1: ID, Name, Age ] -> [ Row 2: ID, Name, Age ] -> [ Row 3: ID, Name, Age ]

Column-Oriented Layout (OLAP):
[ IDs:   1,     2,     3     ]
[ Names: Alice, Bob,   Charlie ]
[ Ages:  25,    30,    35    ]  <--- Aggregations read ONLY this contiguous array!
```

## 2. Technology Comparison: Pandas vs. Polars vs. SQLite

| Dimension | Pandas | Polars | SQLite |
|---|---|---|---|
| Engine Language | Python & C | Rust (Apache Arrow native) | C |
| Execution Model | Eager, single-threaded default | Lazy query optimizer & multithreaded | Single-writer disk engine |
| Memory Overhead | 2x - 5x dataset size | Minimal (zero-copy Arrow views) | On-disk / low RAM footprint |
| Best For | Rapid exploratory data analysis | Enterprise ETL & billion-row data | Embedded relational storage |

## 3. Practical Code Examples with Step-by-Step Explanations

### Example 1: Pure Python Columnar Storage Structure
Build a minimal columnar data container to demonstrate projection and aggregation efficiency.

```python
class ColumnarTable:
    def __init__(self):
        self._columns: dict[str, list] = {}

    def add_column(self, name: str, data: list):
        self._columns[name] = data

    def select(self, *col_names: str) -> dict[str, list]:
        """Column projection: zero row scanning required."""
        return {name: self._columns[name] for name in col_names if name in self._columns}

    def mean(self, col_name: str) -> float:
        """Aggregation touches only the target column."""
        values = self._columns[col_name]
        return sum(values) / len(values) if values else 0.0

table = ColumnarTable()
table.add_column("user_id", [101, 102, 103, 104])
table.add_column("age", [22, 38, 29, 45])
table.add_column("country", ["US", "DE", "IN", "JP"])

# Average age calculation ignores user_id and country entirely
avg_age = table.mean("age")
print(f"Calculated average age: {avg_age:.1f}")

# Projected subset
subset = table.select("user_id", "country")
print(f"Projected columns: {subset}")
```

#### Step-by-Step Explanation:
1. `_columns` stores distinct lists keyed by column name rather than lists of row dictionaries.
2. Computing `table.mean("age")` reads only the numeric age array without parsing irrelevant string columns.
3. This mirrors how analytical engines execute projection and aggregation queries at scale.

#### Expected Output:
```text
Calculated average age: 33.5
Projected columns: {'user_id': [101, 102, 103, 104], 'country': ['US', 'DE', 'IN', 'JP']}
```

### Example 2: Simulating Parquet Column Chunk Filtering (Predicate Pushdown)
Demonstrate predicate pushdown to filter chunks before reading data.

```python
# Simulating Predicate Pushdown metadata
chunks = [
    {"chunk_id": 0, "min_age": 18, "max_age": 29, "data": [19, 24, 28]},
    {"chunk_id": 1, "min_age": 30, "max_age": 45, "data": [32, 41, 44]},
    {"chunk_id": 2, "min_age": 46, "max_age": 65, "data": [50, 58, 62]},
]

def query_ages_greater_than(threshold: int):
    results = []
    skipped_chunks = 0
    
    for chunk in chunks:
        # Predicate pushdown: skip chunk if max_age is below threshold
        if chunk["max_age"] < threshold:
            skipped_chunks += 1
            continue
        # Read and filter records in matching chunks
        results.extend([x for x in chunk["data"] if x >= threshold])
        
    return results, skipped_chunks

matches, skipped = query_ages_greater_than(35)
print(f"Matching ages (>= 35): {matches}")
print(f"Skipped chunks without reading rows: {skipped}")
```

#### Step-by-Step Explanation:
1. Parquet files store minimum and maximum statistics for each column chunk in file metadata headers.
2. When querying `age >= 35`, Chunk 0 (`max_age=29`) is skipped entirely, eliminating disk I/O.
3. This optimization—**predicate pushdown**—is central to high-performance data lake queries.

#### Expected Output:
```text
Matching ages (>= 35): [41, 44, 50, 58, 62]
Skipped chunks without reading rows: 1
```

### Example 3: Parsing Data into Typed Records
Demonstrate transforming semi-structured row records into a columnar mapping for fast analysis.

```python
raw_records = [
    {"timestamp": "2026-09-01", "cpu_pct": 34.2, "mem_mb": 1024},
    {"timestamp": "2026-09-02", "cpu_pct": 78.5, "mem_mb": 2048},
    {"timestamp": "2026-09-03", "cpu_pct": 12.1, "mem_mb": 1024},
]

def rows_to_columns(records: list[dict]) -> dict[str, list]:
    columns = {key: [] for key in records[0].keys()}
    for row in records:
        for key, val in row.items():
            columns[key].append(val)
    return columns

col_data = rows_to_columns(raw_records)
print("Transformed Columnar Layout:")
for col_name, values in col_data.items():
    print(f"  {col_name:10} -> {values}")
```

#### Step-by-Step Explanation:
1. Converts arbitrary row-wise payloads into vectorized columns.
2. Transformed columns can be passed directly into NumPy, Polars, or Arrow tables for analytical processing.

#### Expected Output:
```text
Transformed Columnar Layout:
  timestamp  -> ['2026-09-01', '2026-09-02', '2026-09-03']
  cpu_pct    -> [34.2, 78.5, 12.1]
  mem_mb     -> [1024, 2048, 1024]
```

## 4. Key Takeaways & Best Practices

1. Use columnar formats (Parquet, Arrow) for analytical queries and large-scale data aggregation.
2. Leverage predicate pushdown to filter out data chunks at the metadata level before reading records into memory.
3. For enterprise data processing in Python, evaluate modern engines like Polars or DuckDB alongside Pandas.
