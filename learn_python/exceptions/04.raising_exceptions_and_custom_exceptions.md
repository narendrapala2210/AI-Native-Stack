# 04. Raising Exceptions & Custom Exception Classes

## 📖 Concept Overview
In Python, programs can explicitly trigger exceptions using the **`raise`** statement, and define domain-specific error types by subclassing `Exception`.

---

### 1. Raising Exceptions Manually (`raise`)
```python
def set_age(age):
    if age < 0:
        raise ValueError("Age cannot be negative!")
```

---

### 2. Custom Exception Classes
Standard exceptions like `ValueError` or `TypeError` are often too generic to represent specific business domain failures. By subclassing `Exception`, you create clear, descriptive error hierarchies:
```python
class BankingError(Exception):
    # Base exception for all banking operations.
    pass

class InsufficientFundsError(BankingError):
    def __init__(self, current_balance, amount_requested):
        super().__init__(f"Cannot withdraw ${amount_requested:.2f}; balance is ${current_balance:.2f}.")
        self.balance = current_balance
        self.requested = amount_requested
```

## 🛠️ Practical Hands-On & Real-World Examples

### Example 1: Banking Domain Exception Hierarchy
Implement a financial domain error hierarchy that provides callers with structured transaction metadata.

```python
class BankingException(Exception):
    # Base exception for banking domain.
    pass

class AccountFrozenError(BankingException):
    def __init__(self, account_id: str):
        super().__init__(f"Account '{account_id}' is frozen due to compliance hold.")
        self.account_id = account_id

class InsufficientFundsError(BankingException):
    def __init__(self, account_id: str, balance: float, withdraw_amount: float):
        deficit = withdraw_amount - balance
        super().__init__(f"Insufficient funds in '{account_id}'. Deficit: ${deficit:.2f}")
        self.deficit = deficit

def process_bank_withdrawal(account: dict, amount: float):
    if account.get("is_frozen", False):
        raise AccountFrozenError(account["id"])
    if amount > account["balance"]:
        raise InsufficientFundsError(account["id"], account["balance"], amount)
        
    account["balance"] -= amount
    print(f"[SUCCESS] Withdrew ${amount:.2f}. New Balance: ${account['balance']:.2f}")

user_acc = {"id": "ACC-9921", "balance": 150.0, "is_frozen": False}

try:
    process_bank_withdrawal(user_acc, 200.0)
except InsufficientFundsError as err:
    print(f"Transaction Denied: {err}")
    print(f"Please deposit at least ${err.deficit:.2f} to proceed.")
```

**Step-by-Step Explanation**:
1. `InsufficientFundsError` attaches the exact `deficit` amount as an instance attribute.
2. Callers can inspect `err.deficit` to provide intelligent user guidance.

**Expected Console Output**:
```text
Transaction Denied: Insufficient funds in 'ACC-9921'. Deficit: $50.00
Please deposit at least $50.00 to proceed.
```

### Example 2: Re-Raising Exceptions (`raise` without arguments)
Log an error during intermediate processing and re-raise it to let higher-level services handle the ultimate failure.

```python
def write_to_secure_vault(payload: str):
    try:
        if "MALWARE" in payload:
            raise SecurityError("Malicious payload detected!")
        print(f"Payload '{payload}' safely persisted.")
    except Exception as exc:
        print(f"[LOCAL LOG] Logged security threat to local audit journal: {exc}")
        # Re-raise the current active exception without modifying its traceback!
        raise

class SecurityError(Exception):
    pass

try:
    write_to_secure_vault("VIRUS_MALWARE_BYTE")
except SecurityError:
    print("[GATEWAY ALERT] High-level security alert broadcasted to admin dashboard!")
```

**Step-by-Step Explanation**:
1. Inside an `except` block, a bare `raise` re-emits the exact current exception.
2. Allows local telemetry recording while propagating the failure to top-level controllers.

**Expected Console Output**:
```text
[LOCAL LOG] Logged security threat to local audit journal: Malicious payload detected!
[GATEWAY ALERT] High-level security alert broadcasted to admin dashboard!
```

### Example 3: Exception Chaining with `raise ... from ...`
Wrap low-level system errors into high-level domain exceptions while preserving original tracebacks.

```python
class DataIngestionError(Exception):
    pass

def load_user_metrics(raw_json_string: str):
    import json
    try:
        data = json.loads(raw_json_string)
        return data["metrics"]["score"]
    except (json.JSONDecodeError, KeyError) as cause:
        # Chain domain exception to original technical cause!
        raise DataIngestionError("Failed to ingest user telemetry metrics payload.") from cause

try:
    load_user_metrics("{corrupted_json_payload...")
except DataIngestionError as err:
    print(f"Caught Domain Error: {err}")
    print(f"Underlying Root Cause: {type(err.__cause__).__name__} -> {err.__cause__}")
```

**Step-by-Step Explanation**:
1. `raise DataIngestionError(...) from cause` links the high-level business error with the root low-level JSON parser error.
2. Accessible via `err.__cause__` for debugging.

**Expected Console Output**:
```text
Caught Domain Error: Failed to ingest user telemetry metrics payload.
Underlying Root Cause: JSONDecodeError -> Expecting property name enclosed in double quotes: line 1 column 2 (char 1)
```
