# 02. `try-except` Blocks & Catching Multiple Exceptions

## 📖 Concept Overview
The **`try-except`** block provides structured exception handling in Python, allowing programs to gracefully intercept runtime errors rather than crashing.

```python
try:
    # Code that might raise an exception
except SpecificException:
    # Handler code executed if SpecificException occurs
```

---

### 1. Catching Specific Exceptions
Always catch **specific exception types** rather than bare `except:`. Catching generic exceptions masks real bugs (such as typing errors or `KeyboardInterrupt`).

---

### 2. Handling Multiple Exception Types
You can define multiple distinct `except` blocks or catch multiple exception types in a single tuple:
```python
# Option A: Distinct blocks
try:
    process_data()
except ValueError:
    handle_value_error()
except KeyError:
    handle_key_error()

# Option B: Grouped tuple
try:
    process_data()
except (ValueError, KeyError, TypeError) as err:
    print(f"Data error: {err}")
```

## 🛠️ Practical Hands-On & Real-World Examples

### Example 1: Multi-Exception Defensive CSV Line Ingestion
Safely parse and convert tabular data containing potential missing columns, type casting errors, and division errors.

```python
def parse_and_compute_metric(csv_row: str) -> float | None:
    parts = csv_row.split(",")
    try:
        # Could raise IndexError if fewer than 3 columns
        item_name = parts[0].strip()
        revenue   = float(parts[1].strip())  # Could raise ValueError
        users     = int(parts[2].strip())    # Could raise ValueError
        
        # Could raise ZeroDivisionError
        arpu = revenue / users
        print(f"Item: {item_name:<10} | ARPU: ${arpu:.2f}")
        return arpu
        
    except IndexError:
        print(f"[ERROR] Corrupt row (missing columns): '{csv_row}'")
    except ValueError as ve:
        print(f"[ERROR] Non-numeric data encountered: {ve}")
    except ZeroDivisionError:
        print(f"[ERROR] Cannot compute ARPU: users count is 0 for row '{csv_row}'")
        
    return None

parse_and_compute_metric("Product A, 5000.0, 100")
parse_and_compute_metric("Product B, INVALID, 20")
parse_and_compute_metric("Product C, 2500.0, 0")
parse_and_compute_metric("Product D")
```

**Step-by-Step Explanation**:
1. Catches `IndexError`, `ValueError`, and `ZeroDivisionError` individually.
2. Emits precise, actionable error messages for each distinct failure category.

**Expected Console Output**:
```text
Item: Product A  | ARPU: $50.00
[ERROR] Non-numeric data encountered: could not convert string to float: 'INVALID'
[ERROR] Cannot compute ARPU: users count is 0 for row 'Product C, 2500.0, 0'
[ERROR] Corrupt row (missing columns): 'Product D'
```

### Example 2: Grouped Tuple Exception Handling in REST Client
Catch multiple network and serialization exceptions using a single concise tuple handler.

```python
def mock_fetch_api_data(url: str, payload: dict) -> dict:
    try:
        if not url.startswith("https://"):
            raise ValueError("Insecure HTTP protocol not allowed.")
        if "auth_token" not in payload:
            raise KeyError("Missing 'auth_token' in request payload.")
        if not isinstance(payload["auth_token"], str):
            raise TypeError("Authorization token must be a string.")
            
        return {"status": "SUCCESS", "data": "Cluster Telemetry"}
        
    except (ValueError, KeyError, TypeError) as client_err:
        # Grouped tuple handler catches all three client errors!
        print(f"[CLIENT FAULT] {type(client_err).__name__}: {client_err}")
        return {"status": "FAILED", "error": str(client_err)}

mock_fetch_api_data("http://api.internal", {"auth_token": "TOK123"})
mock_fetch_api_data("https://api.internal", {})
mock_fetch_api_data("https://api.internal", {"auth_token": 12345})
mock_fetch_api_data("https://api.internal", {"auth_token": "VALID_TOKEN"})
```

**Step-by-Step Explanation**:
1. `except (ValueError, KeyError, TypeError) as client_err:` collapses 3 redundant error blocks into one.
2. `type(client_err).__name__` retains visibility of the specific underlying error.

**Expected Console Output**:
```text
[CLIENT FAULT] ValueError: Insecure HTTP protocol not allowed.
[CLIENT FAULT] KeyError: 'Missing \'auth_token\' in request payload.'
[CLIENT FAULT] TypeError: Authorization token must be a string.
```

### Example 3: Hierarchical Exception Catching (`LookupError`)
Demonstrate how parent exceptions catch all child derived exceptions (e.g. `LookupError` catches both `IndexError` and `KeyError`).

```python
def lookup_value(container: list | dict, key_or_index: any):
    try:
        val = container[key_or_index]
        print(f"Retrieved: {val}")
    except LookupError as err:
        # LookupError is the base class for both IndexError and KeyError!
        print(f"[LOOKUP FAILED] Caught via base LookupError: {type(err).__name__} -> {err}")

# Test with List (raises IndexError)
lookup_value([10, 20, 30], 99)

# Test with Dict (raises KeyError)
lookup_value({"user": "Bob"}, "missing_key")
```

**Step-by-Step Explanation**:
1. `LookupError` is the standard library parent class of both `IndexError` and `KeyError`.
2. Allows handling container lookup failures polymorphically.

**Expected Console Output**:
```text
[LOOKUP FAILED] Caught via base LookupError: IndexError -> list index out of range
[LOOKUP FAILED] Caught via base LookupError: KeyError -> 'missing_key'
```
