## 1. Conceptual Deep-Dive: Declarative Transformations

Python comprehensions provide a concise, declarative syntax for transforming, filtering, and flattening iterables without explicit `for` loops or calls to `append()`:
1. **List Comprehensions (`[expr for item in iterable if condition]`)**:
   - Compiles down to optimized `LIST_APPEND` bytecode instructions in CPython.
   - Evaluated eagerly in memory, producing a complete `list`.
2. **Set Comprehensions (`{expr for item in iterable if condition}`)**:
   - Generates a deduplicated `set` with $O(1)$ membership checks.
3. **Dictionary Comprehensions (`{k_expr: v_expr for item in iterable if condition}`)**:
   - Constructs a key-value mapping in a single expressive pass.
4. **Generator Expressions (`(expr for item in iterable if condition)`)**:
   - Uses parentheses `(...)` instead of brackets.
   - **Lazy Evaluation**: Does NOT construct a list in memory; instead, produces a generator object yielding items on demand ($O(1)$ memory consumption for millions of items).

## 🛠️ Practical Hands-On & Real-World Examples

### Example 1: Multi-Dimensional Matrix Flattening and Filtering
Flatten a 2D tabular matrix and filter out outliers using nested list comprehensions.

```python
def process_matrix_signals():
    sensor_grid = [
        [12.5, 14.2, 999.0],    # 999.0 is a sensor fault artifact
        [15.1, -1.0, 16.8],     # -1.0 is uncalibrated reading
        [13.9, 14.8, 15.0]
    ]

    # Flatten 2D grid and filter out invalid values (-1.0 and 999.0)
    valid_readings = [
        val
        for row in sensor_grid
        for val in row
        if 0.0 <= val < 100.0
    ]

    print("Filtered & Flattened Readings:", valid_readings)
    print(f"Mean Value: {sum(valid_readings)/len(valid_readings):.2f}")

process_matrix_signals()
```

#### Step-by-Step Explanation:
1. `for row in sensor_grid` iterates outer rows first.
2. `for val in row` iterates elements inside each row.
3. `if 0.0 <= val < 100.0` filters sensor noise prior to insertion.

#### Expected Output:
```text
Filtered & Flattened Readings: [12.5, 14.2, 15.1, 16.8, 13.9, 14.8, 15.0]
Mean Value: 14.61
```

### Example 2: Inverted Index Generation via Dictionary Comprehension
Invert a user-to-permission mapping into a permission-to-users index.

```python
def invert_permission_index():
    user_roles = {
        "alice": ["READ", "WRITE", "DEPLOY"],
        "bob": ["READ"],
        "charlie": ["READ", "WRITE"],
        "diana": ["DEPLOY", "ADMIN"]
    }

    # Extract all unique permissions using set comprehension
    all_permissions = {perm for perms in user_roles.values() for perm in perms}

    # Invert using dictionary comprehension
    inverted_index = {
        perm: [user for user, perms in user_roles.items() if perm in perms]
        for perm in all_permissions
    }

    print("Inverted Permission Mapping:")
    for perm, users in sorted(inverted_index.items()):
        print(f"  {perm:<8} -> {users}")

invert_permission_index()
```

#### Step-by-Step Explanation:
1. Set comprehension `{perm for perms in ...}` isolates distinct capabilities.
2. Dict comprehension `{perm: [...] for perm in ...}` groups users under each capability.

#### Expected Output:
```text
Inverted Permission Mapping:
  ADMIN    -> ['diana']
  DEPLOY   -> ['alice', 'diana']
  READ     -> ['alice', 'bob', 'charlie']
  WRITE    -> ['alice', 'charlie']
```

### Example 3: Memory-Efficient Stream Filtering via Generator Expressions
Calculate sum of squares for 10 million integers using zero memory allocation.

```python
import sys

def benchmark_memory_comprehension():
    N = 1_000_000

    # Generator Expression: Evaluated lazily on-the-fly
    gen = (x ** 2 for x in range(N) if x % 2 == 0)
    
    # List Comprehension: Evaluated eagerly in memory
    lst = [x ** 2 for x in range(1000)]

    print(f"Generator Expression Memory: {sys.getsizeof(gen)} bytes (Stream of 1M items)")
    print(f"List Comprehension Memory   : {sys.getsizeof(lst)} bytes (Only 1,000 items)")

    # Consume first 3 items from generator
    print("First 3 squares from generator:", [next(gen), next(gen), next(gen)])

benchmark_memory_comprehension()
```

#### Step-by-Step Explanation:
1. `gen` allocates a tiny generator iterator struct (~200 bytes) regardless of whether processing 100 items or 1 billion items.
2. `next(gen)` yields values one by one on demand.

#### Expected Output:
```text
Generator Expression Memory: ~200 bytes (Stream of 1M items)
List Comprehension Memory   : ~8856 bytes (Only 1,000 items)
First 3 squares from generator: [0, 4, 16]
```
