## 📖 Concept Overview
Python built-in functions for calculating aggregations across sequences:

---

### 1. Aggregation Functions
- **`len(s)`**: Returns number of items ($O(1)$ on built-ins).
- **`min(iterable[, key, default])`**: Returns lowest element.
- **`max(iterable[, key, default])`**: Returns highest element.
- **`sum(iterable[, start])`**: Sums all numeric items.
- **`sorted(iterable[, key, reverse])`**: Returns a **new sorted list** (unlike `lst.sort()` which sorts in-place).

---

### 2. Truth Value Aggregators: `all()` and `any()`
- **`all(iterable)`**: Returns `True` if **every** element in the iterable is truthy (or if iterable is empty).
- **`any(iterable)`**: Returns `True` if **at least one** element in the iterable is truthy.

```python
flags = [True, True, False]
print(all(flags))  # False
print(any(flags))  # True
```

## 🛠️ Practical Hands-On & Real-World Examples

### Example 1: Form Input Validation Shield using `all()`
Verify that all mandatory customer checkout fields are populated and valid.

```python
def validate_checkout_form(form_data: dict) -> bool:
    mandatory_fields = ["full_name", "email", "shipping_address", "payment_token"]
    
    # Check that all mandatory fields are present and non-empty (truthy)
    all_fields_present = all(bool(form_data.get(f)) for f in mandatory_fields)
    
    # Check that email contains '@'
    email_valid = "@" in form_data.get("email", "")
    
    is_valid = all_fields_present and email_valid
    print(f"Form submission from '{form_data.get('full_name')}': Valid? {is_valid}")
    return is_valid

form_ok = {
    "full_name": "Alice Smith",
    "email": "alice@cloud.io",
    "shipping_address": "123 Tech Way",
    "payment_token": "TOK_884"
}

form_incomplete = {
    "full_name": "Bob Jones",
    "email": "bob@domain.org",
    "shipping_address": "",  # Empty!
    "payment_token": None    # Missing!
}

validate_checkout_form(form_ok)
validate_checkout_form(form_incomplete)
```

#### Step-by-Step Explanation:
1. `all(...)` checks every field condition cleanly without multiple chained `and` conditions.
2. Returns `False` on the first falsy field.

#### Expected Output:
```text
Form submission from 'Alice Smith': Valid? True
Form submission from 'Bob Jones': Valid? False
```

### Example 2: Finding Extremes with Custom Key Extractor in `max()` & `min()`
Find the most expensive product and lowest stock item from an inventory collection.

```python
inventory = [
    {"name": "Monitor",  "price": 349.99, "stock": 4},
    {"name": "Mouse",    "price": 24.99,  "stock": 85},
    {"name": "Keyboard", "price": 89.99,  "stock": 12},
    {"name": "Laptop",   "price": 1299.00,"stock": 2}
]

# Use key parameter with lambda
highest_priced = max(inventory, key=lambda item: item["price"])
lowest_stock   = min(inventory, key=lambda item: item["stock"])

print(f"Highest Priced Item: {highest_priced['name']} (${highest_priced['price']:.2f})")
print(f"Critically Low Stock: {lowest_stock['name']} ({lowest_stock['stock']} units left)")
```

#### Step-by-Step Explanation:
1. `max()` and `min()` accept a `key` function mapping each element to a comparable scalar.
2. Returns the complete dictionary object matching the extreme.

#### Expected Output:
```text
Highest Priced Item: Laptop ($1299.00)
Critically Low Stock: Laptop (2 units left)
```

### Example 3: `sorted()` vs In-Place `list.sort()`
Compare `sorted()` which returns a new list against in-place `list.sort()`.

```python
original_scores = (78, 92, 64, 85, 99)  # Immutable tuple

# 1. sorted() works on ANY iterable (including tuples) and returns a new list
sorted_scores = sorted(original_scores, reverse=True)
print(f"Original Tuple Untouched: {original_scores}")
print(f"New Sorted List Returned: {sorted_scores}")

# 2. list.sort() works ONLY on lists in-place
mutable_scores = list(original_scores)
mutable_scores.sort()
print(f"In-Place Sorted List    : {mutable_scores}")
```

#### Step-by-Step Explanation:
1. Demonstrates `sorted()` works on immutable tuples, sets, or dictionary views.
2. In-place `sort()` mutates existing lists with zero allocation overhead.

#### Expected Output:
```text
Original Tuple Untouched: (78, 92, 64, 85, 99)
New Sorted List Returned: [99, 92, 85, 78, 64]
In-Place Sorted List    : [64, 78, 85, 92, 99]
```
