## 1. Conceptual Deep-Dive: Unified Thread & Process Pool API

The standard library `concurrent.futures` module provides a clean, unified high-level interface for asynchronous execution:
1. **The Executor Pattern**:
   - `ThreadPoolExecutor(max_workers=N)`: Pool of threads (for I/O-bound tasks).
   - `ProcessPoolExecutor(max_workers=N)`: Pool of processes (for CPU-bound tasks).
   - Both share the exact same interface, allowing applications to switch between threads and processes with a one-line change!
2. **`Future` Objects**:
   - Represents the eventual result of an asynchronous computation.
   - Methods:
     - `future.result(timeout=None)`: Blocks until computation finishes and returns result.
     - `future.done()`: Returns `True` if task completed.
     - `future.cancel()`: Attempts to cancel pending unstarted task.
3. **Coordination Utilities**:
   - `executor.map(func, *iterables)`: Equivalent to `map()` executing in parallel.
   - `as_completed(futures)`: Yields futures as they finish in order of completion.

## 🛠️ Practical Hands-On & Real-World Examples

### Example 1: Asynchronous Execution Order Handling with `as_completed`
Submit heterogeneous background tasks and process results in real-time as each finishes.

```python
from concurrent.futures import ThreadPoolExecutor, as_completed
import time
import random

def simulated_task(task_id: int, sleep_duration: float) -> str:
    time.sleep(sleep_duration)
    return f"Task #{task_id} finished after {sleep_duration*1000:.0f}ms"

def test_as_completed():
    tasks = [(1, 0.05), (2, 0.01), (3, 0.08), (4, 0.02)]

    with ThreadPoolExecutor(max_workers=4) as executor:
        # Submit all tasks
        future_to_id = {
            executor.submit(simulated_task, tid, duration): tid
            for tid, duration in tasks
        }

        print("Waiting for results (yields in order of completion!):")
        for future in as_completed(future_to_id):
            result = future.result()
            print(" ", result)

test_as_completed()
```

#### Step-by-Step Explanation:
1. `executor.submit()` dispatches tasks immediately without blocking.
2. `as_completed()` yields results as soon as any task finishes, rather than waiting in input submission order.

#### Expected Output:
```text
Waiting for results (yields in order of completion!):
  Task #2 finished after 10ms
  Task #4 finished after 20ms
  Task #1 finished after 50ms
  Task #3 finished after 80ms
```

### Example 2: Clean Parallel Mapping with `executor.map`
Compute parallel transformations with deterministic input-order preservation.

```python
from concurrent.futures import ThreadPoolExecutor
import time

def process_item(item_id: int) -> int:
    time.sleep(0.01)
    return item_id * 10

def test_executor_map():
    items = [1, 2, 3, 4, 5]

    with ThreadPoolExecutor(max_workers=3) as executor:
        # executor.map guarantees results return in the SAME order as input items!
        results = list(executor.map(process_item, items))

    print("Input items :", items)
    print("Mapped items:", results)

test_executor_map()
```

#### Step-by-Step Explanation:
1. `executor.map()` operates like built-in `map()`, distributing workload across workers while maintaining sequential order.

#### Expected Output:
```text
Input items : [1, 2, 3, 4, 5]
Mapped items: [10, 20, 30, 40, 50]
```

### Example 3: Handling Worker Timeouts Gracefully
Enforce SLA response deadlines on asynchronous worker jobs.

```python
from concurrent.futures import ThreadPoolExecutor, TimeoutError
import time

def slow_external_api():
    time.sleep(0.5)  # 500ms
    return "API_DATA"

def test_future_timeout():
    with ThreadPoolExecutor(max_workers=1) as executor:
        future = executor.submit(slow_external_api)
        
        try:
            # Enforce 50ms deadline
            result = future.result(timeout=0.05)
            print("Result:", result)
        except TimeoutError:
            print("SLA Alert: External API task timed out after 50ms deadline!")

test_future_timeout()
```

#### Step-by-Step Explanation:
1. `future.result(timeout=...)` raises `TimeoutError` if computation exceeds the limit, preventing hung threads.

#### Expected Output:
```text
SLA Alert: External API task timed out after 50ms deadline!
```
