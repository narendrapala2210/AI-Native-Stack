# 07. Composition: HAS-A vs Inheritance (IS-A)

## 📖 Concept Overview
Software architecture provides two primary ways to combine classes:
1. **Inheritance (IS-A relationship)**: A `Car` **IS-A** `Vehicle`. The derived class inherits implementation details from the parent.
2. **Composition (HAS-A relationship)**: A `Car` **HAS-A** `Engine`. An object contains references to other independent objects to delegate work.

> [!TIP]
> **Design Principle**: *"Favor object composition over class inheritance."*
> - **Inheritance** couples subclasses tightly to superclass internal implementations.
> - **Composition** allows flexible, swappable components at runtime without rigid hierarchy trees.

## 🛠️ Practical Hands-On & Real-World Examples

### Example 1: E-Commerce Shopping Cart & Order System (Composition)
Model an enterprise order workflow where an `Order` contains multiple `Product` objects.

```python
class Product:
    def __init__(self, product_id: str, name: str, price: float):
        self.product_id = product_id
        self.name = name
        self.price = price

    def display(self) -> str:
        return f"{self.name} (${self.price:.2f})"

class Order:
    def __init__(self, order_id: str, customer_email: str):
        self.order_id = order_id
        self.email = customer_email
        # Composition: Order HAS-A list of (Product, quantity) pairs
        self.line_items: list[tuple[Product, int]] = []

    def add_product(self, product: Product, quantity: int = 1):
        self.line_items.append((product, quantity))

    def display_invoice(self):
        print(f"=== INVOICE FOR ORDER: {self.order_id} ({self.email}) ===")
        grand_total = 0.0
        for prod, qty in self.line_items:
            line_cost = prod.price * qty
            grand_total += line_cost
            print(f"  - {prod.display()} x {qty} = ${line_cost:.2f}")
        print(f"Grand Total: ${grand_total:.2f}\n")

book = Product("B101", "Designing Data-Intensive Applications", 45.00)
mug = Product("M202", "Python Developer Ceramic Mug", 15.00)

order = Order("ORD-7741", "alice@cloud.dev")
order.add_product(book, 2)
order.add_product(mug, 1)
order.display_invoice()
```

#### Step-by-Step Explanation:
1. `Order` is not a subclass of `Product`. Instead, `Order` contains and orchestrates `Product` objects.
2. Changes to `Product` internals do not break the `Order` structure.

#### Expected Output:
```text
=== INVOICE FOR ORDER: ORD-7741 (alice@cloud.dev) ===
  - Designing Data-Intensive Applications ($45.00) x 2 = $90.00
  - Python Developer Ceramic Mug ($15.00) x 1 = $15.00
Grand Total: $105.00
```

### Example 2: Swappable Storage Engine (Strategy via Composition)
Build a data archiver where storage backend (S3 Cloud vs Local Disk) can be swapped dynamically at runtime.

```python
class LocalDiskStorage:
    def save(self, filename: str, data: str):
        print(f"[LOCAL DISK] Writing data to /var/storage/{filename}")

class S3CloudStorage:
    def save(self, filename: str, data: str):
        print(f"[AWS S3] Uploading data to s3://company-production-bucket/{filename}")

class BackupManager:
    # Composition: BackupManager HAS-A storage provider
    def __init__(self, storage_provider):
        self.storage = storage_provider

    def create_backup(self, filename: str, payload: str):
        print(f"Initiating system backup for '{filename}'...")
        self.storage.save(filename, payload)

# Swap storage strategies dynamically without changing BackupManager:
local_backup = BackupManager(LocalDiskStorage())
local_backup.create_backup("db_dump_01.sql", "SQL_DATA...")

cloud_backup = BackupManager(S3CloudStorage())
cloud_backup.create_backup("db_dump_02.sql", "SQL_DATA...")
```

#### Step-by-Step Explanation:
1. Demonstrates loose coupling through composition.
2. The storage engine can be swapped on-the-fly without class inheritance.

#### Expected Output:
```text
Initiating system backup for 'db_dump_01.sql'...
[LOCAL DISK] Writing data to /var/storage/db_dump_01.sql
Initiating system backup for 'db_dump_02.sql'...
[AWS S3] Uploading data to s3://company-production-bucket/db_dump_02.sql
```

### Example 3: Computer Hardware Assembled via Composition
Model a desktop PC composed of independent CPU, RAM, and Storage components.

```python
class CPU:
    def __init__(self, model: str, cores: int):
        self.model = model
        self.cores = cores

class Memory:
    def __init__(self, size_gb: int):
        self.size = size_gb

class Workstation:
    def __init__(self, cpu: CPU, ram: Memory):
        # Composition: Workstation HAS-A CPU and HAS-A Memory
        self.cpu = cpu
        self.ram = ram

    def get_specs(self) -> str:
        return f"Workstation Specs: {self.cpu.model} ({self.cpu.cores} cores), {self.ram.size} GB RAM"

my_cpu = CPU("AMD Ryzen 9", 16)
my_ram = Memory(64)
rig = Workstation(my_cpu, my_ram)

print(rig.get_specs())
```

#### Step-by-Step Explanation:
1. Independent component classes are passed and assembled together.
2. Enables modular unit testing of each component in isolation.

#### Expected Output:
```text
Workstation Specs: AMD Ryzen 9 (16 cores), 64 GB RAM
```
